# 发布资源到共享服务

## 执行规则

1. 只在用户明确要求发布、共享或上传时执行；不得自行公开任何内容。
2. 一次只发布一个资源。用户只有文字时，使用“资源共享-发布文字”。工具调用的 `body` 参数必须是对象：`{"title": "标题", "body": "要发布的 Markdown 正文", "bodyFormat": "markdown", "accessMode": "public"}`。其中内层 `body` 必须是字符串；不要使用 `content` 字段，也不要把整段 JSON 编码成外层 `body` 字符串。
3. 用户只提供一个附件时，默认使用“资源共享-上传文件”，将附件的工作区相对路径填入 `workspace_file.path`；用户消息作为标题，未提供标题时使用文件名。这个流程保留原始文件。
4. 仅当附件是 `.md` 且用户明确要求“渲染为网页”“以正文发布”或“将 Markdown 内容发布”时，使用“资源共享-发布文字”，只将该附件的工作区相对路径填入 `workspace_file.path`。不得调用 `read_workspace_file`，不得读取、复述或把 Markdown 全文传入工具；工具会在服务端读取并发布，标题默认使用文件名。不要同时上传该文件。
5. 对 `.md` 附件但用户只说“发布”而未说明要保留文件还是渲染正文时，先询问用户选择“原始 Markdown 文件”还是“渲染后的网页正文”。
6. 同时有文字和附件，或附件多于一个时，先请用户明确本次要发布的对象。
7. 创建或上传成功后，读取返回的 `contentId` 并立即调用“资源共享-开启分享”。
8. 成功时只向用户交付 `shareUrl`。创建、上传或分享失败时停止后续调用，并说明接口返回的实际错误。

## 结束条件

- 等待用户：用户没有明确发布意图，或无法确定唯一发布对象时，提出最小必要问题。
- 完成：分享接口成功并取得 `shareUrl`。
- 失败：创建、上传或分享接口返回不可恢复错误时，说明失败原因和未完成的步骤。
