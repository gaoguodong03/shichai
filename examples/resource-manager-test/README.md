# 资源管理测试场景

## 组成与职责

- 场景提示词只定义共享任务契约：目标、范围、共同要求、工作区约定和完成标准。
- 主持人提示词定义通用调度职责和标准 JSON 输出；主持人 Skill 只包含阶段决策表。
- “资源管理专家”负责资源对象定位、Markdown 发布形式澄清、工具调用和真实结果回复，不参与跨专家调度。
- 资源管理 Skill 只包含执行规则与结束条件，可随专家复用于其他业务场景。
- 九个 HTTP 工具负责调用资源共享服务；工具中的 API Key 仅通过服务端环境变量解析。

## 导入与配置

1. 先部署包含受控 `path_params` 能力的书童四九后端。
2. 在当前四九用户的环境变量中设置 `STATIC_CONTENT_API_KEY`，值为该用户自己的资源共享服务 API Key。
3. 在仓库根目录运行以下命令，根据已跟踪的源资源生成本地 ZIP；ZIP 是本地产物，不进入版本控制：

   ```bash
   python3 - <<'PY'
   from pathlib import Path
   import zipfile

   root = Path("examples/resource-manager-test")
   output = root / "resource-manager-test.zip"
   files = sorted(
       path for path in root.rglob("*")
       if path.is_file() and path.suffix != ".zip" and path.name != ".DS_Store"
   )
   with zipfile.ZipFile(output, "w", zipfile.ZIP_DEFLATED) as archive:
       for path in files:
           archive.write(path, path.relative_to(root).as_posix())
   PY
   ```

4. 在四九前端进入“资源中心 → 场景”，选择“导入场景”，上传生成的 `resource-manager-test.zip`；先确认预览中专家、Skill、工具均无缺失引用，再确认导入。
5. 新建“资源管理测试”会话。已导入旧版“资源发布测试”时，两者可以并存。

场景包是导入时的完整权威配置。前端设计器中的场景、主持人和专家默认提示词只用于“新建资源”，导入时不会自动补齐或合并；因此本包必须完整携带场景契约、主持人协议和专家协议。不要通过直接复制 `backend/data/users/.../resources/` 验收资源包，因为该方式会绕过预览、引用校验、名称映射、Skill 规范化、缓存刷新和依赖预热。

## 输入边界

资源管理测试处理当前会话中明确且具有可靠对象的资源操作：

- 文字创建：在同一条消息中给出“创建/发布”等明确命令和正文。
- 文件操作：附带当前会话工作区中的真实文件，并说明上传、发布或管理意图。
- Markdown 只说“发布”时，由资源管理专家询问保留原文件还是渲染为网页正文；主持人不做该业务判断。
- “刚才那个”“这个资源”只有在当前会话存在唯一、明确的最近 `contentId` 时才可直接使用，否则专家先查询或要求选择。

## 验证方式

- 先使用前端完成一次预览与确认导入；预览中的 `missing_references` 应为空，导入后的场景、专家、Skill 与九个工具应与资源包语义一致。

- 输入“保存这段文字：测试正文”，应创建私密富文本并返回资源 ID。
- 输入“公开刚才的资源”，应使用同一资源 ID 开启分享，不得重新创建。
- 输入“搜索测试正文”，再要求设为私密或更新，应先使用查询结果中的资源 ID。
- 输入“删除刚才的资源”，专家应先核对详情再直接删除，不得要求二次确认。
- 上传一个 `.md` 后只说“发布”，应先由资源管理专家询问形式；回答后应恢复同一专家继续处理。
- 资源管理专家完成后，主持人应依据阶段表结束当前任务，不得重复派发同一请求。

密码设置、原始文件替换、版本管理和批量管理不在本场景范围内，请在资源共享服务 Owner 管理页完成。
