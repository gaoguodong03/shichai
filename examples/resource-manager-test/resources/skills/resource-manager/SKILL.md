# 管理资源共享服务

## 执行规则

1. 普通“发布、上传、保存”默认私密：只创建或上传，不开启分享。只有用户明确说“公开”或“分享”时才调用开启分享。
2. 一次只操作一个资源。对象不唯一时先查询并要求用户选择，不得猜测。
3. 后续写操作只能使用当前会话最近一次成功回复中明确展示的资源 ID，或本轮查询列表、搜索、查询详情结果中的 `contentId`。
4. 不得从任何 URL、`contentHash`、`shareHash` 或公开链接推导资源 ID。
5. 用户明确提出创建、上传、公开、撤销分享、更新或删除时直接执行，不得对同一动作再次要求确认。对象不唯一、资源 ID 不可靠或 Markdown 发布形式不明确时的追问属于必要澄清，不是二次确认。
6. 任一工具失败后立即停止本轮后续写操作，说明实际错误；不得重新创建、重新上传或换工具掩盖失败。错误可通过重新调用同一工具恢复且仍需要用户补充信息时，按“等待用户”结束；无需用户输入且同一请求允许安全重试时，不在当前轮盲目重试，而是如实失败并释放 Skill。
7. 创建直接文字时使用“资源共享-创建富文本”，`body` 必须是 `{"title":"标题","body":"完整正文","bodyFormat":"markdown"}`。不要传 `accessMode`，不要使用 `content` 字段。
8. 上传单个附件时使用“资源共享-管理上传文件”，把工作区相对路径放入 `workspace_file.path`，保留原始文件。
9. `.md` 附件明确要求“渲染为网页”“以正文保存”或“将 Markdown 内容发布”时，使用“资源共享-创建富文本”，只传 `workspace_file.path`；不得调用 `read_workspace_file`，不得把全文放入模型上下文。
10. 用户携带工作区 Markdown 文件且只模糊要求“发布”时，必须询问其选择保留为原文件上传还是渲染为网页正文；不得从摘要、文件内容或文件名推断形式。“完整内容已暂存为附带 Markdown 文件。用户原始请求摘要：...”不是用户选择。
11. 同时含文字和附件、附件多于一个或资源对象不唯一时，只提出本次操作所需的最小选择问题，不执行写操作。
12. 创建或上传成功后，用户没有明确公开意图时直接报告私密状态；用户已明确要求公开时，读取本轮结果的 `contentId`，仅调用一次“资源共享-管理开启分享”，不得重新创建资源。
13. 用户要浏览资源时调用“资源共享-查询列表”；按名称或关键词找历史资源时调用“资源共享-搜索资源”，将关键词放入 `query.q`。
14. 查询结果唯一时，使用其中的 `contentId` 调用“资源共享-查询详情”；多个结果时列出名称、类型、状态和资源 ID，等待用户选择。
15. “刚才那个”“这个资源”仅在当前会话存在唯一、明确的最近资源 ID 时解析；否则先查询。
16. 私密状态以 `isShared=false` 为准；`accessMode=public` 不代表已经公开。
17. 用户要求查询当前所有资源时，逐条列出 `items` 中的全部资源，并对每项展示名称、资源 ID、类型和按该项 `isShared` 判断的状态。不得将部分结果称为全部资源，也不得把一项状态套用到其他项。
18. 响应的 `totalPages` 大于 1 时，列表结果继续按页调用“资源共享-查询列表”；搜索结果继续按页调用“资源共享-搜索资源”并始终携带原 `query.q`。直到取得全部页面后再回复，准确说明 `totalItems`、实际列出数量和页数；未取得全部页面时只能称“当前页结果”。
19. 查询详情只展示标题、资源 ID、类型、公开状态和实际返回的 `ownerUrl`；不展示正文、`accessUrl` 或 `shareUrl`。提示用户可通过 `ownerUrl` 查看完整内容，不得自行拼接链接。
20. 用户明确要求公开或分享且当前会话有唯一可靠 `contentId` 时直接执行。详情显示已分享且包含 `shareUrl` 时直接返回原链接；已分享但没有 `shareUrl` 时，可用同一 `contentId` 调用幂等的“资源共享-管理开启分享”取得原链接。不得再要求用户确认公开。
21. 用户要求设为私密时调用“资源共享-撤销分享”。详情已经是 `isShared=false` 时直接报告当前状态，不调用撤销工具。分享或撤销失败后停止，不得重新创建资源。
22. 仅修改标题且资源 ID 可靠时，直接调用“资源共享-更新富文本”，`body` 只传 `contentId` 和新 `title`；不得调用“资源共享-查询详情”，不得读取或回传正文。
23. 用户直接提供完整正文覆盖富文本时调用“资源共享-更新富文本”，`body` 至少包含 `contentId`，并按需包含 `title`、`body`、`bodyFormat`。不执行“改第三段”“润色一部分”等依赖原文的局部自然语言编辑。
24. 使用工作区 `.md` 覆盖正文时，只传 `workspace_file.path`，并在 `body` 中传 `contentId`、当前标题和 `bodyFormat: "markdown"`，避免文件名意外改变标题；不得读取全文进入模型上下文。
25. 原始文件不能通过本 Skill 编辑或替换，应引导用户前往实际返回的 Owner 管理页。
26. 设置密码不通过本场景 HTTP API 执行。当前会话已有唯一可靠资源 ID 和实际 `ownerUrl` 时，直接回复“请前往 Owner 管理详情页自行设置访问密码：<ownerUrl>”；不得建议改为公开分享，不得再次询问资源对象。资源 ID 可靠但尚无 `ownerUrl` 时，调用“资源共享-查询详情”取得链接。
27. 用户明确请求删除且当前会话有唯一可靠资源 ID 时，先调用“资源共享-查询详情”核对目标；核对成功后直接调用“资源共享-删除资源”，不得要求二次确认。删除调用只传 `body: {"contentId": "..."}`，不得传 `path_params`、URL 或 hash。对象不唯一、查询失败或目标变化时停止并要求用户选择。
28. 每次成功创建、查询或管理后，只回复实际结果中可确认的资源名称、资源 ID、类型和状态。私密资源只展示实际返回的 `ownerUrl`；已分享资源只展示实际存在的 `accessUrl`、`shareUrl`、`ownerUrl`，不得自行拼接缺失链接。
29. 所有链接必须逐字符复制工具响应 JSON 中对应字段的完整字符串，不得凭记忆重写、手动拼接、缩短、格式化或修改主机、端口、路径或分隔符。最终回复中的链接必须与本轮工具结果逐字符一致；工具未返回对应链接时不得生成链接。

## 结束条件

- 等待用户：当资源对象不唯一、资源 ID 不可靠、工作区 Markdown 发布形式不明确、附件对象不唯一或仍缺少其他必要输入时，只提出一个最小问题；使用 `execution_status=blocked`、`next_action.agent_turn=respond`、`next_action.skill_session=keep`，交回主持人并保留当前 Skill。
- 继续：当本轮步骤已成功且同一明确用户请求还有无需用户补充的后续资源步骤，例如创建后按原请求继续公开时，使用 `execution_status=succeeded`、`next_action.agent_turn=continue`、`next_action.skill_session=keep`。
- 完成：当用户当前明确要求的资源操作均已由真实工具结果确认完成，或密码设置已提供实际 Owner 管理详情链接时，交付真实资源信息；使用 `execution_status=succeeded`、`next_action.agent_turn=respond`、`next_action.skill_session=release`。
- 失败：当工具返回不可恢复错误、目标核对失败且无法继续，或无法形成用户要求的结果时，说明真实失败原因和已经取得的内容；使用 `execution_status=failed`、`next_action.agent_turn=respond`、`next_action.skill_session=release`。
