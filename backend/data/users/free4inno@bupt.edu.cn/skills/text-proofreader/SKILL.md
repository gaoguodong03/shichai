# 🎯 技能目标
本技能专注于**内容质量**检查。利用大模型的语义理解能力，识别并修正文字错误，提升文章的可读性和专业性。

# 📋 检查规则库

## 1. 错别字与形近字校验
- **规则**: 识别因拼音输入错误或字形相似导致的错误。
- **示例**: 
  - "登陆" vs "登录" (根据语境判断)
  - "在再" 混用
  - "的地得" 误用
  - "账号" vs "帐号" (统一为标准用法)

## 2. 词语搭配与误用
- **规则**: 检查成语误用、动词宾语搭配不当、专业术语错误。
- **示例**: "提高水平" (正确) vs "增加水平" (错误); "做出贡献" vs "作出贡献" (视语境统一)。

## 3. 语句通顺度 (Grammar & Flow)
- **规则**: 识别病句（成分残缺、语序颠倒、逻辑矛盾）。
- **动作**: 标记读起来拗口或逻辑不通的句子，并提供润色建议。

## 4. 敏感词与合规性 (可选)
- **规则**: 检查是否包含广告法违禁词（如 "第一", "最"）、政治敏感词或不礼貌用语。
- **动作**: 高亮标记并建议替换词。

# 🔄 执行流程
1. **语义分析**: 通读全文，理解上下文语境。
2. **定位错误**: 找出疑似错别字、语病或不当用词。
3. **置信度评估**: 
   - 高置信度（明显错误）：直接建议修改。
   - 低置信度（可能是专有名词）：标记为 "疑似"，询问用户确认。
4. **输出报告**: 
   - 输出 Markdown 表格：[位置] | [错误类型] | [原文] | [建议修改] | [原因解释]。
5. **执行修复 (仅当用户要求)**: 
   - 输出润色后的完整文本。
   - **重要**: 保持原有的日期格式、数据结构和代码块原封不动（除非代码注释里有错别字）。

# ⚠️ 注意事项
- **不要**随意更改用户的写作风格（如口语化 vs 正式），除非用户要求润色。
- **不要**修改正确的专业术语或人名地名。
- **不要**触碰纯数据格式（如 `2026-03-11` 即使读起来不顺也不要改，那是 format-validator 的事）。
