# Markdown 格式化

将纯文本或已有 Markdown 整理成结构清晰、便于扫读的 Markdown。**原则**：只调整排版与明显笔误，不增删、不改写原文内容。

## 何时使用

- 用户说「格式化这篇」「美化排版」「加一下格式」「整理成 Markdown」
- 用户提供长文或从网页/文档粘贴的纯文本，需要变成可读 Markdown
- 文章已有 Markdown 但希望优化标题、加粗、列表和 frontmatter

## 工作流程

### 步骤 1：读取并判断内容类型

读取用户指定文件，根据是否已有 `---` frontmatter、`#` 标题、`**粗体**`、列表、代码块等判断为「纯文本」或「已有 Markdown」。

**若检测到已是 Markdown**，询问用户：

1. **优化排版（推荐）**：分析内容，改进标题/加粗/列表，再做 typography 检查，输出 `{filename}-formatted.md`
2. **保留原结构**：只做 typography 检查并输出 `{filename}-formatted.md`
3. **仅 typography**：只做中英文间距、标点等修正（可对原文件说明修改建议，或若本技能有脚本则调用）

按用户选择执行后续步骤。

### 步骤 2：内容分析（读者视角）

通读全文，从读者视角列出：

- **亮点与关键信息**：核心论点、数据、反常识结论、金句
- **结构**：逻辑线是否清晰、是否有该有但缺的小标题、大段文字是否需拆分
- **适合格式化的地方**：可做成列表的并列项、可做成表格的对比、应标为代码的命令/术语、应加粗的结论句
- **明显问题**：标题层级混乱、一段多主题、错别字

将分析保存为 `{原文件名}-analysis.md`，作为后续排版的依据。

### 步骤 3：检查/创建 Frontmatter、标题与摘要

- **Frontmatter**：若无 `---` 块则创建，包含 `title`、`slug`、`summary`；若同目录有 `imgs/cover.png` 可设 `coverImage`
- **title**：若用户未指定，根据核心论点、读者痛点或金句生成 3～4 个风格不同的候选（如：颠覆常识型、直接给方案型、悬念型、数字型），让用户选或自定。原则：前几个字要有吸引力、具体优于抽象、问句/否定往往更抓人，约 25 字内，避免「浅谈」「关于…的思考」「震惊」「万字长文」
- **summary**：80～150 字，3 个不同角度候选供选择。要传达「读者能得到什么」，避免「本文介绍了…」

若正文首行为 H1，可提取到 frontmatter 的 title 并从正文去掉重复 H1。

### 步骤 4：按分析结果应用排版

在**不增删、不改写内容**的前提下：

| 元素 | 用法 |
|------|------|
| 标题 | 在自然段落边界用 `##`、`###` 分层 |
| 加粗 | 核心结论、重要术语、可摘抄句用 `**粗体**` |
| 无序列表 | 并列要点、特征、示例用 `- item` |
| 有序列表 | 步骤、顺序、排名用 `1. item` |
| 表格 | 对比、选项、结构化数据用 Markdown 表格 |
| 代码 | 命令、路径、变量、技术词用 `` `inline` `` 或围栏代码块 |
| 引用 | 金句、警告、引用他人用 `> blockquote` |
| 分隔 | 大主题切换处可用 `---` |

**禁止**：添加新句子、删减内容、改写原意、用主观化小标题（如「惊人发现」）。**必须**：保留作者语气与用词，只做排版与明显笔误修正。

### 步骤 5：保存与 typography

- 将结果保存为 `{原文件名}-formatted.md`（若已存在可先备份再覆盖）。
- **Typography**：中英文间距、全角/半角标点、CJK 强调标点等。若本技能目录下 `scripts/` 中有 typography 相关脚本，可通过 `run_skill_script` 调用；否则在完成报告中列出建议用户自查的项，或说明可配合 baoyu-skills 的 format-markdown 做最后一步。

### 步骤 6：完成报告

向用户汇报：

- 生成文件：`{原文件名}-analysis.md`、`{原文件名}-formatted.md`
- 分析摘要：亮点数、金句数、已修复的排版问题数
- 具体变更：frontmatter、新增标题数、加粗/列表/表格/代码/引用数、修正的错别字

## 协作说明（群聊场景）

- 仅做排版与结构优化，不判语义对错；若发现错别字或语病，可提示由「文字校对与错别字检查专家」处理。
- 日期、中英文空格、标点规范等严格规则由「格式与数据规范检查专家」负责；本技能侧重可读性与 frontmatter，可与其配合使用。

## 注意事项

- 保持原文写作风格与语气
- 代码块标明语言（如 `python`、`javascript`）
- 遵循中英文混排时的空格习惯
- 分析文件用于对齐「识别出的问题」与「实际修改」，便于复查
