### 编程 Agent：如何重塑工程、产品和设计角色？

**来源**: Harrison Chase 博客  
**发布时间**: 2026-03-19  
**原文链接**: [点击访问原文](https://gaoguodong03.github.io/gdBlog/2026/03/19/%E7%BC%96%E7%A8%8B-Agent-%E5%A6%82%E4%BD%95%E9%87%8D%E5%A1%91%E5%B7%A5%E7%A8%8B%E3%80%81%E4%BA%A7%E5%93%81%E5%92%8C%E8%AE%BE%E8%AE%A1/)

---

#### 核心观点

编程 Agent 的出现使得软件开发流程发生了颠覆性变化，尤其对工程、产品和设计（EPD）团队的角色定位产生了深远影响：

1. **流程变化**：
   - 传统的 PRD（产品需求文档）流程已被快速生成代码的方式替代，瓶颈从实现转向评审。
   - 原型的生成成本极低，但评审环节变得更加重要。

2. **角色影响**：
   - 通才（同时具备产品、工程、设计能力的人）价值提升。
   - 使用编程 Agent 成为必选项。
   - 专业化门槛提高，各角色需要更强的系统思维和产品意识。

3. **评审的重要性**：
   - 产品、工程和设计角色需要围绕原型开展更多评审工作，以确保功能的合理性、可用性和良好的架构。

4. **未来趋势**：
   - PRD 的形式可能转变为结构化的、带版本管理的 prompt，成为沟通的核心工具。
   - 专业化角色虽有空间，但需要在领域内更具深度和广度。

---

#### 文章亮点

- 编程 Agent 让实现成本极低，但评审质量成为新的核心挑战。
- 系统思维在低成本实现时代的重要性大幅提升。
- 每个角色都需要具备产品意识，以避免对组织效率的拖累。
