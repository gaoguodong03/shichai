# 编程 Agent 如何重塑工程、产品和设计

根据 Harrison Chase 的文章《How Coding Agents Are Reshaping EPD》，编程 Agent 正在深刻改变软件公司的工程(Engineering)、产品(Product)和设计(Design)三大职能的协作方式和角色定位。

## 核心观点

软件公司的 EPD 存在的根本目的是产出优质软件，而最终产出实质上就是代码。随着编程 Agent 让写代码变得异常简单，整个 EPD 的工作流程和角色定位正在经历重大变革。

## 主要变化

### 1. 流程变革
- **PRD 已死**：传统的"PRD → 设计稿 → 代码"线性开发流程已经终结。编程 Agent 能直接将想法转化为可运行软件，绕过了传统文档驱动的开发模式。
- **瓶颈转移**：开发瓶颈从"实现"转向"评审"。由于任何人都能快速生成代码原型，EPD 团队现在需要评审大量原型，确保它们在架构、产品价值和用户体验方面都"足够好"。
- **PRD 万岁**：虽然传统 PRD 流程已死，但描述产品需求的文字依然重要。未来 PRD 可能演变为结构化的、带版本管理的 prompt。

### 2. 角色影响
- **通才价值提升**：在产品、工程和设计三方面都有不错感觉的通才比以往更有价值，因为他们可以省去跨团队沟通成本，直接与 Agent 协作完成工作。
- **编程 Agent 成为必选项**：不使用编程 Agent 的人可能会被使用者替代，因为上手并不难且效率提升显著。
- **PM 能力两极分化**：好的产品经理能做出真正有用的东西，而差的产品经理会产生更多需要评审的"垃圾"，浪费团队资源。
- **系统思维成为核心技能**：在执行成本极低的世界里，系统思维（对架构、用户需求或设计原理的清晰心智模型）成为真正的差异化能力。
- **产品意识成为基本要求**：所有角色都需要具备产品意识，否则会制造出需要他人评审的无用原型，拖累整个组织。
- **专业化门槛提高**：专业角色仍然有价值，但门槛更高了——不仅要在自己的领域精通，还需掌握编程 Agent 和具备产品意识。

## 结论

编程 Agent 正在重塑软件开发的本质，使 EPD 团队从"实现者"转变为"评审者"和"把关人"。成功的关键不再是谁能写出代码，而是谁能确保代码解决了正确的问题、架构合理且用户体验良好。在这个新时代，跨领域能力、系统思维和产品意识比单纯的编码技能更为重要。
