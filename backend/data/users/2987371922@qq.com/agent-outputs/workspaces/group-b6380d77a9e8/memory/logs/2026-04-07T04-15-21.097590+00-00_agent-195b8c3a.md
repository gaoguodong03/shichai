## 编程 Agent 如何重塑工程、产品和设计

### 核心观点
Harrison Chase 在其文章中探讨了编程 Agent 对软件公司 EPD（工程、产品、设计）三大职能的变革影响。随着编程 Agent 让代码生成变得异常高效，EPD 的角色定位和协作方式正在经历深刻变化。

---

### 主要变化

#### 1. 流程变革
- **PRD 已死**：传统的开发流程（PRD → 设计稿 → 代码）不再是必须，编程 Agent 可以直接将想法转化为可运行的软件。
- **瓶颈转移**：开发瓶颈从“实现”转向“评审”，EPD 需要确保大量生成的代码原型在架构、产品价值和用户体验上都“足够好”。
- **PRD 万岁**：尽管传统流程已死，但描述产品需求的文字形式依然重要，未来或许会演变为结构化的 prompt。

#### 2. 角色影响
- **通才价值提升**：在产品、工程和设计三方面都有能力的通才，能省去跨团队沟通成本，与 Agent 协作直接完成更多工作。
- **编程 Agent 成为必选项**：不使用编程 Agent 的人将被淘汰，因为其效率提升显著。
- **PM 能力两极分化**：优秀的 PM 能更高效地产出有价值的原型，而差的 PM 则可能浪费资源。
- **系统思维成为核心技能**：拥有对架构、用户需求或设计原理清晰心智模型的人将脱颖而出。
- **产品意识成为基本要求**：所有角色都需要具备产品意识，以减少无用原型的生成并提高评审效率。
- **专业化门槛提高**：专业角色仍有价值，但需掌握编程 Agent 和产品意识，门槛大幅提升。

---

### 结论
编程 Agent 正在重塑软件开发的本质，使 EPD 团队从“实现者”转变为“评审者”和“把关人”。成功关键在于确保代码解决正确的问题、架构合理且用户体验良好。跨领域能力、系统思维和产品意识的重要性显著提升。
