# 编程 Agent 如何重塑工程、产品和设计

根据 Harrison Chase 的文章《How Coding Agents Are Reshaping EPD》，编程 Agent 正在深刻改变软件公司的工程(Engineering)、产品(Product)和设计(Design)三大职能的协作方式和角色定位。

## 核心观点

软件公司的 EPD 存在的根本目的是产出优质软件，而最终产出实质上就是代码。随着编程 Agent 让写代码变得异常简单，整个 EPD 的工作流程和角色定位正在经历重大变革。

## 主要变化

### 1. 流程变革
- **PRD 已死**：传统的"PRD → 设计稿 → 代码"线性开发流程已经终结。编程 Agent 能直接将想法转化为可运行软件，绕过了传统文档驱动的开发模式。
- **瓶颈转移**：开发瓶颈从"实现"转向"评审"。由于任何人都能快速生成代码原型，EPD 团队现在需要评审大量原型，确保它们在架构、产品价值和用户体验方面都"足够好"。
- **PRD 万岁**：虽然传统 PRD 流程已死，但描述产品需求的文字依然重要。未来 PRD 可能演变为结构化的、带版本管理的 prompt
