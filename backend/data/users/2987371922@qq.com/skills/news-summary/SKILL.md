# 新闻搜索摘要 Skill

一个智能新闻搜索和摘要工具，帮你快速获取和分析最新新闻，并生成带「AI 解读」功能的 HTML 页面。

---

## 一、适用场景

- 想快速了解某个主题（如「AI」「deepseek」「A股」）最近几天的新闻动态。
- 希望一键生成一个**本地可访问的新闻汇总网页**，包含摘要、来源、时间、权威性标签等。
- 希望进一步对单条新闻做**深度 AI 解读**（可自定义分析角度），并在浏览器中查看。

---

## 二、核心功能概览

### 1. 搜索新闻

1. 先向用户确认**搜索主题**（如「AI 行业」「deepseek」等），必要时帮用户澄清范围：  
   - 时间范围（默认：最近 3–5 天）  
   - 语言/地区偏好（如「中文新闻为主」）  
   - 是否关注特定来源（如「主流媒体」「官方公告」）
2. 搜索策略：
   - **优先使用 WebSearch 工具**（若当前环境提供 WebSearch 类工具 / MCP，例如 Exa、Linkup 等，请优先调用它们）。
   - 当 WebSearch 不可用或返回结果不足时，**退回 Brave Search MCP**（若已配置），并遵守速率限制：  
     - 每次调用 Brave Search MCP 后必须 `sleep 1 秒` 再进行下一次调用，以避免速率限制。
   - 搜索最近 3–5 天的 **12–25 条**相关新闻：
     - 使用多个关键词组合搜索（如：「AI」+「产业」「融资」「监管」等）。
     - 根据返回结果数量，**分批搜索**以保证总量足够。
     - 对结果按「标题 / URL」进行去重。
     - 如果结果数量仍不足 12 条，适当：
       - 扩大时间范围；
       - 或扩展/放宽关键词。

> 要点：一定要**多批次搜索 + 去重**，保证质量与覆盖度，而不是一次搜索草草了事。

### 2. 分析新闻

对每一条新闻，提取/生成以下信息：

- **标题**：原文标题（可在必要时做轻微润色，但不要歪曲含义）。
- **来源网站**：如「新华社」「The Verge」「澎湃新闻」等。
- **发布时间**：尽量转换为统一格式（如 `YYYY-MM-DD HH:mm`），并保留原时区信息（如有）。
- **权威性评估**：`高 / 中 / 低`
  - 高：官方媒体、监管机构、权威研究机构、大型知名媒体。
  - 中：主流科技媒体、成熟的垂直媒体、可信度较高的博客。
  - 低：个人自媒体、论坛、来源不明的站点等。
- **摘要**：每条新闻生成 **100–200 字**的中文摘要：
  - 用自己的话总结，不要只是复制标题。
  - 核心观点清晰，避免过度夸张或主观判断。
  - 若新闻本身信息噪音较大，可适度整合多个来源的信息。
- **原文链接**：新闻的 URL。

## 三、HTML 页面生成

### 1. 输出目录与命名规则

- 通过 `pwd` 获取**当前工作目录绝对路径**，记为 `WORK_DIR`。  
- 生成目录：  
  - `WORK_DIR/news-summary/<timestamp>_<topic>/`
  - `<timestamp>`：时间戳，格式必须为 `YYYYMMDD_HHMM`（如：`20260111_1145`），确保每次搜索都有唯一目录。
  - `<topic>`：从用户查询中提取的英文/拼音主题关键词（例如：
    - 用户查询「AI 行业发展」→ `AI`
    - 用户查询「deepseek 发展近况」→ `deepseek`
    - 若无法合理提取，则使用默认值：`news`
  - 组合示例：`20260111_1145_AI`，完整路径示例：  
    - `/path/to/work/news-summary/20260111_1145_AI/`

### 2. 文件命名

- 新闻汇总页面：
  - 文件名：`news_summary_<topic>.html`
  - 完整路径：  
    - `WORK_DIR/news-summary/<timestamp>_<topic>/news_summary_<topic>.html`
- AI 解读目录：
  - 目录：`WORK_DIR/news-summary/<timestamp>_<topic>/analysis/`
  - 单条新闻解读文件名：`news_analysis_<newsId>.html`

### 3. HTML 页面结构与要求

- 页面整体要求：
  - **现代简洁、响应式设计**，适配桌面与移动端。
  - 使用卡片式布局展示新闻列表。
  - 顶部包含当前主题与时间范围的概览说明。
  - 必须在 `<head>` 或 `<body>` 中合适位置 **引入**：
    - `<script src="/news-ai.js"></script>`  
    - 注意：使用**绝对路径** `/news-ai.js`，否则 AI 解读功能无法工作。

- 每条新闻卡片**必须包含的内容**：
  - 标题
  - 来源网站
  - 发布时间（同时展示「绝对时间」和「相对时间」如「2 天前」）
  - 权威性标签（颜色约定）：
    - 高：绿色
    - 中：黄色
    - 低：灰色
  - 摘要（100–200 字）
  - 「查看原文」按钮（点击后在新标签页打开原文）

- 每条新闻卡片**必须包含的 data 属性**（用于前端 JS 与 AI 解读交互）：
  - `data-news-id`：新闻 ID（从 0 开始的整数：0、1、2、...）
  - `data-news-url`：原文链接
  - `data-news-source`：来源
  - `data-news-time`：发布时间（字符串）
  - `data-news-title`：新闻标题
  - `data-news-summary`：新闻摘要

- 布局/样式建议：
  - 使用 CSS Grid 或 Flex 布局实现响应式卡片排布。
  - 适度使用阴影、圆角、渐变背景，让页面美观但不过度花哨。
  - 页面背景可以使用淡色渐变，与后续 AI 解读页面主题呼应。

### 4. 与 `news-ai.js` 的约定

- HTML **初始**仅包含「查看原文」按钮；  
  「AI 解读」「查看 AI 解读」「删除解读」按钮由 `news-ai.js` 在页面加载后**动态渲染**。
- 页面中需要提供一个全局可访问的 `<script>` 配置或 `data-*` 属性，使 `news-ai.js` 能够知道当前：
  - `<timestamp>_<topic>` 标识（例如放到 `<body data-timestamp-topic="20260111_1145_AI">`）。

## 四、AI 解读功能（可选扩展说明）

> 对于当前版本的 Skill，**只需要完成新闻搜索 + 摘要分析 + 生成静态 HTML 文件** 即可。  
> 你可以在本地文件系统中通过 `open` / Finder / 浏览器 `file://` 自行打开这些 HTML 文件，**不强制要求 Node.js 服务器或 HTTP 访问**。

- 若你之后希望为单条新闻添加更深度的「AI 解读」页面，可以在此基础上自行实现：
  - 额外的 `analysis` 子目录与 `news_analysis_<id>.html` 文件；
  - 使用任意方式（本地脚本、Node 服务器、MCP、CLI 等）生成对应 HTML；
  - 在汇总页面中自行维护按钮和链接。
- 本 Skill 文档的其他部分（搜索、摘要、`news-summary/<timestamp_topic>/news_summary_<topic>.html` 结构等）依然适用，只是**不再要求自动重启服务器或通过 `http://localhost:3456/...` 打开页面**。

## 五、整体工作流程总结（给 Agent 的执行步骤）

1. **确认主题**：和用户对话，确定新闻搜索主题及范围。
2. **生成标识**：
   - 从查询中提取 `<topic>`（无法提取则使用 `news`）。
   - 生成 `<timestamp>`（格式 `YYYYMMDD_HHMM`），组合得到 `<timestamp_topic>`。
3. **搜索新闻**：
   - 优先用 WebSearch 工具 / MCP，按需多批次搜索。
   - 若可用 Brave Search MCP，则作为补充，并保证每次调用后 `sleep 1 秒`。
   - 对结果去重，确保最终有 12–25 条高质量新闻。
4. **分析与整理**：
   - 为每条新闻生成包含标题、来源、时间、权威性评估、摘要、原文链接等字段的结构化数据。
5. **生成 HTML**（本 Skill 的核心产物）：
   - 使用 `pwd` 获取 `WORK_DIR`。
   - 创建目录：`WORK_DIR/news-summary/<timestamp_topic>/`。
   - 生成 `news_summary_<topic>.html` 文件，带有美观的响应式布局。
   - 为每个新闻卡片写入必要的信息（标题、来源、时间、权威性、摘要、原文链接），也可以根据需要附加 `data-*` 属性。
6. **结束本 Skill 的工作**：
   - 将生成的 HTML 文件路径明确输出给用户，例如：  
     `已生成：WORK_DIR/news-summary/<timestamp_topic>/news_summary_<topic>.html`
   - 由用户自行在本地文件系统中打开该 HTML（如在 macOS 下执行 `open 路径`，或直接在 Finder 中双击）。

> 总结：**这个 Skill 现在的职责就是——帮你搜索和整理新闻，并在本地生成一个可直接打开查看的静态 HTML 页面，其它如服务器、前端脚本等都交由你自行决定是否实现。**
