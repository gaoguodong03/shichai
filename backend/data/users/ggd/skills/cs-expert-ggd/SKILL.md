# 计算机系统知识模块 Skill

## 模块定位

- 提供与以下内容相关的结构化知识与推理路径：
  - 计算机网络
  - 操作系统
  - 数据库系统
  - 软件工程
  - 人工智能基础
  - Python 语言与工程实践
  - Agent 技术栈（MCP / Skill / LangChain 等）
- 详细课程知识结构与要点参见：`references/cs-curriculum.md`

## 适用场景

当用户需求满足以下任意一条时，可以使用本 Skill 提供的知识支持：

1. 涉及计算机网络 / 操作系统 / 数据库 / 软件工程 / AI / Python 的概念讲解、习题分析或知识梳理
2. 需要基于上述基础课程知识进行系统或架构设计（例如后端服务设计、系统性能分析）
3. 需要设计、实现或评审基于 MCP / Skill / LangChain 的 Agent、工具链或工作流
4. 需要将“教材级”知识转化为“工程实践”方案（例如从课本到实际项目）

不适用的场景示例（交给其他 Skill）：

- 纯内容写作（公众号/文案）
- 纯 Web UI 视觉设计

## 总体推理流程（供主体参考）

### 步骤 1：快速识别问题类型

优先判断用户问题属于以下哪一类（可以多选）：

1. **概念/原理型**  
   - 例：「TCP 和 UDP 区别？」「事务的 ACID 是什么？」  
   - 行为：以课程视角解释概念，并给出直观类比和简单示例。

2. **题目/练习型**  
   - 例：「这道操作系统调度题怎么做？」「数据库规范化题目求解」  
   - 行为：先复述题意 → 拆解条件 → 按课本方法求解 → 总结通用解题套路。

3. **工程设计型**  
   - 例：「设计一个高并发接口」「给一个系统做数据库建模」  
   - 行为：从软件工程/网络/数据库/OS 角度综合设计，强调权衡与取舍。

4. **Agent / 工具链设计型**  
   - 例：「怎么基于 MCP + LangChain 设计一个多 Skill 的 Agent？」  
   - 行为：先梳理任务 → 拆成多个 Skill / 工具 → 设计调用顺序与数据流。

### 步骤 2：选取相关课程视角

根据问题内容，从以下课程参考中选择需要用到的视角（可多选）：

- 计算机网络视角：协议分层、时延与吞吐、连接管理、可靠传输等
- 操作系统视角：进程/线程、调度、内存管理、同步互斥等
- 数据库视角：模式设计、索引、事务与并发控制、查询优化等
- 软件工程视角：需求分析、分层架构、模块划分、设计原则等
- 人工智能视角：基本建模思路、常见算法类别与适用场景
- Python 工程视角：代码结构、可维护性、常用标准库与生态

具体知识点的层级结构与提纲，可从 `references/cs-curriculum.md` 中查阅并引用。

### 步骤 3：从“课本”到“工程”的转换

对每个选中的课程视角，遵循以下转换流程：

1. 用「教材视角」先给出**标准定义**和**关键结论**
2. 结合用户的具体场景，说明这些结论在真实工程中的**适用条件与局限性**
3. 给出符合工程实践的**设计建议 / 实现示例 / 权衡分析**
4. 提炼出 1～3 条可复用的「经验规则」，便于用户迁移到类似问题

### 步骤 4：针对 Agent / MCP / LangChain 的专门处理

当问题涉及 Agent 或工具链时，建议遵循以下流程：

1. **梳理任务结构**  
   - 用户目标是什么？  
   - 需要拆成哪些子任务？（如搜索、分析、生成、执行等）

2. **设计 Skill / 工具拆分**  
   - 哪些子任务适合拆成独立 Skill？  
   - 哪些是通用工具（搜索、文件、Web、代码执行）？

3. **确定编排与调用顺序**  
   - 使用 MCP / LangChain 的哪种模式更合适（例如 Tool-Calling、AgentExecutor、Router 等）？  
   - 明确每一步的输入输出格式，避免隐式依赖。

4. **加入安全与鲁棒性考虑**  
   - 明确边界条件与失败重试策略  
   - 尽量让每一步的输出带有「结构化结果 + 摘要」两层

在回答中，应把设计过程说清楚，而不仅给出最终代码。
