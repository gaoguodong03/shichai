## 适用场景

- 用户希望你在真实浏览器里「操作网页」而不是只读网页内容，例如：
  - 登录网站、在页面中连续点击、填写复杂表单、分页滚动浏览内容。
  - 在需要按钮点击、下拉选择等交互后才能看到结果的页面上完成任务。
- 当普通 Web 搜索 / 抓取（如 Linkup、Exa）无法完成需要交互的任务时，优先考虑使用本技能。

## 使用原则

1. 先把任务拆成若干**清晰的浏览器操作步骤**（导航 → 等待加载 → 查找元素 → 点击/输入 → 再等待 → 读取结果），逐步执行。
2. 所有浏览器相关操作，都通过名称前缀为 `playwright-mcp_` 的 MCP 工具完成，不要假想页面状态。
3. 每次导航或操作后，需要使用「等待 / 状态检查」类工具确认页面已稳定，再进行下一步。
4. 涉及登录、输入密码或个人信息时，先向用户说明要做什么，并在得到确认后再继续。
5. 如果发现目标网站无法正常加载、元素找不到或被重定向，要返回清晰的错误说明，而不是编造结果。

## 建议流程

1. **理解需求**：用自然语言复述用户的浏览器任务，确认目标网站和要完成的结果。
2. **规划步骤**：写出 3–10 步左右的操作计划（例如「打开页面」「搜索关键字」「点击第一个结果」「读取结果区域文本」）。
3. **执行步骤**：
   - 使用 Playwright MCP 提供的「打开页面 / 导航」工具进入目标 URL。
   - 使用「快照/检查元素」类工具找到需要交互的元素（按钮、输入框、链接等）。
   - 调用点击、输入、选择等交互工具完成单步操作。
   - 必要时滚动页面，或等待特定元素出现/可见。
4. **收集结果**：用合适的工具获取最终页面上与用户任务相关的文本或结构化信息。
5. **整理回答**：用自然语言总结浏览器中实际看到的结果，必要时列出关键截图链接或结构化数据。

当不确定具体使用哪个 Playwright 工具时，先查看可用工具列表中的名称和描述，选择最接近当前操作意图的那个。所有操作都必须基于工具真实返回的页面状态，不要凭空臆测。
