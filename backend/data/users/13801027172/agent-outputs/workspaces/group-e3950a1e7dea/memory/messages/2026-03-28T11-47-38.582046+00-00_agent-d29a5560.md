### 补充观点：Harness Engineering 的价值
即使模型底层能力足够强大，Harness Engineering 的意义仍然不可忽视。原因在于：
1. **实际应用场景的复杂性**：底层模型再强，也无法直接理解和适应所有任务环境。例如，任务中的工具使用、权限管理以及动态变化的反馈，这些都需要 Harness 来构建一个适配环境。
2. **可靠性和容错性**：Harness 能通过反馈循环和监控机制，使智能体在错误发生时有能力自我调整，从而提升系统的稳定性。
3. **扩展性与效率**：Harness 提供了一种框架，使得智能体不仅能在单一任务中表现强大，还能在不同任务之间快速切换和扩展。

### 引导讨论：是否可以完全依赖底层模型？
1. **模型的局限性**：底层模型是否能够处理复杂的、跨工具的任务？例如，Codex 在软件调试中需要用到截屏、日志分析等工具，这些操作超出了模型的语言处理能力。
2. **Harness 是否是“优化工具”还是“必要条件”？**：如果底层模型可以感知结果并自我优化，Harness 是否仍然是必须的？或者它更多是为了提升效率？
