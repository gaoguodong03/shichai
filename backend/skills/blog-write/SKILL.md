# 博客写作 Skill

先**对话**，再**生成**。与用户充分交流确认需求后，用户说「可以了」「开始写」等再执行生成流程。

---

## phase 1：对话阶段（必须先完成）

与用户进行自然对话，逐步明确以下信息。**不要一次性抛出所有问题**，根据用户回答灵活追问。用户已提供的信息无需重复询问。

### 需要确认的信息

| 信息 | 说明 |
|------|------|
| 主题 | 想写什么内容？核心观点是什么？ |
| 素材 | 有参考链接吗？（URL、文档、GitHub 等） |
| 目标读者 | 谁在读？技术深度如何？ |
| 目标关键词 | 希望用户搜索什么词找到文章？（可选） |
| 特殊要求 | 长度、风格、必须包含的内容等 |

### 对话原则

- **自然交谈**：像和同事讨论选题一样，不要像填表
- **逐步澄清**：用户说「写个 Docker 教程」→ 追问「写哪方面？入门还是进阶？有目标读者吗？」
- **确认再确认**：对模糊表述要追问，避免理解偏差
- **用户说可以了再动手**：听到「可以了」「开始写」「就这些」「写吧」等，才进入 phase 2

### 进入 phase 2 的触发语

用户表达以下任一含义时，结束对话、开始生成：
- 「可以了」「开始写」「写吧」「就这些」
- 「先这样」「按这个写」「没问题了」

---

## phase 2：生成阶段（对话完毕后才执行）

⚠️ 仅当 phase 1 对话完毕、用户确认后，才执行以下步骤。不可跳过。

### Step 1：收集素材

- 若有参考链接：用 fetch 等工具读取，不可仅凭标题猜测
- 主动搜索：补充最新资料、官方文档、权威来源

### Step 2：撰写文章

- 输出纯 Markdown 博客文章
- 写作规范：开头三要素（背景、定义、价值）、案例支撑、通俗类比、内链/外链
- 无需 Front Matter、分类、标签、封面图
