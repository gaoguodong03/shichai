# Agent 工程与框架实践知识提要

> 用途：为 Agent 工程设计、实现与评审提供知识支撑，涵盖任务分解、Skill 模块化、工具（Tool）设计、常见框架模式（以 LangChain 为代表）以及工程实践要点。

---

## 一、整体视角

- 将 Agent 系统视为：**模型 + 指令/系统提示 + 工具/环境 + 任务编排**
- 工程侧重点：
  - 如何把自然语言需求拆成稳定的、可重复的步骤
  - 如何用 Tool/MCP 等接口安全访问外部世界
  - 如何管理复杂任务中的多轮调用与状态

---

## 二、任务分解与 Skill 模块化

- **任务分解（Task Decomposition）**
  - 从用户需求出发，将问题拆分为：
    - 信息收集（搜索、抓取、读取文件或数据库）
    - 分析与推理（综合信息、做判断）
    - 结果生成（生成文本、代码、结构化结果）
    - 执行与反馈（调用外部系统、写文件、发请求）
  - 在复杂场景下可画成任务树或有向图，明确依赖关系

- **Skill 模块化原则**
  - 单一职责：每个 Skill 专注于一个较清晰的能力领域
  - 可组合：Skill 之间输入输出尽量结构化，便于编排与复用
  - 层次清晰：
    - 底层：通用能力（知识模块、通用工具使用模块）
    - 中层：领域或任务级助手（某业务线、某文档类型等）
    - 顶层：总控 Agent / 路由器，根据问题调度下游 Skill

## 三、工具（Tool）与 MCP 设计要点

- **何时需要 Tool / MCP**
  - 需要访问实时信息（搜索、Web 抓取）
  - 需要读写文件、调用脚本或执行代码
  - 需要访问数据库或第三方 API
  - 需要浏览器自动化等复杂交互环境

- **工具接口设计**
  - 输入：
    - 使用结构化参数（JSON 可序列化），避免解析复杂自然语言
    - 参数命名贴近业务含义，增加自解释性
  - 输出：
    - 至少包含两层：
      - 结构化结果（便于后续程序消费）
      - 摘要文本（便于模型理解与后续自然语言使用）
  - 错误处理：
    - 区分“业务失败”和“系统错误”
    - 输出中显式包含错误代码与简要错误原因

- **与 MCP 的关系**
  - MCP 提供一种标准化的工具注册与调用协议
  - 一般建议：
    - 将稳定的外部能力封装成 MCP Server 的工具
    - 在上层 Agent / Skill 中用自然语言说明何时、如何调用这些工具

## 四、常见 Agent 框架模式（以 LangChain 为代表）

- **Chains（链式调用）**
  - 适合步骤较固定的流程，如：
    - 先解析需求 → 再检索知识库 → 再整理回答
  - 工程实现简单、可预测性强

- **单 Agent + 多 Tools**
  - Agent 根据当前对话状态和系统提示，自主选择调用哪些工具
  - 适合工具数量不多、任务类型相对集中但不完全固定的场景

- **Router / 多 Agent 协同**
  - Router/Manager 负责根据用户问题路由到不同专长的 Agent 或 Skill
  - 典型结构：
    - Router Agent：判断问题类型
    - 若干 Worker Agent：各自负责一个领域（如写作、编码、分析等）
  - 适合功能多样、领域边界比较清晰的系统

- **Plan & Execute（规划 + 执行）**
  - 先由 Planner 生成一个大致计划（分步目标）
  - 再由 Executor 按计划逐步执行，每一步可调用工具或子 Agent
  - 优点：对复杂、开放任务有更好表现；缺点是实现和调试复杂度更高

## 五、工程实践要点

- **鲁棒性**
  - 为每一个外部调用考虑失败路径和重试策略：
    - 网络失败、超时、第三方 API 返回异常等
  - 在系统提示中对 Agent 进行“防御式”指导：
    - 明确说明出现错误时应如何汇报与尝试恢复

- **可观测性**
  - 日志中记录：
    - 调用了哪些工具、参数与返回摘要
    - 关键中间结论（避免只记录最终回答）
  - 便于后续复盘问题对话、调试提示词和工具设计

- **可演进性**
  - 避免把所有逻辑写死在一个巨大系统提示中
  - 建议：
    - 将领域知识整理进独立的 Skill / reference 文档
    - 用配置或简单路由逻辑控制不同 Skill 的启用与优先级

---

## 六、与计算机系统知识的结合点

- 计算机网络：
  - 影响工具调用的延迟与吞吐、接口设计的健壮性
- 操作系统与并发：
  - 影响后端服务的资源调度与并发处理能力
- 数据库系统：
  - Agent 系统中的状态存储、对话记录、知识库与索引设计
- 软件工程：
  - 决定整体架构、模块划分、协作方式与演进策略
