# 从链接到博客

当用户**只给出一段 URL**（或明确说「根据这个链接写博客」）时，按以下**固定流程**执行：先整理该文思想 → 询问你的观点与生成偏好 → 成文 → **默认直接**生成封面与文内配图（不需再问用户要不要）。

---

## 标准流程（五步）

### 第 1 步：抓取并整理思想

- **抓取方式**：使用 **run_skill_script_url-to-blog**，`script_path=fetch_url_extract.py`，`input_json` 为 `{"url": "https://..."}`（可选 `"max_chars": 50000`）。脚本会请求 URL 并用 trafilatura 提取中心正文，stdout 为 JSON：`{"title": "...", "text": "...", "url": "..."}`；失败时为 `{"error": "..."}`。你根据返回的 `title` 与 `text` 整理思想。
- **动作**：抓取成功后，用 2～5 条要点**整理该文的核心思想**（论点、论据、结论、可借鉴处），并简要呈现给用户。
- **禁止**：不得仅凭网页标题或猜测写文，必须先调用本脚本拿到正文再整理。

### 第 2 步：询问用户观点与偏好

在整理完思想后，**主动询问**用户（可一次问完，也可自然对话中带出）：

| 询问项 | 说明 |
|--------|------|
| **你的观点** | 你同意/不同意哪几点？有没有想特别强调或反驳的？ |
| **读者与用途** | 写给谁看？用于个人博客、公众号、内部分享？ |
| **长度与风格** | 希望多长？偏干货、偏故事、偏科普？ |
| **必须包含/避免** | 有没有必须写进去的点或不想涉及的角度？ |

得到用户回复后，再进入成文，不要跳过本步直接开写。

### 第 3 步：生成博客正文

- 结合「原文思想」与「用户观点与偏好」撰写一篇**完整 Markdown 博客正文**。
- 结构建议：开头交代背景/由头（可提参考链接），中间按你的观点展开，案例与类比支撑，适当内链或外链，结尾收束。
- 需要补充资料时，使用 **exa_web_search_exa** 或 **zhipu-web-search_web-search**（参数名 `query`），并在文中或文末注明来源。
- 成文后**不要问**「要不要封面/配图」；直接进入第 4、5 步生成封面与配图。

### 第 4 步：封面图（成文后默认执行）

- **时机**：正文生成后**直接**按 **cover-image** 技能生成封面，不要先问用户。
- **做法**：以当前文章标题与核心主题为输入，按 cover-image 的五维（类型、色板、渲染、文字、情绪）生成封面图；使用 **run_skill_script** 调用 `cover-image` 技能下的 `scripts/generate_image.py`，`input_json` 为 `{"description": "从文章提炼的封面提示词", "pic_size": "1024x576"}`（16:9）或 `1024x1024`（1:1）。工具返回的 stdout 为图片 URL，须在回复中用 `![封面](URL)` 或可点击链接呈现给用户。
- **输出位置**：封面图与 prompt 建议写入当前会话工作区，例如 `cover-image/{主题-slug}/cover.png`，并在回复中说明路径。

### 第 5 步：文内配图（成文后默认执行）

- **时机**：封面生成后**直接**按 **article-illustrator** 技能为文章生成配图，不要先问用户。
- **做法**：分析文章结构，在合适位置定出配图方案（类型：infographic / scene / flowchart 等；风格：notion / elegant / minimal 等）。为每张图写 prompt，使用 **run_skill_script_article-illustrator**（`script_path=generate_image.py`，`input_json` 含 description、pic_size）；工具返回的 stdout 为**该张图的 URL**，记下每张图对应的 URL 与插入位置（如「第 2 段后」「小结前」）。

### 第 6 步：输出一条完整推文（必做）

- **目标**：最终必须交付**一条完整推文**，即「封面 + 正文且正文中已嵌入所有配图」的一体内容，用户可直接复制使用或发布。
- **格式**：在**最后一次回复**中按以下顺序输出（全部在同一段 Markdown 里）：
  1. **封面**：先写 `![封面](封面图片URL)`（第 4 步得到的 URL）。
  2. **正文与配图**：接着输出**完整正文**，在对应段落之间已插入各张配图的 Markdown，即 `![描述](该张配图URL)`，顺序、位置与第 5 步规划一致。
  3. 可选：在文末简短说明「封面 1 张，文中配图 N 张」。
- **禁止**：不要只分别贴「正文」「封面」「配图」而不合成一条；不要漏掉封面或某张配图的插入。
- **说明**：配图工具返回的是图片 URL，插入时用 `![描述](URL)` 即可；无需本地 path，以 URL 嵌入即可形成完整推文。

---

## 流程小结

```
用户输入 URL
    → 用 run_skill_script_url-to-blog(fetch_url_extract.py) 抓取并得到正文
    → 整理该文思想（2～5 条要点）并呈现
    → 询问：你的观点、读者、长度风格、必须包含/避免
    → 根据原文 + 用户观点生成博客正文（Markdown）
    → 直接按 cover-image 生成封面（得到封面 URL）
    → 直接按 article-illustrator 生成多张配图（得到每张配图 URL 及插入位置）
    → 第 6 步：输出一条完整推文 = ![封面](封面URL) + 正文（段落间已插入 ![描述](配图URL)）
```

---

## 可选：只做某几步

- 用户若说「只帮我整理一下这篇文章在讲什么」：只执行第 1 步。
- 用户若说「先不要封面」「先不要配图」「只要正文」等：完成第 1～3 步即停，不执行第 4、5 步；可说明「需要时再说，我可以再为你生成封面和配图」。

---

## 避免

- 不要跳过「整理思想」或「询问观点」直接写文。
- 不要只凭 URL 或标题猜测内容；必须先用 run_skill_script_url-to-blog（fetch_url_extract.py）拿到正文。
- 生成封面/配图时不要使用 call_api，只用 run_skill_script 或 MCP 图像工具；工具返回的图片 URL 必须用于第 6 步，全部插入到最终一条推文中呈现给用户。
