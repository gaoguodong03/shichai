## 三、状态机这一页怎么讲（对应文档 53–80 行）

1. **先讲角色**：后端内存里维护编排上下文；前端收到的 **`end` 事件带 `phase`（英文枚举）**，与 `backend/app/agent/orchestrator_state.py` 中 `OrchestrationPhase` 一致。
2. **再亮图**：`stateDiagram-v2`（规划中 → 执行中 → 等待用户 → … → 已结束），见 [技术架构详解.md](./技术架构详解.md) 该节。
3. **三句人话**  
   - **执行中**：专家在跑 LLM / 工具。  
   - **等待用户**：本轮流结束或要你补充信息。  
   - **招募中**：与需要拉新专家相关（与 `build_end_payload` 里对 `NEED_RECRUIT_EXPERT` 等的归一化一致，不必背枚举）。
4. **诚实一句**：图上箭头是**常见路径**；源码里还有钩子、中断、pending 专家续跑等，追问再展开 [梳理.md](./梳理.md) 或 `group_chat.py`。

**衔接语（可用）**：状态机页连接「产品里谁先说话」与「后端推给前端的 `end` 契约」。

## 四、口播提纲（按顺序）

1. **Hook（~30s）**  
   教学研里单一通用助手难覆盖「角色分工 + 工具链 + 数据留在校内/组内」；本项目是私有化、多用户、多专家协作环境。

2. **是什么（~1 min）**  
   Web 前端 + FastAPI；统一「带主持人的会话」；专家可绑定模型、Skill（`SKILL.md` + 脚本）、MCP。

3. **架构（~1.5 min）**  
   第一张 LR 图：前端只做 UI 与流式消费；业务与推理在后端；每用户独立数据目录。

4. **关键路径（~2.5 min）**  
   第二张 LR 图：发消息 → `chat/stream` → 读盘与编排 → 专家 Agent → LLM + MCP/脚本 → SSE 回前端；点出 `content` / `message` / `end`。

5. **编排状态机（~2.5 min）**  
   按第三节讲；补充 `end` 里还有 `waiting_for_user`、`suggested_next_speaker`、`interrupt_reason`（不全展开）。

6. **实现层（~1.5 min）**  
   工具组装、SimpleAgent 流式转 SSE、落盘——各一句，后端岗可指 [梳理.md](./梳理.md)。

7. **扩展与收尾（~1 min）**  
   新能力：加 MCP / Skill / 专家实例；局限：依赖外部 LLM、部署形态等诚实一句。

## 六、追问备用：三问一分钟答法

### 1. 多租户隔离怎么实现？

**答法（约 1 min）**  
请求必须带 `Authorization: Bearer`，后端解析出用户名和稳定 `user_id`，在本次请求上下文里绑定「当前用户」。会话、专家配置、技能、工作区路径都落在 **`data/users/{user_id}/`** 下，代码里通过 `UserContext` 统一解析，避免硬编码。账号凭证可单独库存，不和对话 JSON 混在同一套业务路径里。这样同一套服务进程服务多用户，磁盘与逻辑上隔离。

### 2. 为什么用流式 / SSE 而不是一次 JSON 返回？

**答法（约 1 min）**  
专家回复可能很长，且中间要调 MCP、跑技能脚本，耗时可到分钟级。用**单连接上的流**（`event:` + `data:`，类似 SSE）可以边生成边推 `content`，用户先看到打字，再收到完整 `message`，最后 `end` 告诉本轮是否等你、下一轮建议谁。若等整段 JSON，首字节延迟大、体验差，也容易超时。前端在 `WorkspaceContent` 里按事件类型更新 UI。

### 3. 专家、Skill、MCP 在一次推理里怎么绑在一起？

**答法（约 1 min）**  
编排选出某个 `agent_id` 后，后端读该专家在配置里的 **`skill_ids`、`mcp_server_ids`**。对 Skill：从用户 `skills` 目录加载对应 `SKILL.md`，多 Skill 时还可按上下文选型，把正文与专家的 `system_prompt` 拼进系统侧提示。对 MCP：按用户 MCP 配置拉起工具列表，和 Skill 脚本工具一起在 `build_tools_for_group_chat` 里交给执行器。模型在一条流里可多轮调用工具，工具结果再喂回模型，最后落一条带 `skill_id` 的助手消息。
