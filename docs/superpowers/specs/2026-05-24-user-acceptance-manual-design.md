# 上线验收操作手册设计

## 1. 背景

当前仓库已有文字版用户说明 `docs/user-manual/user-guide.md`，但它更接近普通用户教程，缺少验收人员需要的图文操作路径、按钮标注、预期结果和不通过判定。

本规格定义一份面向验收人员的《书童四九上线验收操作手册》。手册用于上线前或交付验收时，指导验收人员按核心路径逐页操作系统，并根据页面结果判断是否通过。

## 2. 目标读者

目标读者是验收人员，包括项目方测试人员、交付验收人员和临时验收环境操作人员。

文档不面向开发者排查内部实现，也不作为完整产品百科。它只覆盖上线验收核心路径，强调“怎么点、看到什么算通过、什么情况算失败”。

## 3. 交付物

采用 Markdown + PDF 双交付：

- 源文档：`docs/user-manual/README.md`
- 截图目录：`docs/user-manual/images/`
- PDF 文档：`docs/user-manual/书童四九上线验收操作手册.pdf`

Markdown 是后续维护的源文件，PDF 是面向验收人员分发、归档和离线查看的交付文件。

## 4. 手册范围

第一版只覆盖上线验收核心闭环：

1. 登录、注册、登出再登录。
2. 工作空间新建会话、发送问题、查看回复、邀请专家、引用文件。
3. 资源中心新建和编辑场景。
4. 资源中心新建和编辑专家。
5. 资源中心新建和编辑技能，并检查依赖提示。
6. 资源中心配置工具。
7. 资源中心配置模型。
8. 设置中心配置主持人、密钥、沙箱、账号和配色。
9. 资源包导入预览、确认导入、导入后检查资源。
10. 验收记录表。

不在第一版范围内：

- 覆盖每个边角页面和低频管理动作。
- 编写开发者调试手册。
- 覆盖真实生产密钥、真实生产模型或真实客户数据。
- 对内部 API、数据库结构或代码模块做说明。

## 5. 验收环境前置条件

制作和使用手册前，需要满足以下条件：

- 前端和后端服务可以正常启动。
- 浏览器可以访问本地或验收环境地址。
- 使用专门的本地验收账号：`ggd@bupt.edu.cn`。
- 密码仅用于本地操作，不写入最终手册正文、截图标注或 PDF。
- 模型配置使用 `jeniya`。
- API Key 在本地验收时按用户提供的测试值填写；最终手册中按密钥处理，不展示明文。
- 账号内可以新建或保留统一命名的演示数据，例如“验收会话”“问答验收场景”“问答专家”“问答技能”。
- 资源包导入链路需要有可用的测试 ZIP 包或可以在验收过程中现场导出生成。
- 浏览器窗口尺寸固定，截图视觉风格保持一致。

## 6. 数据和敏感信息策略

手册截图和正文必须避免固化敏感信息：

- 不展示账号密码。
- 不展示 API Key 明文。
- 不展示真实业务地址、真实客户数据或不可公开的密钥标识。
- 如果截图无法避免出现敏感字段，必须先打码再写入 `docs/user-manual/images/`。
- 演示数据统一使用“验收”或“问答验收”前缀，避免和真实用户数据混淆。

## 7. 文档结构

`docs/user-manual/README.md` 建议结构如下：

1. 文档说明
   - 适用对象
   - 验收范围
   - 前置条件
   - 通过和不通过的通用判定
2. 验收环境准备
   - 访问地址
   - 登录账号
   - 模型和密钥配置要求
   - 截图和数据命名约定
3. 登录与账号入口
   - 登录
   - 注册
   - 登出后重新登录
4. 工作空间验收
   - 新建会话
   - 删除会话
   - 发送问题并查看回复
   - 邀请专家
   - 移除专家
   - 引用或上传文件
   - 工作区文件增删
   - 新建场景
   - 输入@后制定专家发言
5. 资源中心验收
   - 场景
   - 专家
   - 技能
   - 工具
   - 模型
   - 文件
6. 设置中心验收
   - 主持人设置
   - 密钥
   - 沙箱
   - 账号
   - 配色
7. 资源包导入验收
   - 上传资源包
   - 查看导入预览
   - 确认导入
   - 检查导入结果
8. 验收记录表
   - 功能路径
   - 操作人
   - 验收日期
   - 是否通过
   - 问题记录

## 8. 单个页面章节模板

每个页面或流程章节统一使用以下结构：

```md
## 页面或流程名称

### 验收目标

说明本流程要验证什么。

### 前置条件

列出进入该页面或执行该流程前必须满足的状态。

### 页面截图

截图占位：`docs/user-manual/images/<step-name>.png`

### 按钮和区域说明

1. 区域或按钮名称：说明用途。
2. 区域或按钮名称：说明用途。

### 操作步骤

1. 第一步。
2. 第二步。
3. 第三步。

### 预期结果

说明验收人员应该看到的页面反馈、数据变化或跳转结果。

### 不通过判定

列出算作验收失败的问题，例如按钮无响应、保存后丢失、页面报错、刷新后数据不存在等。
```

## 9. 截图规范

截图需要通过浏览器实际操作生成，避免使用静态想象图。

- 使用固定桌面宽屏尺寸。
- 每张截图只服务一个页面或一个关键流程节点。
- 关键按钮和区域需要编号标注。
- 标注风格保持一致，例如红框、数字圆点和简短标签。
- 截图文件名使用英文小写和短横线，例如 `workspace-create-session.png`。
- 截图保存到 `docs/user-manual/images/`。
- Markdown 中使用相对路径引用图片。

## 10. PDF 导出要求

PDF 从 Markdown 源文档导出，不手写第二份内容。

PDF 需要满足：

- 目录结构清晰。
- 图片清晰可读。
- 页面不出现明显截断。
- 表格不横向溢出。
- 敏感字段已打码。
- 文件名为 `书童四九上线验收操作手册.pdf`。

## 11. 验证方式

实施完成后需要验证：

- `docs/user-manual/README.md` 中所有图片路径存在。
- Markdown 能正常预览。
- PDF 能打开，主要章节和截图完整。
- 手册覆盖第 4 节列出的核心路径。
- 文档中没有明文密码或 API Key。
- 至少按手册抽查一条完整路径：登录 -> 工作空间新建会话 -> 发送问题 -> 查看回复。

## 12. 后续实施计划入口

本规格确认后，再进入实施计划。实施计划应覆盖：

1. 启动或确认本地服务。
2. 准备验收账号和演示数据。
3. 使用浏览器逐页操作并截图。
4. 对截图进行必要标注和打码。
5. 编写 `docs/user-manual/README.md`。
6. 从 Markdown 导出 PDF。
7. 执行文档完整性和敏感信息检查。
