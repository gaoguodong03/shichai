## 分层设计

### 场景任务契约

`scenario.json.system_prompt` 只描述所有参与者共享的任务契约：

- 场景目标：围绕一个可讨论问题，通过材料、引导、同伴讨论、教师追问和终评帮助用户形成更清晰的个人判断；
- 适用范围：需要材料支撑、观点碰撞、边界分析和反思总结的伴学研讨；
- 共同要求：角色必须依据用户输入、最近可见消息、真实材料和实际工具结果发言，不虚构事实或完成状态；
- 讨论纪律：材料包形成前不进入自由讨论，教师追问前保留用户和同伴讨论空间，终评后不再开启新任务；
- 完成标准：教师已经基于用户集中作答给出终评，用户要求的研讨主题已经完成收束。

场景提示词不包含专家长期职责、主持人阶段表、Skill 执行步骤或平台输出 JSON。

### 主持人

场景内嵌一个名为 `伴学研讨主持人` 的主持人，使用目标账号现行主持人长期提示词形状，负责：

- 纯调度，不代替专家输出专业正文；
- 一次只调度一位专家；
- 形成包含目标、输入、交付结果和完成条件的自包含任务单；
- 按四列表判断阶段；
- 输出当前主持人结构化结果。

通用职责和输出合同写入 `scenario.json.host.system_prompt`；具体伴学研讨流程只写入 `skill-companion-learning-host/SKILL.md`。

### 五位专家

每位专家的 `agent.json.system_prompt` 保存长期身份、职责边界、专业标准、执行要求和当前专家结构化输出合同：

| 专家 | 长期职责 | 明确排除 |
| --- | --- | --- |
| 伴学研讨——引导教学的教师 | 定题、材料引导、教师追问、最终评价 | 不整理材料包，不参与普通同伴轮次，不调度其他专家 |
| 伴学研讨——材料搜索与研究 | 搜索、筛选并整理可比较的讨论材料 | 不表达讨论立场，不承担教师引导或终评 |
| 伴学研讨——理性同伴 | 分析边界、机制、证据和可执行性 | 不居高临下辩论，不推进场景阶段 |
| 伴学研讨——感性同伴 | 表达直觉、困惑、经验感受和朴素判断 | 不扮演低水平学生，不替用户下结论 |
| 伴学研讨——推动讨论的助教 | 在明确请求下纠偏、补位或形成讨论预案 | 不进入主流程固定阶段，不连续发言，不改变当前阶段 |

五位专家分别只绑定一个对应普通 Skill。专家长期提示词不复制主持人阶段表，普通 Skill 不复制专家身份和结构化输出合同。

## Skill 设计

### 普通 Skill

五个普通 Skill 均遵循 `docs/skills/skill-standard.md`，Frontmatter 只使用 `name`、`description` 和当前 `allowed-tools`，正文只包含 `执行规则` 和 `结束条件`。

- 教师 Skill 根据主持人任务单区分定题、材料引导、教师追问和终评，并规定各阶段的内容边界和语言质量；
- 材料研究 Skill 生成三条可比较材料、覆盖摘要和张力摘要，最多使用三次检索或抓取；联网失败但已有足够公共知识时仍形成材料包；
- 理性同伴 Skill 每轮围绕一个具体观点和一个材料点，推进边界、机制、证据或做法；
- 感性同伴 Skill 每轮只表达一个核心直觉、困惑或生活经验，并结合一个具体材料点；
- 助教 Skill 先确认用户明确请求的纠偏、补位或预案目标，只短促介入一次，完成后不继续行动。

只有材料研究 Skill 声明目标账号已经存在的 MCP server：`Exa 搜索` 和 `Linkup抓取网页`。其余五个 Skill 的 `mcp`、`http_api` 和 `python` 均为空列表。

### 主持人 Skill

主持人 Skill 遵循 `docs/skills/host-skill.md`，正文只有一张四列表。主阶段为：

```text
（无） → 选题 → 材料包 → 教师材料引导 → 学生初步回应
      → 自由讨论 → 教师追问 → 学生集中作答 → 教师终评 → end
```

阶段规则满足以下要求：

1. 首轮用户给出主题或明确要求开始研讨时调度教师定题；缺少研讨意图和主题时只询问一个必要问题。
2. 教师完成定题后调度材料研究专家；材料包完成后再调度教师做材料引导。
3. 教师材料引导完成后先询问用户的初步回应，不直接调度同伴或继续调度教师。
4. 自由讨论至少包含用户正文回应和一位同伴回应；理性同伴与感性同伴依据最近观点需要选择，不机械轮换。
5. 已形成可追问的具体观点、分歧、证据缺口或行动方案，或用户明确要求收束时，调度教师提出一到三个追问。
6. 用户集中回答追问后调度教师终评；终评形成后结束，不再安排专家。
7. 用户明确要求助教纠偏、补位或讨论预案，且目标明确时，调度完整名称 `伴学研讨——推动讨论的助教`，完成后保持原阶段；没有明确请求时任何阶段都不得调度助教。
8. 助教例外按适用阶段展开为可直接判断的表格行，不使用通配阶段或表外补充规则。

## 数据引用

`scenario.json.agent_names` 固定引用五位完整专家名称。每个专家的 `skills` 只引用对应的新 Skill 目录名。主持人引用 `skill-companion-learning-host`。

所有引用只使用名称和 Skill 目录名，不保留旧 `agent_id`、旧 `skill_id`、角色简称或兼容字段。目标账号已有 `Exa 搜索` 和 `Linkup抓取网页` 工具资源继续复用，不复制工具配置。

## 验证设计

目标账号资源位于本地用户数据目录，不新增依赖特定账号数据的提交测试。实施时使用一次性、只读验证脚本和现有加载逻辑验证：

1. 新增的六个 `SKILL.md` 在写入前先建立会失败的契约检查，确认缺失资源能够被检测；
2. 五个 `agent.json` 和一个 `scenario.json` 均可解析；
3. 六个 Skill Frontmatter 均可解析，普通 Skill 只有 `执行规则` 和 `结束条件`，主持人 Skill 只有一张四列表；
4. 场景引用的五位专家均存在，五位专家引用的 Skill 均存在，主持人引用的 Skill 存在；
5. 材料研究 Skill 声明的两个 MCP server 与目标账号工具名称完全一致；
6. 所有普通 Skill 均不包含旧字段 `auto-tools`、`reference-labels`、隐藏状态块、专家身份章节、主持人调度或平台输出字段；
7. 主持人 Skill 不包含旧 `agent_id`、JSON 示例、长期职责或表外流程章节；
8. 主持人阶段表覆盖首轮、九阶段推进、用户等待、助教显式调度和结束状态；
9. 通过现有资源加载与缺失引用校验逻辑检查目标账号，不修改任何已有会话或历史文件；
10. 最后检查目标账号新增路径、文件内容和引用清单，确认没有覆盖原资源。
