# 深度研究场景（观点/名词 → 核查 → 研究 → 报告）

本场景用于：**用户提出一个观点或一个名词**，系统先检查该观点是否正确（或该名词的常见理解是否有偏差），再进行深入研究，最后整理成一份结构化报告。

**主持人逻辑不单独定制**：使用系统默认主持人即可。流程由「深度研究专家」在自身逻辑内完成（先核查再研究再报告），或与「内容核查专家」协作（专家先核查，深度研究专家收到结论后直接做研究与报告）。

---

## 流程概览

1. **用户输入**：提出一个观点（如「某说法是否正确」）或一个名词/概念（如「请研究一下 XXX」）。
2. **核查阶段**：由「深度研究专家」自己完成，或由「内容核查专家」先发言完成——观点是否成立、常见误解、权威来源等。
3. **研究阶段**：深度研究专家基于核查结论，拆分子问题，使用搜索与抓取工具多阶段调研。
4. **报告阶段**：深度研究专家输出结构化报告（摘要、背景、现状、案例、结论与参考资料）。

---

## 人员与 Skill 配置（1 人即可，2 人可选）

### 推荐配置

| 配置 | 成员 | 说明 |
|------|------|------|
| **1 人** | 仅「深度研究专家」 | 专家自带核查+研究+报告全流程，由系统主持人点名即可，无需单独主持人 DHA。 |
| **2 人** | 「内容核查专家」+「深度研究专家」 | 主持人先点到核查专家做核查，再点到深度研究专家做研究与报告；专家若收到 next_prompt 中已有核查结论则直接从研究开始。 |

**不需要**单独的「深度研究主持人」DHA；主持人使用系统默认逻辑。

### DHA 实例（`backend/config/dha_instances.json`）

| DHA ID | 名称 | 角色 | Skill | MCP |
|--------|------|------|-------|-----|
| `dha-deepresearch-exp` | 深度研究专家 | 独立完成「核查→研究→报告」全流程，或基于已有核查结论直接做研究与报告 | deep-research、content-checker | exa、fetch、zhipu-web-search、file-reader |
| `dha-c1bf68ba` | 内容核查专家 | 事实核查与可信度评估（可选，与深度研究专家协作时使用） | content-checker | exa、fetch、file-reader |

### Skill 说明

- **deep-research**（深度研究）：对齐目标 → 拆分子问题 → 分阶段调研（概念与背景、现状与方案、案例、趋势与风险）→ 结构化报告。支持「观点/名词先行」：先核查再研究，可由本技能执行者一体化完成。
- **content-checker**（内容核查）：提炼待核查主张 → 多源搜索与抓取 → 逐条判定 → 总体结论与引用。深度研究专家已挂载此技能，可独立做核查；也可与专职内容核查专家分工。

## 脚本配置

- **write_report.py**（`backend/skills/deep-research/scripts/write_report.py`）  
  - 用途：将报告正文格式化为「建议保存路径 + 完整 Markdown」，供 Agent 呈现给用户或后续写入工作区。  
  - 调用方式（run_skill_script）：`script_path=write_report.py`，`input_json={"title": "报告标题", "content_md": "# 报告全文 Markdown..."}`。

---

## 如何使用（群聊）

1. **新建群聊**：工作空间 → 「+ 新建会话」。
2. **邀请成员**（二选一或组合）：
   - **仅 1 人**：只添加「深度研究专家」→ 由系统主持人点名，专家在一轮或多轮内完成核查→研究→报告。
   - **2 人**：添加「内容核查专家」+「深度研究专家」→ 主持人按通用逻辑点名，核查专家先发言做核查，深度研究专家再基于结论做研究与报告。
3. **无需单独设主持人**：使用默认群聊主持人即可。
4. **填写讨论目标并发送**，例如：
   - 「请先验证“某某说法”是否成立，再对这个主题做深入调研，最后给一份报告。」
   - 「研究“碳中和”：先核查常见理解有没有偏差，再深入分析现状与案例，最后整理成报告。」

---

## 单聊使用

在单聊中选中 **deep-research**（或同时选 content-checker），由同一 Agent 走「观点先行」流程：先核查观点/名词，再研究与报告。报告可用 run_skill_script 调用 `write_report.py` 得到建议路径与正文后呈现给用户。
