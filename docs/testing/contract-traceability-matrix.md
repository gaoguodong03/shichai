# 契约实施追踪矩阵

本文用于把契约条款落到代码、测试和后续修改动作。它不是普通 TODO 清单，而是后续治理代码时的工作台。

状态只使用以下五类：

| 状态 | 含义 |
|------|------|
| 已实现且有测试 | 文档、代码和自动化测试已经形成闭环。 |
| 已实现但测试不足 | 代码路径基本符合契约，但缺少明确测试编号或覆盖不完整。 |
| 文档已定，代码待改 | 契约已经确定，运行时代码仍需按契约调整。 |
| 代码存在旧逻辑，待删除 | 主路径仍有旧字段、旧兜底或旧入口，需要删除并补测试。 |
| 需确认 | 契约、代码或产品口径仍有歧义，修改前需要先确认。 |

## 使用规则

1. 修改契约前，先新增或更新一行追踪项。
2. 修改代码前，确认该行状态不是 `需确认`。
3. 删除旧逻辑时，把状态改为 `代码存在旧逻辑，待删除`，并补拒绝旧字段或旧入口的测试。
4. 测试通过后，把状态更新为 `已实现且有测试` 或 `已实现但测试不足`。
5. 不把真实用户数据、历史运行输出或临时验收记录写入本文。
