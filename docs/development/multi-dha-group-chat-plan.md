# 多 DHA 群聊开发计划

## 一、目标概述

将 DHA 从「单人对话」扩展为「多 DHA 群聊」模式，实现：
- **群聊界面**：多个 DHA 以不同角色参与讨论，协作解决问题
- **领导人 DHA**：主持讨论、决定发言顺序，预留现实感知与定时任务扩展
- **保留单人模式**：用户仍可与单个 DHA 单独对话

---

## 二、核心概念设计

### 2.1 概念定义

| 概念 | 说明 |
|------|------|
| **DHA 实例** | 一个具有角色、技能、MCP 配置的 AI 智能体，可参与群聊或单人对话 |
| **群聊会话 (Group Session)** | 多个 DHA 参与的讨论会话，有唯一 `group_session_id` |
| **领导人 DHA (Leader DHA)** | 群聊中的主持人，负责：决定谁发言、控制讨论节奏、后续可接入现实感知/定时任务 |
| **参与者 DHA** | 群聊中的普通成员，按领导人指定发言，或根据讨论上下文参与 |

### 2.2 模式对比

| 维度 | 单人模式（现有） | 群聊模式（新增） |
|------|------------------|------------------|
| 参与者 | 用户 + 1 个 DHA | 用户 + N 个 DHA（含 1 个领导人） |
| 发言顺序 | 用户 → DHA → 用户 → … | 由领导人 DHA 决定 |
| 会话类型 | `session`（1v1） | `group_session`（群聊） |
| 记忆/上下文 | 单会话历史 | 群聊共享历史 + 各 DHA 可带角色记忆 |

---

## 三、开发计划（分阶段）

### 阶段 0：前期准备（讨论与设计）

- [x] 确定 DHA 实例的配置模型（沿用全局 skill/mcp，DHA 只做启用/禁用）
- [x] 确定领导人调度策略（每轮都调领导人；领导人判断 task_done，未完成则当前 DHA 继续）
- [x] 确定用户打断与覆盖规则（见 3.3）
- [x] 确定群聊与单人模式的入口切换方式（导航栏增加「群聊」入口，与 Chat 并列）

---

### 阶段 1：数据模型与后端基础

**目标**：建立群聊相关的数据模型和 API 骨架。

#### 1.1 DHA 实例配置

- **Skill/MCP**：沿用现有全局配置；创建/编辑 DHA 时只对该 DHA 做**启用/禁用**（勾选哪些 skill、哪些 MCP 对此 DHA 可用），不单独存一份 skill/mcp 内容。
- **DHA 配置模型**：
  - `dha_id`: 唯一标识
  - `name`: 显示名称
  - `role`: 角色描述（如「技术专家」「产品经理」「主持人」）
  - `system_prompt`: 可选，该 DHA 的系统提示词
  - `skill_ids`: 启用的技能 ID 列表（对应全局 skills 的子集）
  - `mcp_server_ids`: 启用的 MCP server ID 列表（对应全局 MCP 的子集）
  - `is_leader`: 是否为领导人类型

- **存储**：`config/dha_instances.json` 或数据库表

#### 1.2 群聊会话模型

- `group_session_id`: 唯一标识
- `title`: 群聊标题
- `dha_ids`: 参与的 DHA 列表（含领导人）
- `leader_dha_id`: 领导人 DHA
- `messages`: 群聊消息列表（见下）
- `created_at`, `updated_at`

#### 1.3 群聊消息模型

- `message_id`
- `role`: `"user"` | `"assistant"`
- `dha_id`: 若 `role=assistant`，标识是哪个 DHA 发言
- `content`: 消息内容
- `meta`: 可选（skill_id, tool_calls 等）
- `timestamp`

#### 1.4 后端 API 骨架

- `GET /api/dha/instances` - 获取 DHA 实例列表
- `POST /api/dha/instances` - 创建 DHA 实例
- `PUT /api/dha/instances/{id}` - 更新 DHA 实例
- `GET /api/group-sessions` - 获取群聊会话列表
- `POST /api/group-sessions` - 创建群聊会话（选择 DHA、指定领导人）
- `GET /api/group-sessions/{id}` - 获取群聊详情与消息
- `POST /api/group-sessions/{id}/chat` - 发送消息到群聊；请求体支持 `override_next_speaker: "dha_id" | null`（用户覆盖领导人决议时传指定 dha_id，否则由领导人决定）

---

### 阶段 2：领导人调度与发言逻辑

**目标**：实现领导人 DHA 决定「谁发言」的核心逻辑。

#### 2.1 发言调度流程

- **每轮 DHA 发言后都调用领导人**，由领导人判断：当前发言的 DHA 是否已完成本轮任务；未完成则让该 DHA 继续发言，完成则决定下一发言人。

```
用户发送消息 / 上一轮 DHA 发言结束
         │
         ▼
┌─────────────────────────────────────────┐
│ 领导人 DHA 调用                          │
│ 输入：群聊历史 + 当前讨论状态 + 刚发言的 DHA │
│ 输出：task_done（当前 DHA 是否完成任务）   │
│       next_speaker_id（下一发言人）        │
│       或 "user"（等待用户输入）           │
│       或 "end"（讨论结束）                │
└─────────────────────────────────────────┘
         │
         ├─ task_done=false → 当前 DHA 继续发言（再跑一次该 DHA 的 Agent）
         │
         └─ task_done=true → 若 next_speaker_id 为某 DHA：
               → 调用该 DHA 的 Agent，输入群聊上下文
               → 流式输出该 DHA 的回复
               → 保存到群聊历史
               → 再次调用领导人，决定下一轮
```

#### 2.2 领导人 DHA 的 Prompt 设计

- 系统提示词需包含：
  - 当前群聊中所有 DHA 的角色与职责
  - 讨论目标（来自用户首条消息或最近用户消息）
  - 输出格式：JSON `{"task_done": true|false, "next_speaker": "dha_id" | "user" | "end", "reason": "..."}`  
  - 当 `task_done=false` 时，下一轮仍由当前发言的 DHA 继续；为 `true` 时由 `next_speaker` 决定

#### 2.3 被选中 DHA 的上下文

- 输入：群聊历史（最近 K 轮）+ 用户原始问题 + 当前讨论进展
- 系统提示词：该 DHA 的角色 + 绑定的 Skill + 工具列表
- 输出：该 DHA 的发言内容（可含 tool_calls，与现有 ReAct 一致）

---

### 阶段 3：前端群聊界面

**目标**：实现群聊 UI，与现有单人 Chat 并存。

#### 3.1 导航与入口

- 在主导航增加「群聊」入口（与 Chat、Files、Skills 等并列）
- 或：在 Chat 模块内增加 Tab：「单人对话」|「群聊」

#### 3.2 群聊界面布局

- **左侧**：群聊会话列表 + 新建群聊
- **中间/主区域**：群聊消息流
  - 每条消息展示：发言人（用户 / DHA 名称 + 角色）、头像、内容
  - 支持 Markdown、ReAct 步骤展示（与现有 ChatView 类似）
- **右侧可选**：当前群聊的 DHA 列表、角色说明

#### 3.3 用户打断与覆盖领导人决议（已定 + 建议）

- **已定**：在领导人决定「下一发言人」之前，用户可打断并发言，并可**覆盖**领导人的决议（指定下一发言人）。
- **实现建议**：
  1. **打断时机**：在「某 DHA 发言结束 → 等待领导人决策」这段时间内，输入框保持可输入，用户发送即视为打断。
  2. **用户消息处理**：用户发送的内容作为新的一条群聊消息写入历史，并参与后续领导人/被选 DHA 的上下文。
  3. **覆盖下一发言人**：在输入区增加可选控件「下一发言人」：默认「由领导人决定」；用户可改为「指定：DHA A / DHA B / … / 等待用户」。若用户指定了某人，则**跳过**领导人本轮调度，直接让指定 DHA 发言；若选「等待用户」则不再自动调用领导人，等用户下次发言后再由领导人调度。
  4. **与「仅插话」区分**：若用户只发文字、不改「下一发言人」，则仍按正常流程调用领导人，领导人的输入里会包含这条用户消息，从而自然考虑用户插话后再决定谁发言。
- **后端**：请求体可设计为 `{ "message": "用户内容", "override_next_speaker": "dha_id" | null }`，`null` 表示不覆盖，由领导人决定。
- **单人群聊**：支持创建仅包含 1 个 DHA 的群聊（无领导人或该 DHA 兼主持人），便于测试或简单场景；与单人 1v1 会话独立，不互相转换。

#### 3.4 与单人模式的切换

- 保留现有 Chat 路由/视图
- 群聊使用独立路由（如 `/group-chat`）或同一路由下不同 `mode`
- **单人会话与群聊**：不做「单人会话升级为群聊」或「群聊降级为单人」；但支持创建**仅含 1 个 DHA 的群聊**（单人群聊），与普通 1v1 会话并存。

---

### 阶段 4：流式输出与实时体验

**目标**：群聊中 DHA 发言支持 SSE 流式输出，与单人模式一致。

- 复用现有 `POST /api/chat/stream` 的 SSE 事件格式
- 新增 `POST /api/group-sessions/{id}/chat/stream`：
  - 请求体：`{ "message": "用户消息" }` 或 `{ "action": "continue" }`（继续下一轮）
  - 响应：SSE 流，包含 `react_step`、`content`、`end` 等
  - 需在事件中携带 `dha_id`，便于前端区分发言人

---

### 阶段 5：领导人扩展点（现实感知、定时任务）

**目标**：为领导人 DHA 预留扩展能力，便于后续接入。

#### 5.1 扩展点设计

- **现实感知**：领导人可调用 MCP 获取外部信息（如时间、天气、新闻），再决定讨论方向
- **定时任务**：如「每 5 分钟检查一次是否有新议题」→ 可抽象为领导人可调用的工具
- **实现方式**：为领导人 DHA 绑定专用 MCP 或 Skill，在调度前/后执行

#### 5.2 本阶段可做

- 在领导人 DHA 的 system_prompt 中预留「可调用工具获取上下文」的说明
- 为领导人单独配置 MCP（如 time、fetch）用于获取实时信息
- 定时任务可放在后续迭代，先实现「按用户/消息触发」的调度

## 四、技术要点与风险

### 4.1 技术要点

| 要点 | 说明 |
|------|------|
| **Token 控制** | 群聊历史可能很长，需对传入各 DHA 的上下文做摘要/截断 |
| **并发** | 多 DHA 串行发言，无需并发；若未来支持并行讨论需重新设计 |
| **领导人单点** | 领导人 DHA 的 LLM 调用频率高，需注意限流与成本 |
| **会话持久化** | 群聊会话与消息需持久化，与现有 session 存储方式统一（JSON 或 DB） |

### 4.2 风险与缓解

| 风险 | 缓解 |
|------|------|
| 领导人决策不稳定 | 提供 fallback：按固定顺序轮询；用户可随时覆盖「下一发言人」 |
| 群聊上下文过长 | 分层摘要：每轮 DHA 发言后生成简短摘要，只把摘要链传给下一人 |
| 开发量较大 | 分阶段交付：先实现最小可用（2 个 DHA + 简单轮流），再完善领导人调度 |

### 4.3 存储

- **群聊会话与消息**：与现有 session 共用同一目录（如 `data/sessions/`），当前开发阶段不再拆分或迁移存储结构；可通过 `session_type: "group"` 或单独文件前缀区分群聊数据。

---

## 五、最小可行版本（MVP）建议

为快速验证想法，建议 MVP 范围：

1. **DHA 实例**：支持 2～3 个预定义 DHA（含 1 个领导人）
2. **发言调度**：领导人用 LLM 决定下一发言人，失败时 fallback 为轮流
3. **群聊界面**：简化版，仅展示消息流 + 用户输入
4. **单人模式**：完全保留，不做改动

MVP 完成后再迭代：更多 DHA、更丰富的角色、现实感知、定时任务等。

---

## 六、已定结论（讨论结果）

| 问题 | 结论 |
|------|------|
| DHA 的 skill/mcp | 沿用全局配置；创建 DHA 时只做启用/禁用（勾选该 DHA 可用的 skill 与 MCP） |
| 领导人调度频率 | 每轮 DHA 发言后都调领导人；领导人判断当前 DHA 是否完成任务，未完成则让其继续发言 |
| 用户打断与覆盖 | 在领导人决定下一发言人前可打断并发言；用户可覆盖领导人决议、指定下一发言人（见 3.3） |
| 单人↔群聊转换 | 不需要；支持创建「单人群聊」（仅 1 个 DHA） |
| 存储 | 与现有 session 共用同一目录，不新增目录或迁移 |
