# 资源配置与使用说明

本文面向书童四九的实际使用者，说明如何在资源中心配置场景、专家、Skill、工具和模型，以及在会话中使用文件和脚本型 Skill。本文不面向后端开发调试，不要求用户理解服务器目录、沙箱挂载或内部 API。

## 1. 基本概念

书童四九的常用资源分为五类：

| 资源 | 作用 | 典型问题 |
| --- | --- | --- |
| 场景 | 保存一套可复用的工作流程，包括主持人配置和协作专家组合。 | “我要复用一套论文写作团队。” |
| 专家 | 承担某类专业任务的角色，可绑定模型和 Skill。 | “我需要一个只负责财务表格分析的专家。” |
| Skill | 可执行能力包，用来定义专家如何完成一类任务，可包含说明、脚本、模板和依赖。 | “专家需要跑脚本处理 Excel。” |
| 工具 | MCP Server 配置，为 Skill 提供外部工具能力。 | “这个 Skill 需要调用网页检索或专用接口。” |
| 模型 | 大模型服务配置，供主持人或专家调用。 | “这个专家使用哪个模型。” |

建议配置顺序：

1. 先配置模型和密钥，确保主持人、专家有可用模型。
2. 再配置 Skill，明确可执行能力、依赖和输入输出。
3. 然后配置专家，把角色、职责和 Skill 绑定起来。
4. 最后配置场景，把主持人与多个专家组织成可复用流程。
5. 在工作空间中选择场景或邀请专家，上传文件并发起任务。

## 2. 场景配置

场景用于保存一套稳定的协作结构。适合教学备课、科研论文、会议纪要、资料整理、网页抓取、音频转写等可重复工作流。

进入路径：`资源中心 → 场景`。

### 2.1 字段说明

| 字段 | 填写建议 |
| --- | --- |
| 名称 | 使用“业务对象 + 任务类型”的短名称，便于搜索和复用。 |
| 描述 | 说明场景适用范围、输入材料、预期产出和不适用情况。 |
| 场景主持人名称 | 使用稳定名称，例如“四九”“论文项目主持人”“资料整理主持人”。 |
| 场景主持人大模型 | 不确定时使用应用默认；需要更强调度能力时单独选择高质量模型。 |
| 场景主持人系统提示词 | 规定主持人如何分配任务、何时追问用户、何时交给专家。 |
| 主持人技能 | 仅绑定与调度、任务拆解、流程控制直接相关的 Skill。 |
| 协作专家 | 选择本场景需要的专家，避免把所有专家都加入同一场景。 |

### 2.2 名称设计

名称应能让用户在列表中快速判断用途。

推荐：

```text
科研论文写作
教学备课助手
会议纪要整理
招聘信息抓取
音频转写分析
```

不推荐：

```text
测试场景
默认场景
我的场景
综合助手
```

### 2.3 描述设计

描述应回答四个问题：

1. 这个场景处理什么任务。
2. 用户通常需要提供什么材料。
3. 最终会产出什么结果。
4. 哪些任务不适合使用该场景。

示例：

```text
用于科研论文写作与修改。用户可提供论文草稿、审稿意见、实验结果或目标期刊要求；场景会组织文献分析、结构修改、语言润色和格式检查等专家协作，产出修改建议、重写段落或投稿检查清单。不适用于需要真实实验执行或未授权数据获取的任务。
```

### 2.4 主持人系统提示词设计

主持人负责调度，不应替代专家完成专业产出。提示词应写清楚调度策略和边界。

推荐结构：

```text
你是本场景的主持人，负责理解用户目标、拆分任务、选择下一位专家发言，并在信息不足时向用户追问。

调度原则：
1. 先判断用户任务是否属于本场景范围。
2. 如果信息不足，先向用户确认关键输入，不要直接编造。
3. 需要专业处理时，把任务交给最匹配的专家，并给出明确 `speaker_task`。
4. 专家已完成后，汇总当前进展并判断是否还需要下一位专家。

边界：
1. 不代写专家的专业正文。
2. 不调用与本场景无关的 Skill。
3. 场景成员能力不足时，说明缺口并请用户调整场景或补充专家。
```

不建议在主持人提示词里写大量具体业务操作步骤。具体执行方法应写在专家或 Skill 中。

### 2.5 协作专家选择

一个场景只保留完成流程所必需的专家。专家过多会增加调度成本，也会让主持人更难选择下一位发言者。

建议按职责拆分：

| 场景 | 推荐专家组合 |
| --- | --- |
| 科研论文写作 | 结构专家、语言润色专家、审稿意见分析专家、格式检查专家 |
| 会议纪要整理 | 音频转写专家、纪要结构专家、待办提取专家 |
| 数据分析报告 | 数据清洗专家、统计分析专家、报告撰写专家 |
| 网页资料抓取 | 抓取执行专家、内容清洗专家、结果摘要专家 |

如果一个专家能稳定完成全部流程，不必为了形式拆成多个专家。

## 3. 专家配置

专家是会话中的专业角色。一个专家应有明确职责、稳定输出格式和清晰边界。

进入路径：`资源中心 → 专家`。

### 3.1 字段说明

| 字段 | 填写建议 |
| --- | --- |
| 名称 | 使用角色名称，不使用泛化名称。 |
| 大模型 | 不填则使用应用默认；高复杂推理、长文写作可选择更强模型。 |
| 描述 | 说明专家适合什么任务，帮助主持人和用户判断是否邀请。 |
| 系统提示词 | 定义专家身份、职责、处理流程、输出格式和禁止事项。 |
| 技能 | 绑定该专家真正需要使用的 Skill。 |

### 3.2 名称和描述设计

专家名称应体现职责，而不是体现人名或顺序。

推荐：

```text
论文结构专家
表格分析专家
会议纪要专家
网页抓取专家
合同审查专家
```

描述应写成可判断的能力范围：

```text
负责分析 Excel、CSV 等结构化表格，执行字段清洗、统计汇总和异常值解释，并输出可复核的数据分析结论。
```

不推荐：

```text
很厉害的数据专家。
可以帮你解决各种问题。
```

### 3.3 系统提示词设计

专家系统提示词应比描述更具体。建议包含：

1. 角色定位：专家是谁，负责什么。
2. 输入要求：需要用户提供哪些文件、参数或背景。
3. 工作流程：先检查什么，再执行什么，最后如何交付。
4. 输出格式：用 Markdown、表格、清单、文件路径还是结构化字段。
5. 能力边界：不能做什么，信息不足时如何追问。
6. 工具使用：何时使用绑定 Skill，何时只做文本分析。

示例：

```text
你是表格分析专家，负责处理用户上传的 Excel、CSV 或结构化文本数据。

工作流程：
1. 先确认用户要分析的文件路径、目标字段和期望输出。
2. 如果文件较大或需要计算，优先使用绑定 Skill 执行数据读取和统计。
3. 对结果进行解释，指出关键结论、异常点和可能的数据质量问题。
4. 如果生成文件，保存到 outputs/ 目录，并在回复中给出工作区相对路径。

输出要求：
1. 先给出结论摘要。
2. 再列出主要指标或表格。
3. 最后说明输出文件路径和后续建议。

边界：
1. 不编造不存在的数据。
2. 文件路径不明确时先列出工作区文件或向用户确认。
3. 不读取当前会话工作区之外的文件。
```

### 3.4 Skill 绑定原则

只给专家绑定实际需要的 Skill。绑定过多 Skill 会增加误选能力的概率。

建议：

- 文本型专家可不绑定 Skill，只使用模型能力完成分析和写作。
- 需要读取 PDF、Excel、音频、图片、数据库或批处理文件时，绑定脚本型 Skill。
- 需要外部接口或网页能力时，绑定声明了对应 MCP 的 Skill。
- 同一专家绑定多个 Skill 时，每个 Skill 的描述必须能清楚区分触发场景。

## 4. Skill 配置

Skill 是专家的可执行能力包。它可以只是一份操作说明，也可以包含脚本、模板、参考资料、图片素材和运行依赖。

进入路径：`资源中心 → 技能`。

### 4.1 字段说明

| 字段 | 填写建议 |
| --- | --- |
| 名称 | 使用用户能理解的能力名称。 |
| 描述 | 写清楚“什么时候使用、输入是什么、产出是什么”。 |
| MCP 依赖 | 仅选择该 Skill 运行时必须使用的 MCP 工具。 |
| Python 依赖 | 页面编辑时每行一个 Python 包；保存到 `SKILL.md` 时写入 `allowed-tools.python` 数组。 |
| 正文 | 写明触发条件、输入要求、执行步骤、输出格式和结束条件。 |
| 附加文件 | `scripts/` 放脚本，`assets/` 放模板或素材，`references/` 放长参考资料。 |

### 4.2 Skill 描述设计

Skill 描述会影响专家选择能力的准确性，应避免抽象口号。

推荐格式：

```text
当用户需要<任务>时使用，输入为<文件/参数/链接>，产出<结果形式>。
```

示例：

```text
当用户需要处理 Excel 或 CSV 表格并生成统计汇总时使用，输入为工作区表格文件路径，产出 Markdown 分析报告和可下载 CSV 结果。
```

不推荐：

```text
强大的数据分析能力。
帮助用户处理各种文件。
```

### 4.3 Skill 正文设计

Skill 正文应让专家知道如何稳定执行，而不是只说明能力范围。

建议结构：

```text
## 适用场景
说明什么时候使用本 Skill。

## 输入要求
列出必须确认的文件、参数、目标格式或限制条件。

## 执行步骤
按顺序说明读取文件、调用脚本、检查结果、整理回复的流程。

## 输出格式
规定最终回复和生成文件的格式。

## 工作区写入
当任务需要保存阶段产物、素材或最终交付物时，主动调用工作区文件工具，不等待用户额外说“保存”。
保存文件时使用 `write_workspace_file`，并提供工作区相对 `path` 和完整 `content`。
网页抓取或资料采集得到多条独立素材时，每条素材单独保存为一个文件，例如 materials/标题-2026070422145700.md、materials/另一标题-2026070422145700.md，不把所有素材合并进一个文件。

## 异常处理
说明文件缺失、依赖缺失、参数不足、结果为空时如何回复。

## 结束条件
说明什么时候任务完成，什么时候需要继续向用户追问。
```

### 4.4 依赖配置

MCP 依赖用于外部工具能力，例如网页检索、专用接口、文件转换服务等。只有 Skill 明确需要时才添加。

Python 依赖用于脚本执行，例如：

```text
pandas>=2.2
openpyxl>=3.1
pdfplumber>=0.11
```

如果页面提示依赖缺失，说明该依赖未被 `设置 → 沙箱` 中 requirements 的 pip 解析闭包覆盖；先点击技能页的一键添加或到沙箱设置补齐，再等待沙箱安装完成。

## 5. 工具、模型和密钥配置

### 5.1 模型

进入路径：`资源中心 → 模型`。

模型配置用于指定大模型服务。常见字段包括显示名称、Base URL、模型型号和密钥引用。

建议：

- 显示名称使用供应商和模型组合，例如 `OpenAI GPT-4.1`、`Qwen Max`。
- 模型型号填写服务商要求的真实 model 名称。
- API Key 优先通过 `设置 → 密钥` 新建，再在模型中选择引用。
- 不要把密钥明文写进专家提示词、Skill 正文或会话消息。

### 5.2 工具

进入路径：`资源中心 → 工具`。

工具用于配置 MCP Server。普通用户只需要确认工具名称、传输方式和必要密钥是否正确。

建议：

- 工具名称体现能力，例如“网页检索”“企业知识库”“图片生成”。
- 远程工具优先使用密钥引用，不在配置说明中粘贴明文密钥。
- Skill 需要哪个 MCP，就在 Skill 的 MCP 依赖里声明哪个工具。

### 5.3 沙箱

进入路径：`设置 → 沙箱`。

普通脚本型 Skill 使用普通版沙箱即可。需要浏览器自动化、网页截图或复杂网页交互时，选择 Playwright 版。

requirements 中维护当前账号需要的 Python 包。修改后应等待安装完成，再运行依赖这些包的 Skill。

## 6. 工作空间与文件路径

工作空间是会话内的文件区。用户上传文件、专家生成文件、脚本输出结果都应保存在当前会话工作区。

### 6.1 路径规则

在会话和 Skill 任务中，文件路径统一使用当前工作区相对路径。

正确示例：

```text
uploads/report.xlsx
notes/query.sql
outputs/result.md
outputs/images/cover.png
```

错误示例：

```text
/Users/用户名/Desktop/report.xlsx
系统内部工作区路径/report.xlsx
../report.xlsx
服务器内部目录/report.xlsx
```

如果不确定文件路径，先打开右侧“文件”面板查看，或让专家列出当前工作区文件。

### 6.2 输入文件

输入文件必须先上传到当前会话工作区。上传后，使用文件面板显示的路径发起任务。

示例：

```text
请读取 uploads/差旅报销.xlsx，生成 outputs/报销汇总.md。
```

```text
请处理 uploads/meeting.mp3，把转写文本保存到 outputs/meeting-transcript.md。
```

### 6.3 输出文件

需要下载、复用或继续处理的结果，应明确要求保存到工作区。
专家生成阶段产物或最终产物时，也应主动保存到工作区；只有文件工具返回成功后，才能在回复中说明“已保存”。
网页抓取、资料采集和素材整理类任务应按“一个素材一个文件”保存，最终回复只列出文件路径和简短说明。

推荐输出目录：

| 目录 | 用途 |
| --- | --- |
| `outputs/` | 最终结果、报告、表格、图片 |
| `tmp/` | 临时中间文件 |
| `cache/` | 可重复利用但不需要直接阅读的缓存 |
| `notes/` | 用户和专家共同维护的文本资料 |

示例：

```text
请把结果保存到 outputs/result.md，并在回复中给出文件路径。
```

### 6.4 常见路径问题

| 问题 | 处理方式 |
| --- | --- |
| 找不到文件 | 检查是否上传到当前会话，复制文件面板中的真实路径后重试。 |
| 路径不允许 | 改用工作区相对路径，不使用绝对路径、内部路径或 `..`。 |
| 输出文件不存在 | 明确要求“保存到 outputs/某文件”，并确认脚本是否运行成功。 |
| 文件不是文本 | PDF、Excel、图片、音频、数据库等文件通常需要脚本型 Skill 处理。 |

## 7. 典型配置流程

### 7.1 新建一个表格分析场景

1. 在 `资源中心 → 技能` 新建“表格统计分析 Skill”，描述为“处理 Excel/CSV 并输出统计报告”。
2. 在 Skill 中声明需要的 Python 依赖，例如 `pandas`、`openpyxl`。
3. 在 `资源中心 → 专家` 新建“表格分析专家”，绑定该 Skill。
4. 专家系统提示词中写清楚输入文件、分析流程、输出格式和路径规则。
5. 在 `资源中心 → 场景` 新建“表格分析报告”场景。
6. 场景主持人提示词只负责判断任务、追问缺失信息和调度专家。
7. 把“表格分析专家”加入协作专家。
8. 在工作空间选择该场景，上传 `uploads/data.xlsx`，发起分析任务。

### 7.2 新建一个会议纪要场景

1. 新建或导入“音频转写 Skill”。
2. 新建“音频转写专家”，负责把音频转成文本。
3. 新建“纪要整理专家”，负责从转写文本中提炼议题、结论和待办。
4. 新建“会议纪要整理”场景，把两个专家都加入。
5. 主持人提示词中规定：先转写，再整理纪要，信息不足时追问会议主题和输出格式。
6. 用户上传音频后，要求输出 `outputs/meeting-minutes.md`。

## 8. 配置质量检查

保存资源前，建议按以下清单检查：

- 场景名称能否让用户一眼判断用途。
- 场景描述是否写清输入、流程、产出和边界。
- 主持人提示词是否只负责调度，而不是代替专家执行。
- 专家名称是否体现职责。
- 专家描述是否能帮助主持人判断是否邀请。
- 专家系统提示词是否包含输入要求、工作流程、输出格式和边界。
- Skill 描述是否明确触发条件、输入和产出。
- 脚本型 Skill 是否声明了必要 Python 依赖。
- 需要外部工具的 Skill 是否声明 MCP 依赖。
- 文件输入输出是否统一使用当前工作区相对路径。

## 9. 导入与导出

场景、专家、Skill 和工具都支持通过 ZIP 资源包迁移。

建议：

- 迁移一套完整工作流时，优先导出场景包。
- 单独复用某个专家时，导出专家包。
- 单独复用能力实现时，导出 Skill 包。
- 导入后检查缺失专家、缺失 Skill、缺失 MCP 和缺失 Python 依赖。
- 遇到同名资源时覆盖目标账号已有内容；名称不同时作为新版本导入，系统自动处理内部引用。

跨账号迁移后，应先用一条简单会话验证模型、Skill、MCP 和文件路径都能正常工作，再投入正式任务。
