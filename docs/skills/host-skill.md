# 主持人 Skill 规范

主持人是纯调度者。主持人长期提示词负责通用调度职责、工作区使用边界、阶段表读取方式和结构化输出合同；主持人 Skill 只描述一个具体场景怎样推进。

## 1. 职责边界

### 1.1 主持人长期提示词负责

- 判断当前应该调度专家、询问用户还是结束；
- 一次只调度一位专家；
- 形成包含目标、输入、用户要求、交付结果和完成条件的任务单；
- 使用工作区核对调度所需的真实材料；
- 读取四列表并映射为主持人结构化输出；
- 输出字段、字段关系和协议失败处理。

主持人 Skill 不复制以上规则，不保存 JSON 示例，也不解释平台字段。

### 1.2 场景提示词负责

场景提示词是会话内所有角色共享的任务契约，负责场景目标、适用范围、共同要求、完成标准和场景特有工作区约定。

主持人 Skill 不重复场景说明，只把场景完成标准映射为具体阶段条件。

### 1.3 主持人 Skill 负责

主持人 Skill 只负责：

- 当前场景有哪些阶段；
- 每个阶段出现什么条件时采取什么调度动作；
- 本轮动作完成后进入什么阶段；
- 调度专家时任务单必须携带哪些场景特有信息。

## 2. Frontmatter

```yaml
---
name: 【场景名称】主持流程
description: 当【场景名称】需要按阶段调度专家时使用。
allowed-tools:
  mcp: []
  http_api: []
  python: []
---
```

一个场景绑定一个主持人 Skill。同一主持人可以在不同场景中使用不同的主持人 Skill。专家引用只使用完整名称，不使用 id、简称或角色编号。

## 3. 通用模板

主持人 Skill 除 Frontmatter 和标题外，正文只保留一张四列表：

```markdown
---
name: 【场景名称】主持流程
description: 当【场景名称】需要按阶段调度专家时使用。
allowed-tools:
  mcp: []
  http_api: []
  python: []
---

# 【场景名称】主持流程

| 当前阶段 | 如果 | 主持人就 | 然后进入 |
| --- | --- | --- | --- |
| 【阶段】 | 【可以直接判断的条件】 | 【调度专家、询问用户或结束】 | 【阶段】 |
```

方括号内容必须替换，不得保留在可用 Skill 中。

## 4. 填写规则

1. 表格顺序就是同一阶段内的判断顺序，不增加优先级字段。
2. 同一当前阶段可以有多行分支；主持人从上到下判断，执行第一条已经满足的规则。
3. 每行只表达一次完整决策，一次只执行一行，不合并多个阶段或多个专家任务。
4. “如果”必须是可以从用户输入、最近可见消息、真实工作区文件或实际产物判断的条件。
5. “主持人就”只能使用以下三种写法：
   - `调度【专家完整名称】：【具体任务】`；
   - `询问用户：【一个必要问题】`；
   - `告知用户协作结束：【完成说明】`。
6. 调度专家时，同一单元格写清本场景特有的目标、输入或工作区路径、交付结果和完成条件；通用任务单规则不再重复。
7. “然后进入”填写本轮决策后的阶段。等待用户时可以保持原阶段；结束行固定填写 `end`。
8. 没有任何条件能够确认时，由主持人长期提示词规定保持当前阶段并询问最小必要信息，Skill 不增加兜底行。

## 5. 示例

```markdown
---
name: 调研报告主持流程
description: 当用户需要经过资料收集、确认和写作形成调研报告时使用。
allowed-tools:
  mcp: []
  http_api: []
  python: []
---

# 调研报告主持流程

| 当前阶段 | 如果 | 主持人就 | 然后进入 |
| --- | --- | --- | --- |
| 开始 | 用户还没有说明调研主题和用途 | 询问用户：需要调研什么主题，报告用于什么目的 | 开始 |
| 开始 | 用户已经说明调研主题和用途 | 调度`资料检索专家`：按已确认主题和用途收集可追溯资料，并将材料写入工作区 | 资料确认 |
| 资料确认 | 资料文件尚未形成 | 调度`资料检索专家`：继续补齐资料，交付可供用户确认的材料文件 | 资料确认 |
| 资料确认 | 资料文件已经形成，但用户尚未确认采用范围 | 询问用户：请确认采用哪些材料 | 资料确认 |
| 资料确认 | 用户已经确认采用的材料 | 调度`文档合著专家`：根据已确认材料撰写报告并交付工作区文件 | 报告编写 |
| 报告编写 | 报告尚未满足用户已确认要求 | 调度`文档合著专家`：根据用户反馈修改报告文件 | 报告编写 |
| 报告编写 | 报告文件已经形成并满足场景完成标准 | 告知用户协作结束：调研报告已经完成 | end |
```

## 6. 验收

主持人 Skill 上线前检查：

1. 正文只有一张四列表，没有表外流程章节。
2. 阶段名称前后一致，没有“处理中”“继续”等不可判断状态。
3. 每个条件都能从本轮真实上下文判断。
4. 每行只调度一位专家、询问一个必要问题或结束协作。
5. 专家使用完整名称，任务描述足以让专家独立执行。
6. 等待用户的行保持适当阶段，结束行进入 `end`。
7. 正文没有主持人长期职责、通用工作区函数说明、JSON 输出合同或协议重试文本。
8. Frontmatter 和表格中没有未替换占位符。
