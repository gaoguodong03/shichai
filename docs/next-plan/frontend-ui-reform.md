# 前端 UI 大刀阔斧改革方案

本文档描述 DHA 前端 UI 的改革方向与具体设计，供评审后再实施。核心思路：**Chat 仿照 QQ 群聊**（工作区 + 邀请 DHA 办公），其他模块同步升级信息架构与视觉。

---

## 一、项目背景与现状

### 1.1 项目定位

- **DHA**：Digital Human Agent，数字人智能体。每个 DHA 具备自己的 Skill、MCP，对话均支持 **ReAct Agent** 模式。
- **Chat**：当前分为「单聊」（一人一 Agent）与「群聊」（多 DHA 协作，有主持人调度、工作区、邀请 DHA 等）。
- **规划方向**（见 [next-plan](./next-plan.md)、[local-file-operations](./local-file-operations.md)）：
  - 单聊可视为「仅一人的群聊」，统一为「会话 = workspace」；
  - 工作区按会话隔离，文件放进某个 chat = 放入该会话的 workspace；
  - 群聊已有「工作区」「邀请 DHA」等能力，可作为统一 Chat 的标杆形态。

### 1.2 当前前端结构（简要）

| 区域 | 现状 |
|------|------|
| **主导航** | 最左侧窄条：Chat、DHA、Files、Skills、MCPs、设置；纯文字/图标，切换模块 |
| **中间列** | 按模块展示列表：会话列表 / DHA 列表 / 文件列表 / Skill 列表 / MCP 列表 / 设置分类 |
| **主内容区** | Chat：单聊入口、新对话（群聊）、已有群聊会话；或 GroupCreateView / ChatView / GroupChatView |
| **Chat 内** | 单聊：标题 + 保存为文件；群聊：标题 + 打开工作区 + 邀请 DHA + 消息流 + 可拖拽工作区侧栏 + 输入区（插入文件、自动/手动发言人等） |

痛点与改进空间：

- Chat 与「群聊」概念未在信息架构上统一为「QQ 群式」体验；
- 工作区、邀请 DHA 已存在但入口分散，未形成「群聊房间」的完整心智；
- 单聊 / 群聊仍是两个入口，与规划中的「统一会话模型」不一致；
- 整体视觉与交互偏工具化，缺少「群聊/办公」的沉浸感与清晰层级。

---

## 二、改革目标

1. **Chat 仿照 QQ 群聊**：以「群/会话」为中心，每个会话具备「工作区」与「邀请 DHA 办公」的显性入口与动线。
2. **统一会话模型**：单聊视为「1 人的群」，入口可合并为「新建会话」时选择参与 DHA（0 个=单聊默认 Agent，≥1 个=群聊），列表统一为「会话列表」。
3. **其他模块**：导航、DHA/Skills/MCP/设置、文件等，在信息架构与视觉上做一轮整理，与 Chat 的「群聊化」风格一致，并提升可发现性与操作效率。

---

## 三、Chat 仿照 QQ 群聊 — 详细设计

### 3.1 整体隐喻：一个「群」= 一个会话

- **列表形态**：中间列不再区分「单聊」「新对话（群聊）」两个按钮 + 群列表，改为**统一会话列表**。
  - 每条：群头像（可选用首 DHA 头像或默认群图标）、**群名称**、**副标题**（如「3 个 DHA · 工作区 5 个文件」或「单聊」）、最后活动时间。
  - 顶部操作：**「+ 新建会话」**（点击后为「创建群聊」：标题 + 选择参与的 DHA，0 个即单聊）。
- **进入会话后**：主内容区 = **群聊房间**，包含：
  - **房间头部**：群名称、成员（DHA）列表、**工作区**入口、**邀请 DHA** 入口；
  - **消息区**：时间线式消息流（用户 / 主持人 / 各 DHA），样式可参考 QQ 群消息（头像、昵称、角色标签、内容气泡）；
  - **工作区**：以侧栏或可折叠面板形式与消息区并存（当前 GroupChatView 已有可拖拽工作区侧栏，保留并强化为「本群工作区」）；
  - **输入区**：保留插入文件、自动/手动下一发言人等，必要时增加「@DHA」等快捷方式（可选）。

### 3.2 工作区

- **定位**：本会话的共享文件空间，与 [local-file-operations](./local-file-operations.md) 中「会话 = workspace」一致。
- **入口**：
  - 房间头部常驻：「工作区」按钮/标签，点击展开或打开侧栏（与现有「打开工作区」一致，可改文案为「工作区」或「群文件」）；
  - 在消息中插入文件时，来源为本会话工作区（列表来自 `/api/workspaces/{session_id}/files`）。
- **展示**：侧栏内保留现有能力：目录树、文件列表、上传/新建/删除、预览/在线编辑等；标题统一为「工作区」或「本群工作区」，副标题可带 `session_id` 或群名。

### 3.3 邀请 DHA 办公

- **定位**：在已有群聊中追加 DHA 成员，使其参与后续讨论与工作区协作。
- **入口**：房间头部常驻：「邀请 DHA」按钮（与现有「邀请 DHA」一致，仅未加入的 DHA 可选）。
- **交互**：点击后弹出/抽屉：可选 DHA 列表（排除已在群内的），多选后确认「邀请」；成功后刷新群成员与 dha_ids，并在消息区可展示一条系统提示「xxx 邀请了 DHA：A、B」（可选）。
- **与「新建会话」的区别**：新建时选 DHA = 建群时初始成员；邀请 DHA = 对已有群追加成员，两者共用后端「添加 DHA 到会话」的能力。

### 3.4 单聊的呈现（已确认）

- **统一入口**：**不再保留「单聊」按钮**。新建会话时选 0 个 DHA = 单聊（使用默认 Agent）；选 ≥1 个 DHA = 群聊。
- **列表**：单聊会话在会话列表中与群聊混排，通过副标题或图标区分，如「1 个 DHA」或「单聊」。
- **房间内**：同样展示「工作区」「邀请 DHA」（邀请后即变为 2 人群聊）；界面布局与群聊一致，仅成员数为 1，主持人/下一发言人逻辑可简化展示。

### 3.5 消息区视觉（轻度借鉴 QQ 群）

- **风格程度**：**轻度借鉴**（头像 + 气泡 + 主持人弱化），不高度仿 QQ，避免版权与品牌混淆。
- **用户消息**：右侧气泡，圆角与配色做适度统一。
- **主持人消息**：居中或偏左的灰色/中性样式，弱化视觉权重。
- **DHA 消息**：左侧 DHA 头像（首字或图标）+ 名称 + 角色/主持人标签；右侧气泡内容；不同 DHA 可用气泡边框色或头像色区分。
- **时间与分组**：可选按日期/时间分组显示「今天」「昨天」等。

## 四、突破模块划分 — 信息架构可选项

当前按 Chat / DHA / Files / Skills / MCPs / 设置 分模块并非唯一解，可按使用场景重新划分，以下为若干备选思路（可择一或杂交）。

### 4.1 方案 A：工作空间 + 资源中心 + 设置（三大块）

- **工作空间**：主界面即「会话列表 + 当前会话房间」。左侧会话列表，右侧为选中会话的完整房间（消息 + 工作区侧栏 + 邀请 DHA）。**不单独设 Files 模块**：要跨会话看文件时，在工作空间左侧选不同会话，房间内工作区即切换为该会话工作区；或在工作空间顶部/侧边提供「按会话切换」的快捷方式。
- **资源中心**：DHA、Skills、MCP 合并为一个入口。进入后可为 Tab 或分组：**智能体（DHA）** | **技能（Skills）** | **工具（MCP）**，三者都是「可被会话使用的资源」，新建/邀请 DHA 时从「智能体」选，DHA 配置里关联技能与 MCP。列表与详情风格统一，便于管理。
- **设置**：应用设置、模型、账号等，保持独立入口。

**特点**：会话与工作区强绑定，Files 不再作为顶栏模块，而是「在会话内看工作区」或「在工作空间通过换会话看不同工作区」。

### 4.2 方案 B：以会话为唯一首页，其余收进「管理」或「设置」

- **首页**：仅「会话列表 + 当前会话房间」（含工作区、邀请 DHA）。无顶栏多模块切换。
- **管理/设置**：一个入口（如「管理」或齿轮），进入后为二级结构：DHA 管理、Skills 管理、MCP 管理、应用设置等。平时以对话为主，需要配 DHA/Skill/MCP 时再进管理。

**特点**：极简，所有对话相关能力都在会话内完成；配置类能力收敛到一处，不分散在多个顶栏。

### 4.3 方案 C：按「做什么」分：对话、文件、配置

- **对话**：会话列表 + 房间（消息 + 工作区侧栏 + 邀请 DHA），与方案 A 的工作空间一致。
- **文件**：**仅做「选会话 → 该会话工作区」**（已确认）。左侧为会话列表，右侧为该会话的文件树/列表/预览。适合「我想专门浏览/整理某个会话下的文件」而不想打开完整房间。
- **配置**：DHA、Skills、MCP、应用设置统入「配置」，内部再分子 Tab 或侧栏。

**特点**：保留「文件」为独立视角，但语义明确为「按会话的工作区」，不与 Chat 内工作区重复感过重。

### 4.4 方案 D：保留多模块但重命名与重组

- 若仍希望顶栏有多个入口，可重组为例如：**对话**（原 Chat）、**智能体与能力**（DHA + Skills + MCP 合并为一个模块，内部分 Tab）、**文件**（选会话→工作区）、**设置**。这样从 6 个减为 4 个，且「智能体与能力」更符合「为对话提供 DHA/Skill/MCP」的心智。

### 4.5 建议与已选方案

- **已选方案**：**方案 A（工作空间 + 资源中心 + 设置）**，已按此改造前端。
- **Files 模块**：按方案 A 不单独设 Files 模块；文件仅在各会话房间内通过「工作区」侧栏查看与操作。
- **单聊**：**不保留「单聊」按钮**，统一为「新建会话」且选 0 个 DHA = 单聊。
- **平台**：**先桌面端**，响应式与移动端后续再做。

## 五、其他部分更改（在选定信息架构后）

### 5.1 主导航（若采用多模块）

- 结构按第四章选定方案（如工作空间 + 资源中心 + 设置，或 对话 + 文件 + 配置）。
- 视觉：图标 + 短文案或仅图标悬停提示；选中态明确。
- **Files**（若存在）：仅「选会话 → 该会话工作区」，入口文案可为「文件」或「会话文件」。

### 5.2 中间列与主内容区

- **会话列表**：统一「+ 新建会话」，列表项为群名、副标题（如「3 个 DHA」或「1 个 DHA」）、时间；重命名、删除保留。
- **资源类列表**（DHA/Skills/MCP）：头像或图标、名称、状态/简述，与「邀请 DHA」等场景风格统一。
- **文件**：左侧会话列表，右侧该会话工作区文件树/列表/预览。
- 空状态、标题栏、主要操作按钮风格统一。

### 5.3 视觉与组件

- **轻度借鉴** QQ 群：头像、气泡、主持人弱化即可。
- 色彩与圆角、字体层级统一；先桌面端，响应式后续迭代。

## 六、实施顺序建议

| 阶段 | 内容 | 说明 |
|------|------|------|
| **P0** | 确定信息架构 | 在第四章 A/B/C/D 中选定或混合，确定主导航与模块划分 |
| **P1** | 统一「会话列表」+「新建会话」（0 个 DHA=单聊） | 取消「单聊」按钮，中间列仅会话列表 |
| **P2** | 会话房间：头部「工作区」「邀请 DHA」强化 | 文案与入口统一，与现有 API 对齐 |
| **P3** | 消息区轻度借鉴 QQ 群（头像、气泡、主持人弱化） | 视觉与信息层级优化 |
| **P4** | 主导航与中间列按新架构落地 | 图标、选中态、空状态；Files 若保留则仅「选会话→工作区」 |
| **P5** | 资源类（DHA/Skills/MCP）列表与详情统一 | 与选定架构一致；先桌面端 |

## 七、与现有实现的关系

- **后端**：无需大改。群聊已有 `group-sessions`、工作区 `workspaces/{id}/files`、邀请 DHA（添加成员）等 API；单聊统一为「新建会话选 0 个 DHA」后，后端为单聊 session 提供 workspace 能力即可（见 [local-file-operations](./local-file-operations.md)）。
- **前端**：MainView 按选定信息架构重构主导航与中间列；GroupCreateView 作为「新建会话」弹窗/页，支持选 0 个 DHA（单聊）；ChatView 与 GroupChatView 可逐步合并为同一套「会话房间」组件。
- **路由**：先保持单页内模块切换；若日后需要会话独立 URL（如 `/chat/:sessionId`），再增加路由与深链。

## 八、已确认事项

| 项 | 结论 |
|----|------|
| 单聊入口 | **不保留「单聊」按钮**，统一为「新建会话」且选 0 个 DHA = 单聊 |
| Files 模块 | **仅做「选会话 → 该会话工作区」**，不做全局/跨会话文件浏览 |
| QQ 风格 | **轻度借鉴**（头像 + 气泡 + 主持人弱化） |
| 平台 | **先桌面端**，响应式与移动端后续迭代 |
| 模块划分 | **不局限于 Chat / Skill / MCP / File**，可按第四章方案突破重组 |
