# 项目流程通俗说明

本文档用通俗易懂的语言描述 DHA 项目的工作流程，帮助非技术人员理解整个系统是如何运作的。

## 整体比喻

想象一下，这个系统就像一个**智能助手团队**：

- **ReAct Agent（智能助手）**：是团队的核心大脑，负责思考、决策和协调
- **MCP Tools（工具箱）**：是各种实际工具，比如计算器、时钟、文件管理器等
- **Skills（技能手册）**：是操作指南，告诉助手"怎么做"和"按什么步骤做"
- **前端界面**：是你和助手对话的窗口

---

## 一、系统启动：准备阶段

### 1.1 后端启动（打开服务窗口）

就像开一家店：

1. **启动服务器**：打开店铺大门，开始营业
2. **加载配置**：读取店铺的营业规则和设置
3. **设置权限**：配置哪些人可以访问（CORS 设置）
4. **准备接口**：准备好对话窗口、设置窗口等
5. **等待客户**：开始监听，等待用户来咨询

### 1.2 延迟初始化（按需准备工具）

**为什么要延迟初始化？**

就像你不会在开店时就把所有工具都拿出来，而是等有客户需要时再准备。这样：
- 启动更快
- 节省资源
- 只准备需要的工具

**初始化过程：**

1. **第一次有用户来咨询时**：
   - 检查工具是否已准备好
   - 如果没准备好，开始准备

2. **准备 MCP 工具箱**：
   - 读取工具箱清单（配置文件）
   - 找到所有启用的工具
   - 连接每个工具服务器
   - 询问每个工具有什么功能
   - 把工具登记到工具目录中

3. **准备 Skills 技能手册**：
   - 扫描技能手册目录
   - 读取每本手册的目录页（了解有什么技能）
   - 先不读完整内容，只记住技能名称和简介

4. **标记完成**：所有工具和技能都准备好了

## 二、用户提问：完整流程

### 2.1 用户发送消息

就像你走进一家智能咨询店：

1. **你在前端界面输入问题**：比如"现在几点了？"
2. **前端发送请求**：把你的问题打包发送给后端服务器
3. **后端接收请求**：服务器收到你的问题

### 2.2 系统准备回答

1. **检查工具是否准备好**：
   - 如果还没初始化，先初始化（见上面的过程）
   - 如果已准备好，直接使用

2. **收集可用资源**：
   - 从工具箱获取所有可用工具列表
   - 从技能手册获取相关技能指导

3. **创建智能助手（Agent）**：
   - 把工具列表和技能手册交给助手
   - 告诉助手："这是你可以用的工具，这是操作指南"

4. **开始思考过程**：助手开始工作

## 三、ReAct 循环：助手的思考过程

### 3.1 什么是 ReAct 循环？

ReAct = **Reasoning（推理）** + **Acting（行动）**

就像人类解决问题的方式：
1. **思考**：分析问题，想想要怎么做
2. **行动**：如果需要，就去执行操作
3. **观察**：看看结果如何
4. **再思考**：基于结果继续思考
5. **重复**：直到得出最终答案

### 3.2 详细流程

#### 第一步：思考阶段（Agent 节点）

1. **构建提示词**：
   - 助手准备一份"工作说明"
   - 包含：你的问题、可用工具列表、技能指导

2. **调用 AI 大脑（LLM）**：
   - 把工作说明发给 AI
   - AI 开始思考："用户问时间，我需要调用时间工具"

3. **AI 返回结果**：
   - 可能返回两种结果：
     - **需要调用工具**：返回工具调用的指令（JSON 格式）
     - **直接回答**：返回最终答案

#### 第二步：判断是否需要工具

系统检查 AI 的回复：
- 如果包含工具调用指令 → 进入工具执行阶段
- 如果是直接回答 → 结束，返回给用户

#### 第三步：工具执行阶段（Tool 节点）

如果需要调用工具：

1. **解析工具调用**：
   - 从 AI 的回复中提取：要调用哪个工具、需要什么参数
   - 比如：`{tool: "time_get_time", arguments: {}}`

2. **查找工具**：
   - 在工具目录中找到对应的工具

3. **执行工具**：
   - 调用工具的实际功能
   - 获取执行结果

4. **格式化结果**：
   - 把工具返回的结果整理成"工具执行结果：当前时间：2024-01-01 12:00:00"

5. **返回给思考阶段**：
   - 把工具结果作为新的信息，让 AI 继续思考

#### 第四步：再次思考

AI 收到工具结果后：
- 再次思考："工具返回了时间，我需要用友好的方式告诉用户"
- 生成最终回复："现在是 2024年1月1日 12点整"

#### 第五步：结束或继续循环

- 如果 AI 不再需要调用工具 → 结束，输出最终答案
- 如果还需要更多工具 → 继续循环

## 四、MCP 工具：实际执行者

### 4.1 MCP 是什么？

MCP（Model Context Protocol）就像**标准化的工具接口协议**。

想象一下：
- 不同品牌的工具（MCP Server）都遵循同一个标准
- 这样助手就可以统一管理和调用它们

### 4.2 工具初始化过程

1. **读取工具配置**：
   - 从配置文件读取有哪些工具服务器
   - 比如：时间工具、计算器工具、文件工具等

2. **连接工具服务器**：
   - 对每个启用的工具，建立连接
   - 就像给每个工具插上电源

3. **询问工具功能**：
   - 问每个工具："你有什么功能？"
   - 工具回答："我有 get_time 功能"

4. **登记工具**：
   - 把工具登记到工具目录
   - 为了避免重名，给工具加上前缀：`time_get_time`（时间工具_获取时间）

### 4.3 工具调用过程

当助手决定调用工具时：

1. **助手说**："我要调用 `time_get_time` 工具"

2. **工具适配器处理**：
   - 找到对应的工具
   - 提取原始工具名：`get_time`
   - 找到对应的工具服务器连接

3. **发送调用请求**：
   - 通过标准协议发送："请执行 get_time 功能"

4. **工具服务器执行**：
   - 工具服务器收到请求
   - 执行实际的 Python 函数：`get_time()`
   - 返回结果："当前时间：2024-01-01 12:00:00"

5. **返回结果**：
   - 结果一层层返回给助手
   - 助手继续思考

## 五、Skills：操作指南

### 5.1 Skills 是什么？

Skills 就像**操作手册**或**技能指南**。

- **MCP Tools**：是实际工具（比如锤子、螺丝刀）
- **Skills**：是使用手册（告诉你如何用这些工具完成任务）

### 5.2 Skills 的作用

Skills 告诉助手：
- **做什么**：任务的目标是什么
- **怎么做**：分步骤的操作指南
- **最佳实践**：完成任务的最佳方式

### 5.3 Skills 加载过程

1. **扫描技能目录**：
   - 系统扫描 `skills/` 文件夹
   - 找到所有技能手册

2. **读取技能信息**：
   - 读取每本手册的封面（SKILL.md 的元数据）
   - 先只记住：技能名称、简介
   - 不读完整内容（节省资源）

3. **存储技能列表**：
   - 把所有技能的名称和简介存起来
   - 等需要时再读详细内容

### 5.4 Skills 使用过程

1. **用户提问**：
   - 比如："分析这个数据文件"

2. **激活相关技能**：
   - 系统判断：这个问题需要"数据分析"技能
   - 加载完整的技能手册内容

3. **注入到提示词**：
   - 把技能指导添加到给 AI 的"工作说明"中
   - AI 看到："数据分析技能：1. 收集数据 2. 清理数据 3. 分析数据 4. 生成报告"

4. **AI 按指导执行**：
   - AI 根据技能指导，知道要分步骤执行
   - 先调用 `read_file` 工具读取文件
   - 再调用 `query_database` 工具清理数据
   - 最后调用 `generate_chart` 工具生成图表

### 5.5 渐进式披露（按需加载）

就像读书：
- **启动时**：只看目录，知道有什么书
- **需要时**：才读完整内容
- **必要时**：才看附录和参考资料

这样既快速又节省资源。

## 六、前端交互：用户看到的界面

### 6.1 前端的作用

前端就像**对话窗口**，让你：
- 输入问题
- 看到助手的思考过程
- 看到最终答案

### 6.2 前端工作流程

1. **用户输入消息**：
   - 你在聊天界面输入问题
   - 点击发送

2. **建立连接**：
   - 前端创建一个"实时连接"（SSE）
   - 就像打开一个实时通话频道

3. **接收实时更新**：
   - 后端会实时推送各种事件：
     - **开始事件**：助手开始工作了
     - **思考步骤**：助手在想什么
     - **工具调用**：助手在调用什么工具
     - **工具结果**：工具返回了什么
     - **内容片段**：助手在说什么（一个字一个字地显示）
     - **结束事件**：助手完成了

4. **更新界面**：
   - 前端收到每个事件，就更新界面
   - 你可以实时看到助手的思考过程

5. **显示结果**：
   - 最终显示完整的对话
   - 包括思考过程、工具调用、最终答案

## 七、流式输出：实时反馈

### 7.1 什么是流式输出？

传统方式：等助手完全想好，一次性给你完整答案（可能等很久）

流式输出：助手一边想一边告诉你，就像：
- 打字聊天时，对方正在输入...
- 你可以实时看到进度

### 7.2 流式输出的好处

1. **实时反馈**：
   - 不用等，立即看到助手开始工作
   - 看到助手的思考过程

2. **透明化**：
   - 知道助手在做什么
   - 知道调用了什么工具
   - 知道工具返回了什么

3. **更好的体验**：
   - 感觉更流畅
   - 不会觉得卡顿

### 7.3 流式输出过程

1. **后端处理**：
   - 助手每完成一步，就立即发送给前端
   - 不等待全部完成

2. **事件格式**：
   - 每个事件都有类型：思考、工具调用、内容、结束等
   - 前端根据类型显示不同内容

3. **前端接收**：
   - 实时接收事件
   - 实时更新界面
   - 用户看到"打字效果"

## 八、完整示例：询问时间

让我们用一个完整例子，看看整个流程：

### 场景：用户问"现在几点了？"

#### 步骤 1：用户发送消息
- 你在前端输入："现在几点了？"
- 前端发送请求到后端

#### 步骤 2：系统准备
- 后端检查：工具准备好了吗？
- 如果没准备好，先初始化：
  - 连接时间工具服务器
  - 登记 `time_get_time` 工具
- 获取工具列表和技能

#### 步骤 3：创建助手
- 创建 ReAct Agent
- 告诉助手："你有这些工具可用，这是操作指南"

#### 步骤 4：第一次思考
- 助手构建提示词：
  - "用户问：现在几点了？"
  - "可用工具：time_get_time（获取当前时间）"
- 调用 AI 大脑
- AI 思考："用户问时间，我需要调用 time_get_time 工具"
- AI 返回：`{action: "tool_call", tool: "time_get_time"}`

#### 步骤 5：执行工具
- 系统判断：需要调用工具
- 查找工具：找到 `time_get_time`
- 执行工具：
  - 调用 MCP 工具服务器
  - 执行 `get_time()` 函数
  - 返回："当前时间：2024-01-01 12:00:00"
- 格式化结果："工具执行结果：当前时间：2024-01-01 12:00:00"

#### 步骤 6：第二次思考
- 助手再次调用 AI：
  - "工具返回了：当前时间：2024-01-01 12:00:00"
  - "用户问：现在几点了？"
- AI 思考："工具已经返回时间，我需要用友好的方式告诉用户"
- AI 返回："现在是 2024年1月1日 12点整"

#### 步骤 7：结束
- 系统判断：不需要更多工具
- 流式输出给前端：
  - 事件1：思考步骤（"用户询问时间，我需要调用工具..."）
  - 事件2：工具调用（"调用 time_get_time"）
  - 事件3：工具结果（"当前时间：2024-01-01 12:00:00"）
  - 事件4：内容（"现在是"）
  - 事件5：内容（"2024年1月1日"）
  - 事件6：内容（"12点整"）
  - 事件7：结束

#### 步骤 8：前端显示
- 前端实时接收事件
- 显示：
  1. 思考过程（可折叠）
  2. 工具调用（可折叠）
  3. 最终答案："现在是 2024年1月1日 12点整"

## 九、复杂示例：数据分析任务

### 场景：用户说"分析这个数据文件"

这个例子展示了 Skills 如何指导复杂任务：

#### 步骤 1：用户请求
- 用户上传数据文件，说："分析这个文件"

#### 步骤 2：激活技能
- 系统判断：需要"数据分析"技能
- 加载技能手册：
  ```
  ## 数据分析技能
  1. 收集数据
  2. 清理数据
  3. 分析数据
  4. 生成报告
  ```

#### 步骤 3：创建助手
- 助手收到：
  - 工具列表：read_file, query_database, generate_chart
  - 技能指导：数据分析的步骤

#### 步骤 4：多轮 ReAct 循环

**第一轮：**
- AI 思考："根据技能指导，第一步是收集数据"
- 调用工具：`read_file`（读取文件）
- 工具返回：文件内容

**第二轮：**
- AI 思考："根据技能指导，第二步是清理数据"
- 调用工具：`query_database`（清理数据）
- 工具返回：清理后的数据

**第三轮：**
- AI 思考："根据技能指导，需要生成图表"
- 调用工具：`generate_chart`（生成图表）
- 工具返回：图表数据

**第四轮：**
- AI 思考："根据技能指导，最后一步是生成报告"
- 不需要工具，直接生成分析报告

#### 步骤 5：流式输出
- 前端看到完整的分析过程：
  - 思考步骤
  - 每个工具调用
  - 每个工具结果
  - 最终的分析报告

## 十、三者协作关系

### 10.1 形象比喻

想象一个**智能助手团队**：

```
┌─────────────────────────────────┐
│    ReAct Agent（团队大脑）        │
│                                  │
│  - 理解用户需求                  │
│  - 制定行动计划                  │
│  - 协调各方资源                  │
│  - 生成最终答案                  │
└────────────┬────────────────────┘
             │
             │ 协调
             │
    ┌────────┴────────┐
    │                 │
    ▼                 ▼
┌──────────┐    ┌──────────┐
│ Skills   │    │ MCP Tools│
│ (策略师)  │    │ (执行者)  │
│          │    │          │
│ • 制定   │    │ • 实际   │
│   计划   │    │   执行   │
│ • 分解   │    │ • 操作   │
│   任务   │    │   工具   │
│ • 提供   │    │ • 返回   │
│   指导   │    │   结果   │
└──────────┘    └──────────┘
```

### 10.2 具体协作

1. **Skills（策略师）**：
   - 告诉大脑："这个任务应该分4步"
   - 提供每步的指导

2. **ReAct Agent（大脑）**：
   - 理解任务
   - 根据策略师的指导，决定每一步做什么
   - 决定调用哪些工具

3. **MCP Tools（执行者）**：
   - 实际执行操作
   - 返回执行结果
   - 大脑根据结果继续决策

### 10.3 为什么需要三者？

- **只有 MCP Tools**：有工具，但不知道什么时候用什么工具
- **只有 Skills**：知道怎么做，但没有实际执行能力
- **只有 ReAct Agent**：能思考，但需要工具和指导才能完成复杂任务

**三者结合**：策略指导 + 执行能力 + 智能协调 = 强大的 AI 助手

## 十一、总结

### 11.1 核心流程

1. **启动**：系统启动，按需准备工具和技能
2. **接收**：用户提问，系统接收请求
3. **准备**：收集工具和技能，创建智能助手
4. **思考**：助手分析问题，决定行动
5. **执行**：如果需要，调用工具执行操作
6. **再思考**：基于工具结果，继续思考
7. **循环**：重复思考-执行-观察，直到完成
8. **输出**：流式输出过程和结果
9. **显示**：前端实时显示给用户

### 11.2 关键特点

- **智能决策**：ReAct Agent 像人类一样思考
- **工具集成**：MCP Tools 提供实际执行能力
- **策略指导**：Skills 提供操作指南
- **实时反馈**：流式输出让用户看到过程
- **透明化**：用户可以看见助手的思考过程

### 11.3 实际应用

这个系统可以：
- 回答简单问题（直接回答）
- 执行工具操作（调用工具）
- 完成复杂任务（多轮工具调用 + 技能指导）
- 提供透明化的过程（显示思考步骤）

就像有一个**24小时在线、能力强大、过程透明的智能助手**！
