# 场景与专家新建默认提示词设计

版本：v1.0  
日期：2026-07-19  
适用范围：资源中心“新建场景”和“新建专家”的 `system_prompt` 初始化、编辑与保存。

## 1. 目标

新建场景和新建专家时，提示词文本框直接显示各自可编辑的默认模板。默认正文必须是表单中真实的 `system_prompt` 字段值，不使用 placeholder 模拟默认内容，也不复制项目整体系统提示词。

本设计只改变新建资源的初始化行为，不覆盖已有场景或已有专家保存的提示词。

## 2. 字段与职责

三类资源继续使用各自顶层的同名字段，不增加包装对象或平行字段：

- 项目设置：`app_settings.system_prompt`，保存所有角色共享的项目规则。
- 场景资源：`scenario.system_prompt`，保存场景目标、适用范围、共同要求和完成标准。
- 专家资源：`agent.system_prompt`，保存专家跨场景、跨 Skill 不变的长期职责、专业标准和输出合同。

字段名称相同，但默认正文和运行时职责不同。场景和专家不得直接复制 `project.system.default.v1` 的正文。

## 3. 默认模板唯一来源

默认正文统一保存在后端 Prompt 注册表 `backend/app/agent/platform_prompt_templates.json`：

- 场景默认模板：新增 `scenario.system.default.v1`。
- 专家默认模板：复用现有 `expert.system.default.v1`。

后端分别通过 Prompt 访问函数读取模板。Vue 文件、E2E fixture 和业务 API 不维护第二份完整默认正文。

场景默认模板正文确定为：

```text
场景目标：
【说明这个场景要解决的问题和最终目标】

适用范围：
- 【说明适用的用户、任务、材料或业务边界】。
- 【说明不属于本场景处理范围的事项】。

共同要求：
- 【说明主持人和所有专家共同遵守的业务规则】。
- 【说明本场景对事实依据、协作方式和交付形式的要求】。

完成标准：
- 【说明哪些结果必须完成】。
- 【说明如何判断本场景可以结束】。
```

## 4. 默认模板接口

新增只读接口 `GET /api/settings/resource-prompt-defaults`。响应中的每种资源保持与其持久化对象一致的 `system_prompt` 字段：

```json
{
  "status": "ok",
  "data": {
    "scenario": {
      "system_prompt": "场景默认模板正文"
    },
    "expert": {
      "system_prompt": "专家默认模板正文"
    }
  }
}
```

接口不返回项目设置或主持人配置；它只服务资源中心场景、专家的新建初始化。

## 5. 新建初始化流程

### 5.1 场景

1. 资源中心加载资源默认模板。
2. 用户点击“新建场景”。
3. 新草稿的顶层 `system_prompt` 初始化为 `data.scenario.system_prompt`。
4. textarea 通过现有 `v-model="scenarioDraft.system_prompt"` 展示并编辑这个真实值。
5. 保存时继续写入场景顶层 `system_prompt`，不增加其他字段。

### 5.2 专家

1. 资源中心加载资源默认模板。
2. 用户点击“新建专家”。
3. 新表单的顶层 `system_prompt` 初始化为 `data.expert.system_prompt`。
4. textarea 通过现有 `v-model="form.system_prompt"` 展示并编辑这个真实值。
5. 保存时继续写入专家顶层 `system_prompt`，不增加其他字段。

默认模板未加载完成时，不创建带空提示词的新草稿。异步响应不得覆盖用户已经修改的表单值。

## 6. 编辑与清空语义

- 编辑已有场景或专家时，只显示资源已经保存的 `system_prompt`。
- 已有值为空字符串时保持为空，不用默认模板回填。
- 用户在新建表单中主动清空默认正文后，可以保存空字符串。
- 默认模板只参与新建草稿的首次初始化，不参与资源读取、更新或后台迁移。
- 不批量修改 `backend/data/users` 中的既有资源。

## 7. 失败处理

- 默认模板接口失败时，显示可见的加载失败信息，不静默创建空提示词草稿。
- 用户可以重新触发新建操作以重试加载。
- 模板接口只读，不改变当前资源列表或已保存数据。

## 8. 测试与验收

### 8.1 后端

- `scenario.system.default.v1` 存在并包含场景目标、适用范围、共同要求和完成标准。
- 专家默认值等于 `expert.system.default.v1`。
- 默认模板接口返回 `scenario.system_prompt` 与 `expert.system_prompt`，不返回平行别名字段。
- 默认正文只从后端 Prompt 注册表读取。

### 8.2 前端

- 新建场景时，场景 textarea 显示场景默认模板的真实字段值。
- 新建专家时，专家 textarea 显示专家默认模板的真实字段值。
- 编辑已有资源时不被默认模板覆盖。
- 用户修改或清空默认模板后，保存 payload 使用修改后的 `system_prompt`。
- 异步模板响应不覆盖用户已输入内容。

### 8.3 回归

- 场景和专家仍只保存一个顶层 `system_prompt` 字段。
- 项目、场景、主持人、专家的 Prompt 组装顺序不因本次初始化调整而改变。
- 前端构建、后端定向测试和资源中心场景/专家 Playwright 用例通过。

## 9. 非目标

- 不修改项目整体系统提示词模板。
- 不修改主持人长期提示词模板。
- 不改变 Prompt 运行时组装顺序。
- 不为旧资源自动补写默认正文。
- 不新增默认模板重置按钮。
