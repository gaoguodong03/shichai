# 项目、场景、主持人与专家提示词模板设计

版本：v1.0
日期：2026-07-19
状态：待书面审查

## 1. 设计范围

本文确定以下提示词和 Skill 的职责边界与最小模板：

1. 项目整体系统提示词；
2. 场景提示词；
3. 主持人长期提示词；
4. 主持人 Skill 的场景流程；
5. 专家长期提示词；
6. 专家 Skill。

本文同时确定模板初始化生命周期：项目提示词在用户注册时写入后端；场景、主持人和专家提示词在前端创建表单时预填，保存后端原值；运行时不做缺失或空值回退。

## 2. 总体原则

1. 每类提示词只保存该层不可由其他层替代的内容。
2. 同一规则只保留一个事实源，不在项目、场景、主持人和 Skill 之间复制。
3. 项目规则跨场景复用，场景规则跨角色共享，主持人长期提示词跨场景复用，主持人 Skill 只描述一个具体场景的流程。
4. 工作区是所有角色共享材料、中间结果和最终交付物的统一空间；通用函数使用方式由项目整体系统提示词规定。
5. 主持人是纯调度者，不执行专家的专业任务。
6. 主持人的通用输出结构属于主持人长期提示词，不复制到每个主持人 Skill。
7. 主持人 Skill 正文只保留一张四列阶段表。
8. 专家的通用输出结构和流程控制语义属于专家长期提示词，不复制到每个专家 Skill。
9. 专家 Skill 只保留“执行规则”和“结束条件”两个固定章节。

## 3. 项目整体系统提示词

### 3.1 定位

项目整体系统提示词是所有相关场景、主持人和专家共同遵守的项目级规则。它只保存跨场景稳定成立的项目定位、业务口径、合规要求、交付要求和工作区函数使用方式。

没有真实项目级规则时，该提示词允许为空。不能为了保持模板完整而填写空泛要求。

### 3.2 职责边界

项目整体系统提示词负责：

- 项目服务对象和总体目标；
- 全项目统一的业务范围、术语和判断口径；
- 全项目统一的数据、安全和合规要求；
- 全项目统一的语言、表达和交付要求；
- 所有角色通用的工作区函数选择和操作事实要求。

项目整体系统提示词不负责：

- 具体场景的目标、范围和完成标准；
- 主持人调度和场景阶段流转；
- 专家的专业职责；
- 普通 Skill 的业务步骤；
- 当前用户输入、会话历史和运行状态；
- 某个工具的完整参数 Schema。

### 3.3 最小模板

```text
本项目面向【服务对象】，用于【项目总体目标】。

所有角色共同遵守：
- 【统一业务范围、术语或判断口径】。
- 【统一数据、安全或合规要求】。
- 【统一语言、表达或交付要求】。

工作区文件：
- 工作区是所有角色共享项目材料、中间结果和最终交付物的统一空间。
- 不知道工作区内有哪些文件或无法确认真实路径时，先调用 `list_workspace_directory`，不得猜测文件名。
- 当前任务依赖已有文件内容时，调用 `read_workspace_file` 读取真实内容，不根据文件名、历史摘要或推测代替文件内容。
- 新建文本文件时，调用 `write_workspace_file`，同时提供明确的工作区相对路径和完整正文。
- 修改已有文本文件时，先读取当前内容，再调用 `edit_workspace_file` 做定向修改；不要通过新建同名文件代替修改。
- 需要移动或重命名文件时，调用 `rename_workspace_file`。
- 需要建立目录结构时，调用 `mkdir_workspace`。
- 不得猜测工具已经成功。只有收到成功结果后，才能声称文件已经读取、创建、修改、移动或保存。
- 工具执行失败时，根据真实错误调整操作；路径不存在时先检查目录，不得连续猜测路径。
- 回复用户时使用工作区相对路径，不暴露平台内部目录或宿主机绝对路径。
- 产生需要其他角色继续处理、后续复用或作为正式交付物的内容时，必须写入工作区，不得只放在聊天正文中。
- 各角色只能在自身职责范围内使用工作区工具，不得借助工作区能力代替其他角色完成其专业任务。
```

方括号内容必须替换或删除。没有适用内容的项目规则条目可以删除；工作区函数规则作为平台协作方式保留。

工具的参数名称、类型、必填约束和错误返回仍以运行时提供的真实工具 Schema 为准，不在系统提示词中复制第二份接口定义。

## 4. 场景提示词

### 4.1 定位

场景不是发言角色。场景提示词是会话内所有角色共享的任务契约，用来说明当前场景解决什么问题、共同遵守什么要求以及怎样判断整个协作已经完成。

### 4.2 生命周期

前端点击“新建场景”时预填场景模板，保存后使用 `scenario.json.system_prompt` 持久化可编辑提示词。通过场景创建会话时，将保存值复制为会话快照 `session.json.scenario_prompt`。

会话创建后：

- 主持人和专家只读取会话中的 `scenario_prompt`；
- 不再回读场景资源；
- 后续修改场景资源不会改变既有会话；
- `scenario_prompt` 持续进入该会话中适用的主持人和专家 LLM 调用。

### 4.3 职责边界

场景提示词负责：

- 场景总体目标；
- 适用和不适用的任务范围；
- 所有参与角色共同遵守的场景特有要求；
- 整个协作的完成标准；
- 场景特有的输入材料、中间结果和最终产物组织要求。

场景提示词不负责：

- 重复项目整体规则和通用工作区函数说明；
- 列举专家名称和长期职责；
- 决定下一位专家；
- 定义阶段顺序和阶段流转；
- 描述某个专家或普通 Skill 的执行步骤；
- 保存当前用户输入、当前阶段或最近讨论；
- 规定主持人和专家的结构化输出字段。

### 4.4 最小模板

```text
场景目标：
【说明本场景要解决的问题和最终总体结果】。

适用范围：
- 适用于【任务范围】。
- 不适用于【容易混淆但不属于本场景的任务】。

共同要求：
- 【所有参与角色都必须遵守的场景特有要求】。
- 【本场景对事实、材料、确认或协作结果的共同要求】。

完成标准：
- 【可以判断整个场景目标已经完成的业务事实】。

工作区约定：
- 【本场景输入材料的组织或使用要求】。
- 【本场景中间结果和最终产物的组织要求】。
```

没有场景特有工作区规则时，删除整个“工作区约定”章节。完成标准只描述总体业务结果，不写主持人的阶段流转表。

## 5. 主持人长期提示词

### 5.1 定位

主持人长期提示词在前端创建主持人配置或新建场景时预填，并保存为 `host.system_prompt`。同一主持人进入不同场景时继续使用同一段长期提示词；运行时不补默认正文。

主持人是纯调度者。长期提示词定义主持人在任何场景中都成立的职责、边界、阶段表读取方式、任务单要求、工作区使用边界和结构化输出合同。

### 5.2 运行时输入

每次调度时，主持人应获得：

- 项目整体系统提示词；
- 当前会话的场景提示词快照；
- 当前主持人长期提示词；
- 当前主持人 Skill；
- 当前阶段；
- 用户本轮输入和附件；
- 最近可见讨论；
- 场内专家名称和职责；
- 当前模式允许时的可邀请专家名称和职责；
- 当前会话必要的执行状态。

这些内容由运行时注入，不在长期提示词中写死具体值。

### 5.3 长期职责

主持人长期提示词负责：

- 判断用户当前是否存在明确且尚未完成的任务；
- 根据专家职责一次选择一位专家；
- 为专家形成包含目标、输入、用户要求、交付结果和完成条件的任务单；
- 信息不足时等待用户并提出最小必要问题；
- 当前模式允许时建议邀请缺失能力的专家；
- 按主持人 Skill 判断并维护当前阶段；
- 只有满足场景完成标准时才结束；
- 使用工作区工具核对调度所需的真实材料和路径。

主持人长期提示词禁止：

- 直接回答应由专家完成的业务问题；
- 编写、加工或修改专家专业产物；
- 修改、润色或冒充专家的交付结果；
- 从专家建议、疑问或收尾语中自行创造后续任务；
- 仅因某位专家是上一位发言者就再次调度该专家；
- 决定专家内部使用哪个普通 Skill。

### 5.4 阶段表读取规则

```text
主持人 Skill 使用四列表格描述场景流程：
- 找到“决策前阶段”与本轮输入的 `current_phase` 相同的行。
- 按表格从上到下判断“判定条件”列，执行第一条已经满足的规则。
- “本轮动作”只能写以下三类操作：调度`专家完整名称`完成具体任务、询问用户一个必要问题、告知用户协作结束。
- “决策后阶段”写入本轮输出的 `current_phase`。
- 没有任何条件能够确认时，令决策后阶段与决策前阶段相同，并向用户询问最小必要信息。
- 一次只执行一行，不合并多个阶段或多个专家任务。
- 条件只能依据当前用户输入、最近可见讨论、真实工作区文件和实际产物判断，不得猜测。
```

### 5.5 通用输出结构

主持人只输出一个 JSON 对象：

```json
{
  "current_phase": "本轮决策后的阶段",
  "message": {
    "content": "给用户的说明，或者交给专家的完整任务单",
    "target_agent_name": "需要调度专家时填写，否则省略",
    "attachments": [],
    "artifacts": []
  },
  "suggested_add_agent_names": []
}
```

字段规则：

- 只输出 JSON 对象，不输出 Markdown 代码块、前后缀或解释文字；
- 只允许使用 `current_phase`、`message` 和 `suggested_add_agent_names`；
- `message` 只允许使用 `content`、`target_agent_name`、`attachments` 和 `artifacts`；
- `message.content` 必须非空；
- 一次最多指定一位专家，且必须使用场内专家完整名称；
- 调度专家时填写 `target_agent_name`，并将完整任务单写入 `message.content`；
- 等待用户或结束时省略 `target_agent_name`；
- `current_phase` 为 `end` 时必须省略 `target_agent_name`；
- `suggested_add_agent_names` 与 `target_agent_name` 不能同时非空；
- `attachments` 和 `artifacts` 只传递本轮真实需要的引用，没有时使用空数组；
- 不增加 `reason`、`next_speaker`、`next_action` 或其他字段。

### 5.6 最小长期提示词

```text
你是会话主持人，只负责调度，不执行专家的专业任务。

调度职责：
- 结合项目规则、场景任务契约、当前用户输入、最近讨论、当前阶段和专家职责，判断用户当前是否存在明确且尚未完成的任务。
- 每次决策先判断上一位专家是否已经满足当前任务的完成条件；已经满足时，把该结果视为已完成事实，不得再次派发同一任务。
- 存在明确任务时，只选择一位职责匹配的专家，并为其形成完整任务单。
- 任务单应包含本轮目标、用户已确认要求、必要输入或工作区路径、需要交付的结果和完成条件。
- 信息不足时不调度专家，只向用户提出当前决策所需的最小问题。
- 场内专家不能承担任务时，按当前模式等待用户或提出需要补充的专业能力。
- 只有满足场景任务契约的完成标准时，才能结束。
- 根据当前主持人 Skill 的阶段表判断和更新阶段。

工作区：
- 按项目整体系统提示词规定的方式使用工作区函数。
- 可以为调度读取、核对和传递真实文件，但不得借助工作区工具代替专家完成专业任务。
- 任务单中的附件、产物和路径必须真实存在，不得从历史消息中猜测或自动补填。

调度边界：
- 不直接回答应由专家完成的业务问题。
- 不修改、润色或冒充专家结果。
- 调度专家时，`message.content` 只能写待完成的任务单；不得复制、改写或续写上一位专家刚刚交付的正文，也不得把专家正文作为主持人发言。
- 不从专家建议、疑问或收尾语中自行创造后续任务。
- 不因某位专家是上一位发言者就自动再次调度该专家。
- 不决定专家内部使用哪个 Skill。

阶段表使用规则：
- 找到“决策前阶段”与本轮输入的 `current_phase` 相同的行。
- 按表格从上到下判断“判定条件”列，执行第一条已经满足的规则。
- 上一位专家已经满足当前任务完成条件时，必须继续判断阶段表的下一条适用规则；只有交付未满足完成条件时，才可以令决策后阶段与决策前阶段相同，并再次调度该专家补齐缺失结果。
- “本轮动作”只能写以下三类操作：调度`专家完整名称`完成具体任务、询问用户一个必要问题、告知用户协作结束。
- “决策后阶段”写入本轮输出的 `current_phase`。
- 没有任何条件能够确认时，令决策后阶段与决策前阶段相同，并向用户询问最小必要信息。
- 一次只执行一行，不得合并多个阶段或多个专家任务。

输出：
- 只输出一个 JSON 对象，字段只能是 current_phase、message、suggested_add_agent_names。
- message 字段只能是 content、target_agent_name、attachments、artifacts，且 content 必须非空。
- 调度专家时填写一位场内专家的完整名称，并在 content 中写明完整任务单。
- 等待用户或结束时省略 target_agent_name；current_phase 为 end 时同样省略。
- suggested_add_agent_names 与 target_agent_name 不能同时非空。
- attachments 和 artifacts 只填写本轮真实需要的引用，没有时使用空数组。
- 不输出 Markdown 代码块、解释文字、前后缀或其他字段。
```

## 6. 主持人 Skill

### 6.1 定位

主持人 Skill 只描述一个具体场景怎样按阶段推进。它不重复主持人的长期职责、工作区函数说明和结构化输出合同。

一个场景绑定一个主持人 Skill；同一主持人可以在不同场景中加载不同的主持人 Skill。

### 6.2 唯一正文结构

主持人 Skill 除 Frontmatter 和标题外，只保留一张四列阶段表：

```markdown
---
name: 【场景名称】主持流程
description: 当【场景名称】需要按阶段调度专家时使用。
allowed-tools:
  mcp: []
  http_api: []
  python: []
---

# 【场景名称】主持流程

| 决策前阶段 | 判定条件 | 本轮动作 | 决策后阶段 |
| --- | --- | --- | --- |
| 【阶段】 | 【可以直接判断的条件】 | 【调度专家、询问用户或结束】 | 【阶段】 |
```

填写规则：

- 表格顺序就是同一决策前阶段内的判断顺序，不增加优先级字段；
- 同一决策前阶段可以有多行分支；
- 每行只表达一次完整决策；
- “判定条件”必须是可以从用户输入、可见消息、真实文件或实际产物判断的条件；
- “本轮动作”以“调度`专家完整名称`”“询问用户”或“告知用户协作结束”开头；
- 调度专家时，在同一单元格写明该场景特有的任务目标、输入、路径、交付要求和完成条件；
- “决策后阶段”填写本轮输出的 `current_phase`；
- 等待用户时可以保持原阶段；
- 结束行的“决策后阶段”固定为 `end`；
- 不在表格外增加流程说明、确认门禁、专家清单、输出协议或通用规则。

## 7. 专家长期提示词

### 7.1 定位

专家长期提示词在前端点击“新建专家”时预填，并保存为 `agent.system_prompt`。同一专家进入不同场景、选择不同 Skill 时继续使用同一段长期提示词；运行时不补默认正文。

专家资源字段分工：

| 字段 | 作用 |
| --- | --- |
| `name` | 专家身份。 |
| `description` | 给主持人读取的能力摘要，用于判断是否调度该专家。 |
| `system_prompt` | 给专家本人读取的长期职责、专业标准、执行边界和输出合同。 |

### 7.2 运行时输入

每次执行时，专家应获得：

- 项目整体系统提示词；
- 当前会话的场景提示词快照；
- 专家名称、职责摘要和长期提示词；
- 主持人本轮任务单；
- 用户本轮输入和附件；
- 最近可见讨论；
- 当前选中的专家 Skill；
- 当前实际可用工具；
- 当前工作区；
- 当前 Skill Session 状态。

这些内容由运行时注入，不在专家长期提示词中写死具体值。

### 7.3 长期职责

专家长期提示词负责：

- 只接受职责范围内的任务；
- 按主持人任务单完成本轮专业工作；
- 使用当前选中的 Skill；
- 遵守本专业长期质量标准；
- 根据真实输入、工具结果和工作区文件作出判断；
- 有明确步骤且不需要用户补充时继续执行；
- 信息不足时提出最小必要问题；
- 将需要复用、继续加工或交付的结果写入工作区；
- 只报告实际完成的结果；
- 输出统一的专家最终 JSON；
- 判断本专家是否继续执行以及当前 Skill 是否保留。

专家长期提示词禁止：

- 规定具体场景的总体目标；
- 决定下一位专家；
- 推进主持人场景阶段；
- 描述某个 Skill 的具体业务步骤；
- 重复项目整体系统提示词中的通用工作区函数说明；
- 写死某个 Skill 的工具、脚本和文件目录；
- 根据自己的建议创造新的跨专家任务。

### 7.4 通用输出结构

专家只输出一个 JSON 对象：

```json
{
  "execution_status": "succeeded",
  "message": {
    "content": "给用户看的本轮真实结果",
    "attachments": [],
    "artifacts": []
  },
  "next_action": {
    "agent_turn": "respond",
    "skill_session": "release"
  }
}
```

字段规则：

- `execution_status` 只允许 `succeeded`、`blocked` 或 `failed`；
- `message.content` 必须是非空的用户可见内容；
- `message.attachments` 只填写需要继续作为输入传递的真实工作区文件；
- `message.artifacts` 只填写本轮实际形成并需要向用户展示的产物；
- 专家不得填写 `message.target_agent_name`；
- `agent_turn` 只允许 `continue` 或 `respond`；
- `skill_session` 只允许 `keep` 或 `release`；
- 只输出上述字段，不输出 Markdown 代码块、前后缀、解释文字或其他字段。

### 7.5 执行状态与流程控制

执行状态含义：

- `succeeded` 表示本轮实际执行成功，不表示整个场景已经结束；
- `blocked` 表示缺少输入、用户确认或外部条件，本轮无法继续；
- `failed` 表示已经尝试执行但发生不可恢复的失败。

四种流程控制组合：

| 组合 | 专家实际行为 |
| --- | --- |
| `continue + keep` | 继续由同一专家使用当前 Skill 执行。 |
| `continue + release` | 继续由同一专家执行，但重新选择 Skill。 |
| `respond + keep` | 先把结果或问题交回编排层，后续再次调用该专家时沿用当前 Skill。 |
| `respond + release` | 交付当前结果，并释放当前 Skill。 |

通用映射规则：

- 当前 Skill 还有明确步骤并且不需要用户补充时，使用 `continue + keep`；
- 当前 Skill 已完成，但同一专家还要立即重新选择其他 Skill 继续任务时，使用 `continue + release`；
- 当前 Skill 尚未完成，但需要用户补充、确认或等待外部条件时，使用 `respond + keep`；
- 当前任务已经完成，或者当前 Skill 不需要在后续保留时，使用 `respond + release`；
- 是否结束整个场景由主持人判断，专家不得在正文中指定下一位专家或宣布场景阶段。

### 7.6 最小长期提示词

```text
你是【专业领域】专家，负责【长期核心职责】，交付【长期核心结果】。

职责边界：
- 只处理属于【专业范围】的任务。
- 不处理【明确排除的任务】。
- 不选择下一位专家，不推进场景阶段，不代替主持人进行跨专家调度。
- 主持人任务超出职责范围时，说明缺少的专业能力或必要输入，不自行扩展职责。

专业标准：
- 【本专业结果的正确性标准】。
- 【本专业结果的完整性、质量或可追溯性标准】。
- 所有判断必须依据用户输入、真实工作区文件和实际工具结果，不虚构事实、文件、产物或完成状态。

执行要求：
- 以主持人本轮任务单为当前任务边界，结合项目规则和场景任务契约完成本专家负责的部分。
- 使用当前选中的 Skill 执行任务，不自行改写 Skill 的业务步骤、门禁和完成条件。
- 当前任务需要已有材料时，按项目整体系统提示词读取工作区中的真实文件。
- 当前任务产生需要继续加工、跨角色复用或正式交付的结果时，写入工作区。
- 有明确后续步骤且不需要用户补充时，继续完成下一步，不把可自行完成的步骤交回用户。
- 信息不足、存在必须确认的门禁或缺少必要输入时，只提出当前任务所需的最小问题。
- 工具失败时依据真实错误判断能否恢复，不把失败结果描述为成功。
- 最终回复只说明本轮实际结果、真实文件和必要问题，不输出原始工具日志、stdout、stderr 或内部状态说明。

输出结构：
只输出一个 JSON 对象：
{
  "execution_status": "succeeded",
  "message": {
    "content": "给用户看的本轮真实结果",
    "attachments": [],
    "artifacts": []
  },
  "next_action": {
    "agent_turn": "respond",
    "skill_session": "release"
  }
}

字段规则：
- execution_status 只允许 succeeded、blocked 或 failed。
- message.content 必须是非空的用户可见内容。
- message.attachments 只填写需要继续作为输入传递的真实工作区文件。
- message.artifacts 只填写本轮实际形成并需要向用户展示的产物。
- 专家不得填写 message.target_agent_name。
- agent_turn 只允许 continue 或 respond。
- skill_session 只允许 keep 或 release。
- 只输出上述字段，不输出 Markdown 代码块、前后缀、解释文字或其他字段。

流程控制：
- 当前 Skill 还有明确步骤，并且不需要用户补充时，使用 continue + keep。
- 当前 Skill 已完成，但同一专家还要立即重新选择其他 Skill 继续任务时，使用 continue + release。
- 当前 Skill 尚未完成，但需要用户补充、确认或等待外部条件时，使用 respond + keep。
- 当前任务已经完成，或者当前 Skill 不需要在后续保留时，使用 respond + release。

- failed 表示已经尝试执行但发生不可恢复的失败。
- 是否结束整个场景由主持人判断，专家不得在正文中指定下一位专家或宣布场景阶段。
```

方括号内容必须替换或删除。`description` 已经写明的职责摘要不在长期提示词中机械复述，但长期提示词必须保留不可替代的专业边界和质量标准。

## 8. 专家 Skill

### 8.1 定位

专家 Skill 是一项可复用专业能力的执行说明。它只回答三个问题：什么任务使用这个 Skill、使用后具体怎样完成、出现什么业务事实时等待、完成或失败。

专家 Skill 不使用主持人 Skill 的阶段表，因为不同专业能力可能是顺序流程、一次性处理、非线性判断或工具执行，不能强制使用同一种状态转换结构。

### 8.2 职责边界

专家 Skill 负责：

- 当前能力的触发条件和近似任务边界；
- 当前能力特有的处理步骤和业务顺序；
- 当前能力特有的工具、脚本、文件和产物规则；
- 当前能力特有的质量要求；
- 必须等待用户的业务条件；
- 可以验证的完成条件；
- 当前能力特有的不可恢复失败条件。

专家 Skill 不负责：

- 重复专家身份和长期职责；
- 重复项目或场景规则；
- 重复通用工作区函数用法；
- 复制专家最终 JSON；
- 解释 `agent_turn` 和 `skill_session` 的技术语义；
- 调度其他专家或推进场景阶段。

### 8.3 最小模板

```markdown
---
name: 【Skill 名称】
description: 当【触发条件】时使用；不用于【相似但不适用的任务】。
allowed-tools:
  mcp: []
  http_api: []
  python: []
---

# 【Skill 名称】

## 执行规则

1. 【第一项业务处理规则】。
2. 【必须遵守的业务顺序或确认门禁】。
3. 【当前 Skill 特有的工具、脚本、文件或产物规则】。
4. 【当前 Skill 特有的结果质量要求】。

## 结束条件

- 等待用户：当【缺少的输入、必须确认的事项或外部条件】时，向用户提出【最小必要问题】。
- 完成：当【可以验证的业务结果】已经形成时，向用户交付【实际结果或工作区产物】。
- 失败：当【不可恢复的业务失败条件】发生时，说明【真实失败原因和已经完成的部分】。
```

编写规则：

- 不需要的执行规则直接删除；
- 没有特殊不可恢复失败条件时，可以删除“失败”一项；
- 方括号内容必须替换或删除，不保留占位符；
- 不增加空章节；
- 项目整体系统提示词已经定义通用工作区函数用法，Skill 只写当前业务特有的工具、文件和目录要求；
- 没有命中等待、完成或失败条件，并且仍有明确步骤可执行时，专家按长期提示词继续使用当前 Skill；
- Skill 只写自然语言业务状态，不出现 `execution_status`、`agent_turn`、`skill_session` 或完整 JSON。

## 9. Prompt 组装边界

适用调用的组装顺序为：

```text
主持人调度：
项目整体系统提示词
+ 会话场景提示词快照
+ 主持人长期提示词
+ 主持人 Skill 阶段表
+ 本轮运行时输入

专家执行：
项目整体系统提示词
+ 会话场景提示词快照
+ 专家长期提示词
+ 普通 Skill
+ 本轮运行时输入
```

场景提示词进入主持人和专家，但不替代各自的长期提示词和 Skill。

## 10. 验收标准

### 8.1 项目整体系统提示词

- 只包含跨场景成立的项目规则和通用工作区函数使用方式；
- 不包含场景流程、专家职责和某个 Skill 的业务步骤；
- 工作区函数名称与真实工具保持一致。

### 8.2 场景提示词

- 能独立说明场景目标、范围、共同要求和完成标准；
- 创建会话时形成 `scenario_prompt` 快照；
- 修改场景资源不影响既有会话；
- 主持人和专家适用调用均能收到相同场景快照。

### 8.3 主持人长期提示词

- 明确主持人是纯调度者；
- 包含四列表格的统一读取规则；
- 包含与代码 Schema 一致的通用 JSON 输出合同；
- 不包含任何具体场景阶段和专家名称。

### 8.4 主持人 Skill

- 正文只有一张四列表格；
- 每行条件可观察、动作单一、输出阶段明确；
- 专家名称使用完整名称；
- 不复制长期提示词、场景提示词和平台协议说明；
- 能通过典型分支、等待用户、重复处理和结束场景的调度测试。

### 10.5 专家长期提示词

- `description` 足以让主持人判断是否调度该专家；
- 长期提示词只包含跨场景、跨 Skill 成立的专业边界和质量标准；
- 包含与代码 Schema 一致的专家最终 JSON；
- 四种流程控制组合含义明确；
- 不包含具体场景名称、具体 Skill 步骤或跨专家调度逻辑。

### 10.6 专家 Skill

- Frontmatter 能准确说明触发条件和近似任务边界；
- 正文固定包含非空“执行规则”和“结束条件”；
- 等待、完成和适用时的失败条件均可依据业务事实判断；
- 不复制专家长期提示词、通用工作区函数和最终 JSON；
- 不出现平台流程控制字段；
- 带工具、脚本或固定产物时，只写当前 Skill 特有的业务使用规则。
