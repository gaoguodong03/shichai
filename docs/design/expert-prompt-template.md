# 专家通用提示词模板设计

版本：v1.0
日期：2026-07-19
适用范围：`resources/agents/{name}/agent.json` 中的 `description` 和 `system_prompt`。

## 1. 设计目标

专家资源描述一种可以跨场景复用的长期专业能力。专家配置不绑定具体协作场景，不复制主持人 Skill、普通 Skill 或平台运行时已经负责的规则。

本模板采用“职责摘要与专业规则分离”的方式：

- `name` 保存专家身份。
- `description` 用一句话说明专家能够完成的核心任务和交付结果。
- `system_prompt` 只补充职责边界、专业质量标准和通用判断原则。

## 2. 平台已有能力

以下内容由字段或运行时直接提供，不写入专家 `system_prompt`：

- 专家名称来自 `name`。
- 正向职责摘要来自 `description`，运行时会以“你的职责”注入专家执行提示。
- 专家绑定的 Skill 清单由 `skills` 和 Skill 元数据生成。
- Skill 选择由平台选择器完成。
- 具体执行步骤、输入要求、确认门禁和交付方式由当前 Skill 定义。
- MCP、HTTP API、工作区和脚本权限由 Skill 的 `allowed-tools` 决定。
- 最终输出结构、流程控制字段和协议失败处理由平台固定合同负责。
- 跨专家调度和场景阶段推进由主持人及主持人 Skill 负责。

## 3. 通用模板

### 3.1 `description`

```text
负责【核心专业任务】，交付【核心结果】。
```

`description` 必须是一句话，不写工作步骤、工具名称、Skill 名称或场景流程。

### 3.2 `system_prompt`

```text
职责边界：
- 不处理【明确排除的任务】。
- 任务超出职责范围时，说明缺少的专业能力或必要输入，不自行扩展职责。

专业标准：
- 【本专业的正确性标准】。
- 【本专业的完整性、质量或可追溯性标准】。

判断原则：
- 只根据明确输入和本轮实际获得的结果作出结论，不虚构事实、产物或完成状态。
- 信息不足以完成职责内任务时，只提出当前任务所需的最小补充问题。
```

方括号内容是模板变量。创建具体专家时必须替换为真实业务内容；不适用的第二项专业标准可以删除，不能保留未填写的占位符。

## 4. 必填要求

每个专家必须包含：

1. 一句非空 `description`。
2. 至少一项明确排除的任务。
3. 至少一项能够判断结果是否合格的专业标准。
4. 模板中的两条通用判断原则。

专业标准必须描述业务结果质量。例如，检索专家可以要求来源可追溯，文档专家可以要求结构与用户目标一致，图片专家可以要求生成结果与已确认的配图方案一致。不能只写“高质量完成”“认真执行”等不可验证表述。

## 5. 禁止重复的内容

专家 `system_prompt` 不写：

- “你是【专家名称】”等身份复述。
- `description` 已经表达的正向职责清单。
- “协同写作场景”等具体场景名称。
- 主持人调度、交回主持人或下一阶段安排。
- 绑定 Skill 的名称、版本、步骤和退出条件。
- 工作区读写规则或任何工具权限。
- JSON 示例、最终状态结构和流程控制字段。
- 平台已经固定的 Skill 选择、工具调用和错误处理规则。

## 6. 字段示例

以下示例仅展示字段分工，不是某个具体专家的最终配置：

```json
{
  "name": "资料核验专家",
  "description": "负责公开资料核验与来源整理，交付可追溯的事实材料。",
  "system_prompt": "职责边界：\n- 不处理正文写作、图片生成和非公开数据调查。\n- 任务超出职责范围时，说明缺少的专业能力或必要输入，不自行扩展职责。\n\n专业标准：\n- 关键事实必须能够对应到明确来源。\n- 结论必须区分来源原文、事实归纳和无法确认的信息。\n\n判断原则：\n- 只根据明确输入和本轮实际获得的结果作出结论，不虚构事实、产物或完成状态。\n- 信息不足以完成职责内任务时，只提出当前任务所需的最小补充问题。"
}
```

## 7. 后续迁移边界

本设计确认后，现有专家迁移只改专家资源中的 `description` 和 `system_prompt`：

- 删除场景名称、主持人交接说明和平台输出协议。
- 删除 Skill 名称、版本、具体步骤和工具规则。
- 将正向职责收敛到 `description`。
- 将不可替代的领域边界和质量标准保留在 `system_prompt`。

流程控制测试专家必须先套用本通用模板，再加入该专家特有的测试边界和质量标准。普通 Skill 模板仍需单独确认，不属于本文范围。

## 8. 验收标准

- 单独阅读 `description`，主持人能够判断何时选择该专家。
- 单独阅读 `system_prompt`，能够判断专家不会做什么以及结果怎样才算合格。
- 删除 `system_prompt` 中的任何平台协议描述后，专家仍能依靠平台和 Skill 正常执行。
- 同一专家放入不同场景时，不需要改写专家配置。
