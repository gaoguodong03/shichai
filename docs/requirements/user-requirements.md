版本：v1.1 项目验收版
日期：2026-07-05
适用范围：书童四九 Web 应用、后端服务、资源中心、工作区、Skill、MCP、沙箱、模型与平台内用户级环境变量配置、资源导入导出以及 Docker/1Panel 私有化部署形态。

## 1. 文档概述

### 1.1 文档目的

本文从用户和项目验收视角定义书童四九的平台需求，用于对齐项目定位、交付范围、功能边界、验收口径和后续迭代优先级。

本文关注平台本体能力，不评价具体上层应用的内容质量、业务流程成熟度或运营效果。教学、科研、办公等具体应用只能作为平台能力的验证样例，不构成平台交付承诺。

### 1.2 读者对象

| 读者 | 关注点 |
|------|--------|
| 项目负责人 | 平台定位、交付范围、验收边界 |
| 验收人员 | 功能是否可用、数据是否隔离、流程是否闭环 |
| 平台使用者 | 是否能在工作区完成会话、文件、资源和工具操作 |
| 应用/场景建设者 | 是否能配置专家、场景、Skill、工具和模型 |
| 管理员或运维人员 | 是否能私有化部署、排查故障、保障数据持久化 |
| 开发和测试人员 | 需求编号、验收项、测试入口和回归范围 |

| 术语 | 含义 |
|------|------|

## 2. 项目背景与建设目标

### 2.1 背景问题

用户在使用 AI Agent 完成复杂任务时，常见问题不是缺少单次问答能力，而是缺少一套可复用、可配置、可迁移、可私有化运行的应用底座：

| 问题 | 用户影响 | 平台建设方向 |
|------|----------|--------------|
| Agent 应用搭建成本高 | 每个应用都要重复处理会话、角色、工具、文件和配置问题 | 提供统一工作区、资源中心和会话运行框架 |
| 多角色协作难沉淀 | 主持人、专家、流程和工具调用规则散落在提示词中 | 用主持人、专家、场景和 Skill 形成可复用配置 |
| 工具能力分散 | MCP、脚本、文件处理、浏览器自动化难以统一授权和调用 | 提供工具组装、权限控制、沙箱执行和诊断反馈 |
| 数据和环境变量不适合放到公共平台 | 会话、文件、环境变量真实值和资源配置存在隐私与合规风险 | 支持私有化部署、多用户隔离和环境变量脱敏 |
| 成果和配置难迁移 | 做好的专家、Skill 或场景难以复制给其他账号复用 | 支持资源包导入导出、依赖预览和冲突处理 |
| 故障边界不清 | 模型、MCP、脚本、沙箱、文件路径任何一环失败都难定位 | 提供可诊断错误、健康检查和分层测试入口 |

### 2.2 建设目标

书童四九的建设目标是搭建一个可私有化部署的 AI Agent 应用搭建与运行平台。平台应让用户能够在同一套系统中完成资源配置、会话运行、工具调用、文件沉淀、应用复用和部署运维。

平台的交付重点包括：

- 提供统一工作区，使用户能创建会话、发送消息、邀请专家、引用文件并查看运行状态。
- 提供主持人调度和多专家协作机制，使复杂任务能由可配置角色协同完成。
- 提供资源中心，使场景、专家、Skill、MCP、模型和文件能够集中维护。
- 提供 Skill、MCP、脚本和沙箱机制，使平台能接入确定性工具能力和外部服务。
- 提供用户数据隔离、环境变量脱敏和路径安全控制，使平台适合私有化部署。
- 提供导入导出机制，使用户搭建的应用资源可以迁移和复用。
- 提供部署、健康检查、日志和测试入口，使项目具备上线验收条件。

## 3. 产品定位

书童四九是一个可私有化部署的 AI Agent 应用搭建与运行平台。平台提供统一工作区、主持人调度、多专家协作、资源中心、Skill 机制、MCP 工具接入、脚本与沙箱执行、模型与用户级环境变量配置、文件管理以及资源导入导出能力，使用户能够在平台上配置、运行、沉淀和迁移不同类型的 Agent 应用。

平台本身关注应用运行底座、能力编排机制和资源复用机制；具体业务应用如何设计、优化和运营，不属于平台本体的交付范围。

### 3.1 定位边界

| 是什么 | 不是什么 |
|--------|----------|
| AI Agent 应用搭建与运行平台 | 单一聊天机器人 |
| 主持人、多专家、工具和文件协作底座 | 某一个固定业务应用 |
| 可私有化部署的资源与会话系统 | 面向公网运营的 SaaS 商业平台 |
| 可配置、可导入导出的 Agent 应用基础设施 | 完整应用市场或内容运营系统 |
| 支持上层场景快速搭建的能力平台 | 对上层应用效果负责的业务交付系统 |

## 6. 典型验收场景

以下场景用于验证平台能力，不代表平台必须交付或持续运营某个具体业务应用。

### 6.1 从零搭建一个 Agent 应用

应用/场景建设者在资源中心新建专家、配置模型、绑定 Skill 和 MCP 工具，再创建场景并设置主持人和协作专家。验收重点是平台是否支持从资源配置到工作区运行的闭环，而不是该应用本身的业务效果。

### 6.2 主持人组织多专家协作

用户在工作区发起一个需要多角色参与的任务。主持人根据场景配置或当前会话成员选择专家，专家按职责回复，必要时请求用户补充信息。验收重点是主持人调度、专家路由、状态提示和等待用户机制。

### 6.3 Skill 驱动的流程复用

资源配置者为专家编写 Skill，声明触发条件、执行步骤、脚本路径、依赖和输出要求。用户在会话中触发该专家时，平台按 Skill 选择工具并返回结果。验收重点是 Skill 可编辑、可保存、可选择、可执行、可诊断。

### 6.4 MCP 和脚本工具接入

用户配置 MCP Server、保存型 API 工具或脚本型 Skill，并在 Skill `allowed-tools` 中声明本轮允许使用的外部工具。专家在会话中通过所选 Skill 获得工具集合，完成搜索、抓取、转写、生成、文件处理或内部服务访问。验收重点是 Skill 工具授权、参数传递、错误回传、环境变量脱敏和未授权工具不可见。

### 6.5 工作区文件沉淀

用户上传或新建文件，在消息中引用文件，专家读取或生成文件，结果回到当前工作区。验收重点是文件上传、预览、编辑、保存、下载、路径安全和跨用户隔离。

### 6.6 资源导入导出与团队复用

场景建设者将已配置的场景、专家、Skill 或工具导出为 ZIP 资源包，其他账号导入后可在资源中心查看并运行。验收重点是导入预览、同名覆盖、依赖处理、引用重映射和导入结果提示。

### 6.7 私有化部署和运行排障

管理员通过 Docker 或 1Panel 部署平台，完成健康检查、登录、会话、资源配置、沙箱执行和文件持久化冒烟。验收重点是服务可启动、数据可持久化、故障可定位。

## 7. 用户旅程

| 阶段 | 用户动作 | 系统需求 |
|------|----------|----------|
| 进入平台 | 登录或注册账号 | 鉴权可靠，未登录访问受保护页面时跳转登录 |
| 初始化底座 | 配置模型、环境变量、默认主持人和沙箱 | 配置入口集中，保存后对新会话生效 |
| 准备资源 | 新建或导入专家、Skill、MCP、场景和文件 | 资源可编辑、可保存、可引用、可校验 |
| 新建会话 | 新建空会话或从场景进入 | 会话有稳定 ID、标题、成员、历史和工作区 |
| 发起任务 | 输入消息、上传文件、引用文件或点名专家 | 支持流式响应、文件引用、专家调度和错误提示 |
| 执行工具 | 专家使用 Skill、MCP、脚本或沙箱 | 调用状态可见，结果和错误能回到会话 |
| 等待补充 | 系统要求用户确认、补充字段或继续执行 | 前端展示明确下一步，不让用户误以为卡死 |
| 沉淀结果 | 保存生成文件、继续会话或导出资源 | 工作区文件可预览、编辑、下载和复用 |
| 迁移复用 | 导出或导入资源包 | 依赖、冲突和导入结果可理解 |
| 运维排障 | 检查健康状态、日志和配置 | 问题能定位到模型、沙箱、MCP、文件或部署层 |

## 8. 功能需求

### UR-01 账号与用户隔离

优先级：P0

用户需要通过账号登录平台，并在独立数据空间内使用会话、资源、文件、环境变量和沙箱配置。

验收标准：

- 未登录用户访问工作区、资源中心、设置、导入等受保护页面时，系统应跳转登录页并保留 redirect。
- 登录成功后刷新页面应保持登录态。
- A 用户不能读取、修改或删除 B 用户的会话、工作区文件、专家、Skill、MCP、模型、环境变量和沙箱配置。
- 生产环境关闭匿名 API 后，无有效令牌的受保护接口请求应被拒绝。

### UR-02 工作区与统一会话

优先级：P0

用户需要在工作区新建会话、发送消息、查看历史、管理成员、上传和引用文件，并通过统一会话入口运行普通会话或多专家协作会话。

验收标准：

- 用户可以新建、进入、重命名、删除会话。
- 会话消息应支持流式显示，并在完成后形成完整气泡。
- 刷新页面后，会话历史、成员列表、工作区文件和会话状态应可恢复。
- 用户可以通过页面专家选择控件指定本轮专家；请求协议使用 `target_agent_name`，不依赖正文中的 `@专家`。
- 会话结束、等待用户补充、工具异常、轮次上限等状态应有明确提示。

### UR-03 主持人与专家协作

优先级：P0

用户需要通过主持人调度多个专家，让平台能够按当前会话、场景配置或显式点名组织专家协作。

验收标准：

- 新建会话无专家时，主持人应能根据用户目标推荐可邀请专家。
- 场景会话中，主持人应按场景配置选择已有专家，不应随意推荐场景外专家。
- 用户通过结构化目标专家字段指定专家时，系统应优先交给该专家处理。
- 专家发言前，主持人调度说明应作为可见消息展示给用户。
- 专家任务需要用户补充时，系统应进入等待用户状态，而不是无提示地继续循环。

### UR-04 资源中心

优先级：P0

用户需要在资源中心集中维护平台应用所需的场景、专家、Skill、MCP 工具、模型和文件。

验收标准：

- 场景支持新建、编辑、保存、导出和导入。
- 专家支持新建、编辑、删除、配置模型、提示词、头像、Skill 和 MCP 权限。
- Skill 支持编辑 `SKILL.md`、维护 `scripts/`、`references/`、`assets/` 等文件，并展示依赖提示。
- MCP 工具支持 `stdio`、`SSE`、`HTTP` 等传输配置，并支持 `${env:NAME}` 引用平台内用户级环境变量。
- 模型配置支持 Base URL、模型名、参数和 `api_key_env` 环境变量名。
- 文件模块支持跨会话查看工作区文件。

### UR-05 Skill 与脚本执行

优先级：P0

用户需要通过 Skill 将可复用工作方法、执行步骤、脚本、依赖和输出规范绑定到专家能力中。

验收标准：

- 每个 Skill 应以 `SKILL.md` 描述用途、触发条件和执行步骤。
- 专家绑定多个 Skill 时，系统应能根据任务选择合适 Skill。
- Skill 脚本应在当前用户工作区和用户沙箱内执行，不能越权访问其他用户数据。
- 脚本执行结果、错误、超时和必要诊断信息应能回传到会话。
- Skill 依赖缺失时，页面应引导用户维护 requirements 或切换合适沙箱版本。

### UR-06 MCP 工具能力

优先级：P0

用户需要把外部工具能力通过 MCP 接入 Skill，使专家在执行所选 Skill 时只能调用该 Skill `allowed-tools` 声明的搜索、抓取、转写、生成或外部服务能力。

验收标准：

- 用户可以新增、编辑和删除 MCP Server 配置。
- 专家只能获得其配置允许且当前 Skill 声明可用的 MCP 工具。
- MCP 连接失败、断连、鉴权失败或参数错误时，应返回可诊断错误。
- 远程 MCP 使用环境变量时，前端不应明文展示完整变量值。

### UR-07 沙箱运行环境

优先级：P0

用户需要安全、稳定地运行 Skill 脚本和浏览器自动化任务。

验收标准：

- 用户可以在普通版和 Playwright 版沙箱之间选择。
- 用户可以维护本账号的 Python requirements。
- 默认策略下，未授权网络访问应被拦截。
- 沙箱冷启动、依赖安装、脚本执行超时和工具不可用应有明确错误信息。
- 部署侧可以通过固定镜像和环境变量控制沙箱模板、资源配额和预热策略。

### UR-08 工作区文件管理

优先级：P0

用户需要在每个会话中管理文件，并让专家安全读取或写入当前工作区文件。

验收标准：

- 用户可以上传、预览、编辑、保存、重命名、删除和下载工作区文件。
- 用户可以在消息中引用工作区文件。
- 专家和工具只能访问当前会话或授权范围内的工作区路径。
- 路径穿越、内部排障日志误读、跨用户路径访问应被拒绝。
- 专家生成的新文件应出现在对应工作区中。

### UR-09 导出与导入

优先级：P1

用户需要把场景、专家、Skill 或工具配置导出为资源包，并在其他账号中导入复用。

验收标准：

- 导出资源包应包含对象类型、名称、描述和必要依赖关系。
- 导入前应展示资源包内容、同名覆盖项和本地引用重映射结果，避免用户误解导入结果。
- 场景导入应带入必要专家、Skill 和工具引用。
- 资源包格式错误、依赖缺失或无权限导入时应返回明确错误。

### UR-10 模型、环境变量与个人设置

优先级：P1

用户需要管理模型供应商、平台内用户级环境变量、默认主持人、账号信息、主题和个人偏好。

验收标准：

- 模型和环境变量保存后，新会话或新专家配置可以引用。
- 环境变量真实值在前端列表和详情中应脱敏展示。
- 默认主持人配置应影响新建普通会话。
- 场景会话可以覆盖默认主持人配置。
- 修改密码、修改账号和主题切换应有明确保存反馈。

### UR-11 部署与运维

优先级：P1

管理员需要在本地、服务器或 1Panel 中部署系统，并能通过健康检查和日志定位问题。

验收标准：

- 系统提供后端健康检查接口。
- Docker/1Panel 编排应明确主应用、OpenSandbox、数据卷、端口和镜像配置。
- 后端数据、账号配置、用户运行数据应持久化，不应依赖容器临时文件系统。
- OpenSandbox 不可达、镜像不匹配、沙箱 endpoint 异常、MCP 断连等问题应有日志关键词和排查路径。

## 10. 数据与权限需求

| 数据类型 | 存储与访问要求 |
|----------|----------------|
| 账号凭证 | 与平台运行数据分离，密码不得明文存储 |
| 会话历史 | 按用户和会话隔离，刷新后可恢复 |
| 工作区文件 | 按用户和会话隔离，工具访问需经过路径校验 |
| 场景配置 | 每用户独立维护，可引用主持人、专家、Skill、模型和工具 |
| 专家配置 | 每用户独立维护，可被会话和场景引用 |
| Skill 文件 | 每用户独立目录，脚本执行在用户沙箱中完成 |
| MCP 配置 | 每用户独立维护，工具权限由本轮 Skill `allowed-tools` 收紧 |
| 模型配置 | 每用户独立维护，引用环境变量名时不得泄露变量真实值 |
| 平台内用户级环境变量 | 可被模型、MCP、HTTP API、Skill 和沙箱按需引用，前端脱敏展示真实值 |
| 沙箱依赖 | 每用户维护 requirements 和沙箱版本偏好 |

## 12. 范围边界

### 12.1 本版本覆盖

- 私有化 AI Agent 应用搭建与运行平台。
- 账号、工作区、会话、主持人、专家、场景、Skill、MCP、模型、环境变量、文件和沙箱。
- 资源中心配置、资源包导入导出、部署运维、上线前验收所需的核心能力。
- 支持用户基于平台搭建不同类型的 Agent 应用。

### 12.2 本版本不覆盖

- 具体业务应用的完整设计、持续优化、内容质量和运营效果。
- 面向公网的商业化计费、套餐、组织层级权限和审计报表。
- 完整应用市场或 Skill 商店运营机制。
- 多租户 SaaS 级别的企业组织管理、审批流和细粒度 RBAC。
- 大规模并发性能指标的压测承诺。
- 移动端原生 App。

## 13. 成功指标

| 指标 | 目标 |
|------|------|
| 首次平台使用 | 登录后能在 5 分钟内新建会话并看到主持人或专家回复 |
| 应用配置闭环 | 用户能新建专家、Skill、MCP 或场景，并在工作区中引用运行 |
| 协作调度 | 主持人能按场景配置或用户通过结构化字段指定的目标专家组织发言 |
| 文件沉淀 | 用户上传文件后，专家能正确引用并生成当前工作区可见结果 |
| Skill 执行 | 脚本型 Skill 能在沙箱中完成执行，失败时有可读错误 |
| MCP 调用 | 已配置 MCP 工具能被当前 Skill 调用，未在 `allowed-tools` 声明的工具不可见 |
| 资源复用 | 用户能导出并导入资源包，导入结果和冲突处理可理解 |
| 数据隔离 | 不同用户之间无法通过 API、文件路径或工具访问彼此数据 |
| 部署验收 | Docker/1Panel 环境启动后健康检查通过，核心路径冒烟通过 |

## 16. 修订原则

后续新增或调整功能时，应同步更新本文对应章节，并检查以下问题：

- 新功能服务的是哪个平台用户和平台目标。
- 是否属于平台本体能力，还是上层应用设计与运营问题。
- 是否影响 P0 核心路径。
- 是否新增数据、权限或环境变量泄露风险。
- 是否需要补充验收标准和测试命令。
- 是否需要更新用户使用说明、架构说明、测试用例或上线验收手册。
