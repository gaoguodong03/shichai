# 书童四九用户需求文档

版本：v1.0 初稿
日期：2026-06-05
适用范围：书童四九 Web 应用、后端服务、资源中心、工作区、Skill、MCP、沙箱与 1Panel/Docker 部署形态。

## 1. 文档目的

本文从用户视角定义书童四九的产品需求，用于对齐项目目标、功能边界、验收口径和后续迭代优先级。

本文不替代实现说明、接口文档或测试清单。实现细节参考 `docs/architecture/runtime-architecture.md`、`docs/requirements/acceptance-and-tests.md`、`docs/user-manual/user-guide.md` 和 `docs/architecture/` 下的架构文档。

## 2. 产品定位

书童四九是一个可私有化部署的多专家 Agent 对话与工具平台。它不是单一聊天助手，而是一个可配置、可扩展、可沉淀的数字团队工作台。

平台让用户在同一套工作区内管理会话、主持人、专家、场景、Skill、MCP 工具、模型、密钥、文件和沙箱运行环境，并通过带主持人的统一会话完成任务拆解、专家调度、工具执行和结果沉淀。

## 3. 背景与问题

面向教学、科研、教研协作和办公资料处理等任务时，用户通常会遇到以下问题：

| 问题 | 用户影响 | 书童四九的应对方向 |
|------|----------|--------------------|
| 单一 AI 助手难以承担多角色协作 | 复杂任务需要用户反复提示、手动切换角色 | 用主持人和专家组合承载分工协作 |
| 工具、脚本和模型能力分散 | 同一任务中搜索、转写、生成、整理等能力难以串联 | 用 Skill 描述流程，用 MCP 和脚本提供执行能力 |
| 组织数据不适合放到公共平台 | 对话、文件、密钥和工具配置存在隐私与合规顾虑 | 支持私有化部署和多用户数据隔离 |
| 成果与过程不易沉淀 | 同类任务每次从零开始，场景和专家难复用 | 用场景、资源中心、工作区文件和导入导出复用资产 |
| 工具运行环境不稳定 | 依赖、网络、浏览器自动化、脚本执行容易失败 | 用用户沙箱、普通版/Playwright 版镜像和可诊断日志降低不确定性 |

## 4. 目标用户与干系人

| 角色 | 典型目标 | 核心关注点 |
|------|----------|------------|
| 普通使用者 | 在工作区完成问答、资料整理、写作、转写、生成等任务 | 易用、响应清楚、结果可保存 |
| 场景使用者 | 复用一套专家组合处理固定工作流 | 场景入口清晰、专家分工稳定 |
| 资源配置者 | 维护专家、Skill、MCP、模型、密钥和沙箱依赖 | 配置可见、错误可诊断、可迁移 |
| 场景建设者 | 为团队沉淀可复用的业务场景 | 打包导出、依赖预览、导入可控 |
| 组织管理员或运维 | 在本地或服务器部署平台并保障运行 | 数据隔离、镜像版本、健康检查、沙箱资源 |
| 开发和测试人员 | 迭代功能并保证回归稳定 | 模块边界、测试入口、验收标准 |

## 6. 典型使用场景

### 6.1 教学备课

教师在工作区上传教学资料或输入备课目标，选择教学备课场景。主持人根据任务安排教学设计、资料整理、内容审校等专家协作，专家可调用搜索、文档处理或脚本能力，最终在工作区沉淀教案、课件提纲或课堂活动设计。

### 6.2 科研论文与资料整理

研究人员上传论文、笔记或数据文件，邀请文献综述、方法分析、写作润色等专家参与。平台需要支持文件读取、长期会话上下文、阶段性输出保存，以及后续继续追问。

### 6.3 教研会议纪要

用户上传音频或会议资料，选择音频转写或纪要整理相关专家。专家通过音频转写 MCP 或 Skill 处理文件，再由总结专家形成纪要、待办和决议摘要。

### 6.4 办公材料生成

用户提出汇报、通知、说明、检查表等办公材料需求。主持人可将任务交给写作、审校、格式整理专家，生成的 Markdown、表格或附件应能落盘到当前工作区。

### 6.5 网页抓取与资料采集

用户提供网址、主题或检索目标。专家通过已授权 MCP 工具或 Playwright 沙箱获取网页信息，整理成结构化结果。平台需要明确展示工具调用状态，并在失败时提示是网络、授权、依赖还是远端服务问题。

### 6.6 场景导出与团队复用

场景建设者配置一套专家、Skill 和工具依赖后，通过 ZIP 导出交给其他账号导入。导入前应展示内容预览、同名覆盖和 id 重映射提示，避免用户误解导入结果。

## 7. 用户旅程

| 阶段 | 用户动作 | 系统需求 |
|------|----------|----------|
| 进入系统 | 登录或注册账号 | 鉴权可靠，未登录访问受保护页面时跳转登录 |
| 初始化资源 | 配置模型、密钥、默认主持人和沙箱 | 配置入口集中，保存后立即对新会话生效 |
| 新建会话 | 新建会话或从场景进入 | 会话有稳定 ID、标题、成员、历史和工作区 |
| 发起任务 | 输入问题、上传文件、引用文件或点名专家 | 支持流式响应、文件引用、专家调度和错误提示 |
| 专家协作 | 主持人选择专家，专家使用 Skill、MCP 或脚本 | 调度结果可见，工具状态可追踪，输出可落盘 |
| 等待补充 | 系统要求用户确认、补充字段或继续执行 | 前端展示明确的下一步，不让用户误以为卡死 |
| 沉淀成果 | 保存生成文件、导出会话或复用场景 | 工作区文件可预览、编辑、下载和复用 |
| 扩展能力 | 新建专家、Skill、MCP 或导入外部资源包 | 配置可编辑、可校验、可迁移 |

## 8. 功能需求

### UR-01 账号与用户隔离

优先级：P0

用户需要通过账号登录系统，并在独立数据空间内使用会话、资源、文件、密钥和沙箱。

验收标准：

- 未登录用户访问工作区、资源中心、设置、导入等受保护页面时，系统应跳转登录页并保留 redirect。
- 登录成功后刷新页面应保持登录态。
- A 用户不能读取、修改或删除 B 用户的会话、工作区文件、专家、Skill、MCP、模型、密钥和沙箱配置。
- 生产环境关闭匿名 API 后，无有效令牌的受保护接口请求应被拒绝。

### UR-02 工作区与统一会话

优先级：P0

用户需要在工作区新建会话、发送消息、查看历史、管理成员、上传和引用文件，并通过统一会话入口完成单人或多人专家协作。

验收标准：

- 用户可以新建、进入、重命名、删除会话。
- 会话消息应支持流式显示，并在完成后形成完整气泡。
- 刷新页面后，会话历史、成员列表、工作区文件和会话状态应可恢复。
- 用户可以通过 `@` 或页面操作点名主持人或专家。
- 会话结束、等待用户补充、工具异常、轮次上限等状态应有明确提示。

### UR-03 主持人与专家协作

优先级：P0

用户需要通过主持人调度多个专家，让复杂任务由合适的专家分工完成。

验收标准：

- 新建会话无专家时，主持人应能根据用户目标推荐可邀请专家。
- 场景会话中，主持人应按场景配置选择已有专家，不应随意推荐场景外专家。
- 用户显式点名专家时，系统应优先交给该专家处理。
- 专家发言前，主持人调度说明应作为可见消息展示给用户。
- 专家任务需要用户补充时，系统应进入等待用户状态，而不是无提示地继续循环。

### UR-04 资源中心

优先级：P0

用户需要在资源中心集中维护场景、专家、Skill、MCP 工具、模型和文件。

验收标准：

- 场景支持新建、编辑、保存、导出和导入。
- 专家支持新建、编辑、删除、配置模型、提示词、头像、Skill 和 MCP 权限。
- Skill 支持编辑 `SKILL.md`、维护 `scripts/`、`references/`、`assets/` 等文件，并展示依赖提示。
- MCP 工具支持 `stdio`、`SSE`、`HTTP` 等传输配置，并支持引用密钥。
- 模型配置支持 Base URL、模型名、参数和密钥引用。
- 文件模块支持跨会话查看工作区文件。

### UR-05 Skill 与脚本执行

优先级：P0

用户需要通过 Skill 将可复用工作方法、步骤、脚本、依赖和输出规范绑定到专家能力中。

验收标准：

- 每个 Skill 应以 `SKILL.md` 描述用途、触发条件和执行步骤。
- 专家绑定多个 Skill 时，系统应能根据任务选择合适 Skill。
- Skill 脚本应在当前用户工作区和用户沙箱内执行，不能越权访问其他用户数据。
- 脚本执行结果、错误、超时和必要诊断信息应能回传到会话。
- Skill 依赖缺失时，页面应引导用户维护 requirements 或切换合适沙箱版本。

### UR-06 MCP 工具能力

优先级：P0

用户需要把外部工具能力通过 MCP 接入专家，使专家能够搜索、抓取、转写、生成或调用外部服务。

验收标准：

- 用户可以新增、编辑和删除 MCP Server 配置。
- 专家只能获得其配置允许且当前 Skill 声明可用的 MCP 工具。
- MCP 连接失败、断连、鉴权失败或参数错误时，应返回可诊断错误。
- 远程 MCP 使用密钥时，前端不应明文展示完整密钥。

### UR-07 沙箱运行环境

优先级：P0

用户需要安全、稳定地运行 Skill 脚本和浏览器自动化任务。

验收标准：

- 用户可以在普通版和 Playwright 版沙箱之间选择。
- 用户可以维护本账号的 Python requirements。
- 默认策略下，未授权网络访问应被拦截。
- 沙箱冷启动、依赖安装、脚本执行超时和工具不可用应有明确错误信息。
- 部署侧可以通过固定镜像和环境变量控制沙箱模板、资源配额和预热策略。

### UR-08 工作区文件管理

优先级：P0

用户需要在每个会话中管理文件，并让专家安全读取或写入当前工作区文件。

验收标准：

- 用户可以上传、预览、编辑、保存、重命名、删除和下载工作区文件。
- 用户可以在消息中引用工作区文件。
- 专家和工具只能访问当前会话或授权范围内的工作区路径。
- 路径穿越、内部排障日志误读、跨用户路径访问应被拒绝。
- 专家生成的新文件应出现在对应工作区中。

### UR-09 导出与导入

优先级：P1

用户需要把场景、专家、Skill 或工具配置导出为资源包，并在其他账号中导入复用。

验收标准：

- 导出资源包应包含对象类型、名称、描述和必要依赖关系。
- 导入前应展示资源包内容、同名覆盖项和本地 id 重映射结果，避免用户误解导入结果。
- 场景导入应带入必要专家、Skill 和工具引用。
- 资源包格式错误、依赖缺失或无权限导入时应返回明确错误。

### UR-10 模型、密钥与个人设置

优先级：P1

用户需要管理模型供应商、API Key、默认主持人、账号信息、主题和个人偏好。

验收标准：

- 模型和密钥保存后，新会话或新专家配置可以引用。
- API Key 在前端列表和详情中应脱敏展示。
- 默认主持人配置应影响新建普通会话。
- 场景会话可以覆盖默认主持人配置。
- 修改密码、修改账号和主题切换应有明确保存反馈。

### UR-11 部署与运维

优先级：P1

组织管理员需要在本地、服务器或 1Panel 中部署系统，并能通过健康检查和日志定位问题。

验收标准：

- 系统提供后端健康检查接口。
- Docker/1Panel 编排应明确主应用、OpenSandbox、数据卷、端口和镜像配置。
- 后端数据、账号配置、用户运行数据应持久化，不应依赖容器临时文件系统。
- OpenSandbox 不可达、镜像不匹配、沙箱 endpoint 异常、MCP 断连等问题应有日志关键词和排查路径。

## 9. 非功能需求

| 类别 | 需求 | 验收口径 |
|------|------|----------|
| 安全 | 多用户数据隔离、密钥脱敏、路径白名单、默认禁网沙箱 | 认证测试、路径攻击用例、密钥展示检查 |
| 稳定性 | 长任务流式可见、工具异常不中断整个服务、沙箱错误可诊断 | 流式会话联调、故障注入、日志检查 |
| 可用性 | 核心入口清晰，用户知道下一步该做什么 | 登录、会话、资源配置、导入流程手工验收 |
| 可扩展性 | 新专家、Skill、MCP 和模型可通过配置接入 | 新建资源并在会话中调用 |
| 可维护性 | 文档、模块边界、测试入口与部署脚本保持一致 | 代码审查、文档链接检查、回归命令 |
| 可部署性 | 支持本地开发、Docker 和 1Panel 部署 | 构建、导入、健康检查和冒烟测试 |
| 性能体验 | 长回答应尽快显示首段内容，工具耗时应有状态提示 | SSE 首屏可见、工具执行提示、超时提示 |

## 10. 数据与权限需求

| 数据类型 | 存储与访问要求 |
|----------|----------------|
| 账号凭证 | 与业务会话数据分离，密码不得明文存储 |
| 会话历史 | 按用户和会话隔离，刷新后可恢复 |
| 工作区文件 | 按用户和会话隔离，工具访问需经过路径校验 |
| 专家配置 | 每用户独立维护，可被会话和场景引用 |
| Skill 文件 | 每用户独立目录，脚本执行在用户沙箱中完成 |
| MCP 配置 | 每用户独立维护，工具权限按专家和 Skill 收紧 |
| 密钥 | 可被模型和 MCP 引用，前端脱敏展示 |
| 沙箱依赖 | 每用户维护 requirements 和沙箱版本偏好 |

## 11. 范围边界

本版本需求覆盖：

- 私有化多用户 Agent 工作台。
- 工作区会话、主持人、专家、场景、Skill、MCP、模型、密钥、文件和沙箱。
- 导入导出、部署运维、上线前验收所需的核心能力。

本版本不覆盖：

- 面向公网的商业化计费、套餐、组织层级权限和审计报表。
- 完整应用市场或 Skill 商店运营机制。
- 多租户 SaaS 级别的企业组织管理、审批流和细粒度 RBAC。
- 大规模并发性能指标的压测承诺。
- 移动端原生 App。

## 12. 成功指标

| 指标 | 目标 |
|------|------|
| 新用户完成首次会话 | 登录后能在 5 分钟内新建会话并看到主持人或专家回复 |
| 场景复用 | 用户能通过场景入口快速加载专家组合并完成一次任务 |
| 文件处理 | 用户上传文件后，专家能正确引用并生成可见结果 |
| Skill 执行 | 脚本型 Skill 能在沙箱中完成执行，失败时有可读错误 |
| MCP 调用 | 已配置 MCP 工具能被授权专家调用，未授权工具不可见 |
| 数据隔离 | 不同用户之间无法通过 API、文件路径或工具访问彼此数据 |
| 部署验收 | Docker/1Panel 环境启动后健康检查通过，核心路径冒烟通过 |

## 15. 修订原则

后续新增或调整功能时，应同步更新本文对应章节，并检查以下问题：

- 新功能服务的是哪个目标用户和用户目标。
