# 拾柴·GatherFlame（DHA）项目介绍与对比

面向对外介绍、融资/合作材料或技术选型时的**项目定位说明**，以及与豆包、千问等产品的优劣势对比、亮点提炼。

---

## 一、项目介绍

### 1.1 一句话定位

**拾柴·GatherFlame**（原 DHA，Digital Human Agent）是一套**可私有化部署的 AI Agent 对话平台**：所有对话都运行在 **ReAct Agent** 上，自动选择技能、调用 MCP 工具，并支持**多数字人（DHA）群聊协同**，适合企业内网、垂直场景与二次开发。

### 1.2 核心能力概览

| 能力 | 说明 |
|------|------|
| **ReAct Agent 对话** | 类似 ChatGPT/Gemini 的对话体验，但每条回复背后都是「思考 → 可选工具调用 → 再思考」的 Agent 循环，而非纯生成 |
| **Skill + MCP 两阶段** | 先按用户意图选一个 Skill（策略/说明书），再按该 Skill 的步骤执行，步骤内按需调用 MCP 工具（搜索、抓取、计算等） |
| **多 DHA 群聊** | 多个数字人（天气专家、研究专家、助教等）在同一会话中，由主持人 DHA 调度轮流发言，协作完成「规划出行」「教学研讨」「深度研究」等目标 |
| **深度研究 / 内容核查** | 内置「观点或名词 → 先核查 → 多阶段调研 → 结构化报告」的闭环，可单 DHA 完成或与核查专家协作 |
| **可扩展** | Skills 用 Markdown 说明书 + 可选脚本；MCP 用标准协议接入；支持多 LLM（OpenAI/Anthropic/本地等） |

### 1.3 技术栈（便于技术听众）

- **前端**：Vue 3 + Vite + Pinia，SSE 流式输出
- **后端**：Python + FastAPI，LangGraph 实现 ReAct，LangChain 接 LLM，官方 MCP Python SDK 接工具
- **部署**：前后端分离，可内网/私有化部署，Session/配置可落库或文件

## 二、与豆包、千问的对比

**豆包**（字节）、**千问/通义千问**（阿里）是**通用大模型对话产品**：强在模型能力、多模态、联网与官方插件，以云端服务为主。拾柴·GatherFlame 是**Agent 平台/框架**：强在可部署、可定制、多智能体协作与工具链闭环。

### 2.1 对比维度简表

| 维度 | 豆包 / 千问 | 拾柴·GatherFlame（DHA） |
|------|-------------|----------------------|
| **产品形态** | 通用对话/助手，闭源云端服务 | 开源/可私有化 Agent 平台，对话即 Agent |
| **部署与数据** | 数据在厂商云上，合规与内网需求受限 | 可完全内网部署，数据不出域，满足合规与保密 |
| **可定制性** | 以官方插件与 API 为主，逻辑不可改 | Skill/MCP/DHA 均可自建与编排，流程与工具链可深度定制 |
| **多智能体** | 多为单模型单会话，无原生「多角色群聊」 | 原生多 DHA 群聊 + 主持人调度，适合研讨、分工、多角色协作 |
| **工具与扩展** | 官方或生态插件，扩展边界由平台决定 | MCP 标准 + 自建 Skill，工具与步骤可无限扩展 |
| **推理透明** | 一般不展示中间推理与工具调用 | 可选展示 ReAct 步骤、工具调用与结果，便于审计与调试 |
| **模型依赖** | 绑定自家或合作模型 | 可切换多种 LLM（OpenAI/Claude/本地等），模型与平台解耦 |
| **品牌与生态** | 大厂品牌与用户规模 | 中小团队/企业自用或二次开发，生态靠社区与集成 |

### 2.2 拾柴的劣势（相对豆包/千问）

- **模型能力不占优**：不提供自研大模型，效果依赖所选用的底层模型（如 Claude、GPT、千问 API 等）。
- **开箱即用程度**：豆包/千问打开即聊；拾柴需要部署、配置 MCP/Skills/模型，有一定使用门槛。
- **生态与触达**：无大厂应用商店与预装，需要主动部署或集成到现有系统。
- **多模态与体验**：豆包/千问在语音、图像、文档解析等体验上更成熟；拾柴当前以文本对话 + 工具调用为主，多模态能力取决于接入的模型与工具。

### 2.3 拾柴的优势（相对豆包/千问）

- **数据与合规**：私有化/内网部署，数据不出企业，适合政企、金融、医疗等对数据主权要求高的场景。
- **流程与场景可控**：Skill 定义「做什么、按什么顺序做」，MCP 提供「怎么做」；可固化「深度研究」「内容核查」「教学研讨」等流程，而不是依赖模型自由发挥。
- **多智能体协同**：多 DHA + 主持人调度是原生能力，可演示、可落地「多角色分工」的复杂任务，而不是单模型单轮对话。
- **可审计、可调试**：ReAct 步骤与工具调用可展示、可落日志，便于合规审计与问题排查。
- **成本与自主**：可用自建或便宜模型 + 自建工具链，长期成本与供应商锁定风险更可控。

## 三、如何体现项目亮点

对外介绍时，建议**按听众类型**选不同侧重点，并配**可演示场景**。

### 3.1 对技术/架构听众

- **亮点 1：对话即 Agent，而非「聊天 + 偶尔插件」**  
  强调：所有回复都走 ReAct 循环，自动选技能、按步骤执行、按需调 MCP，架构文档与运行流程可对照 [架构概述](./architecture/overview.md)、[运行流程](./architecture/runtime-flow.md)。

- **亮点 2：Skill 与 MCP 职责分离、可组合**  
  强调：Skill 管策略与步骤，MCP 管执行能力；多 Skill、多 MCP 可并行存在，由 Agent 在运行时选择与调用。见 [Skill + MCP 设计](./architecture/skill-mcp-design-draft.md)。

- **亮点 3：多 DHA 群聊与主持人调度**  
  强调：多智能体在同一会话中，由 Leader DHA 决定「谁接着说」，适合研讨、分工、多角色任务。见 [多 DHA 群聊方案](./development/multi-dha-group-chat-plan.md)。

- **演示建议**：用「工作空间 → 新建会话 → 发一条触发技能的消息」展示选技能 + 工具调用；用「多智能体演示」或「教学研讨」群聊展示主持人 + 多 DHA 轮流发言。见 [演示场景](./demo/demo-scenarios.md)。

### 3.2 对业务/产品听众

- **亮点 1：可私有化、数据不出域**  
  一句话：和豆包/千问不同，拾柴可以部署在你们自己的机房或内网，数据不经过第三方，满足合规与保密。

- **亮点 2：固定流程、可复用的「研究/核查/报告」**  
  一句话：深度研究、内容核查等场景不是靠模型临时发挥，而是由 Skill 规定步骤（先核查再研究再报告），结果更稳定、可复现。见 [深度研究场景](./features/deepresearch-scenario.md)。

- **亮点 3：多角色协同，而不是一个人工智能**  
  一句话：一个会话里可以有「教师 + 学伴 + 助教」或「天气专家 + 导航 + 图标生成」，由主持人协调，适合教学、规划、评审等需要分工的场景。

- **演示建议**：优先演示「深度研究」（提一个观点或名词 → 核查 → 研究 → 报告）和「多智能体演示」（规划出行：天气 → 路线 → 图标），用实际界面与话术走一遍。

### 3.3 对投资人/合作方

- **定位一句话**：可私有化部署的「多智能体 Agent 工作台」，与豆包/千问等通用对话产品形成互补：他们要的是模型与流量，我们要的是企业内场景、数据主权与多角色协作。
- **差异化**：私有化 + 多 DHA 群聊 + Skill/MCP 可扩展 + 流程可固化；适合政企、教育、研究、内部知识运营等。
- **证据**：可提供架构文档、演示场景文档与本地/内网演示环境，展示从「发一条消息」到「多 DHA 协作产出报告」的完整链路。

## 四、总结表（可裁剪进 PPT）

| 项目 | 拾柴·GatherFlame（DHA） |
|------|----------------------|
| **定位** | 可私有化部署的多智能体 Agent 对话平台 |
| **核心差异** | 对话即 ReAct Agent；原生多 DHA 群聊；Skill + MCP 可扩展；数据可不出域 |
| **相对豆包/千问** | 优势：私有化、可定制、多智能体、流程可固化、可审计；劣势：非自研模型、开箱即用与生态弱于大厂 |
| **亮点呈现** | 技术侧：Agent 架构、两阶段 Skill/MCP、主持人调度；业务侧：数据主权、深度研究/核查闭环、多角色协同；演示：技能执行 + 群聊多 DHA |
